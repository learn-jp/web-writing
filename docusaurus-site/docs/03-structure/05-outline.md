# 3-5 構成案（アウトライン）の作り方

問いもペルソナも決めたのに、いきなり本文を書き始めていませんか。アウトラインは本文を書く前に導管の設計図を引く作業です。第2章で決めた問いと出口から逆算し、見出し・PREP・Must/Must Notを一枚の図にします。

## なぜ「いきなり書き始めない」のか

> この節の要点：アウトライン＝情報の導管設計図。本文の前に流路を決め、水が溢れて読者に届かない状態を防ぐ。

第1章で、多くの初心者が本文（③）から始めてしまうと述べました。第2章で、執筆前にペルソナと検索意図を決めると述べました。第3章では、その間（構成）を担います。

```
② 構成（骨格）を作る  ← 手紙の型、導管の設計図
        ↓
③ 本文を書く
```

いきなり本文を書くと、「導管なしに水を流す」状態です。水は溢れ、読者のところには届きません。アウトラインは、「流路を先に決める」作業です。

> 「アウトライン＝情報の導管設計図。」  
> 「見出しは関所、各セクションはPREP返球、全体は逆ピラミッド。これらを、本文の前に可視化する。」

寿司職人が握り始める前に「今日のネタと客の好み」を整理するように、アウトラインは本文の「下準備」です。

---

## アウトライン作成の6ステップ

> この節の要点：問い・出口→Must/Not→H2→PREP骨格→リスト/表配置→ペルソナ視点で検証。第2章・第3-1節と連続する実務フロー。

第2章のペルソナ5ステップ、第3-1節のPREP設計手順と連続する、実務フローです。

### アウトライン・ステップ1：問いと出口を1行ずつ書く

```
問い：副業を始めたいが、何から手をつければいいかわからない
出口：今週末、1つの副業にアカウント登録まで進む
```

第2章の6つの問いの①と④から持ってくる。

### アウトライン・ステップ2：Must / Must Not を確認

```
Must：種類の紹介、就業規則、最初の一歩
Must Not：法人設立、上級テクニック、煽り
```

アウトラインに「含める論点」と「含めない論点」の境界。

### アウトライン・ステップ3：H2の関所を、出口から逆算して並べる

```
H2：初心者向け副業の選び方（3つに絞る）
H2：始める前に確認：就業規則と確定申告
H2：今週末に登録まで進む手順
H2：よくある不安（バレる？時間がない？）
```

見出しだけを読んで、「通り道が通るか」確認（第3-2節）。

### アウトライン・ステップ4：各H2にPREPの骨格をメモ

| H2 | P（要点） | R | E | P（締め） |
|---|---|---|---|---|
| 選び方 | 在宅・週末・0円で3選 | 理由… | 具体例… | 1つ選ぶ |
| 就業規則 | 確認必須 | … | … | … |

本文は書かない。「返球フォームの骨」だけ。

### アウトライン・ステップ5：リスト・表・図の配置を決める

```
H2「選び方」→ 比較表
H2「手順」→ 番号付きリスト ＋ スクリーンショット
H2「不安」→ FAQ形式（H3）
```

### アウトライン・ステップ6：見出しだけを読み上げ、ペルソナ視点で検証

健太さんになりきり、「この順序で、出口に着くか？」「不要な関所はないか？」を確認。

## アウトライン・テンプレート

> この節の要点：`templates/article-outline.md` と併用できる最小テンプレート。問い・出口・H2＋PREP骨格を一枚にまとめる。

`templates/article-outline.md` と併用できる、最小テンプレートです。

```markdown
# [記事タイトル案 / H1]

## メタ情報
- 問い：
- 出口：
- ペルソナ：
- 意図の型：
- 流入プラットフォーム：

## Must / Must Not
- Must：
- Must Not：

## 構成（H2＝関所）

### H2：［見出し］
- P：
- R：
- E：（表 / リスト / 図：）
- P（締め）：
- 想定字数：

### H2：［見出し］
（同様）

## 内部リンク候補
- 

## 公開前チェック
- [ ] 見出しだけで骨格が通る
- [ ] 出口までの距離は適切か
- [ ] Must Not に抵触していないか
```

## 逆ピラミッドとアウトラインの順序

> この節の要点：アウトラインは上ほど重要な情報を置く。最重要H2を上にし、上側だけ読んでも核心に触れられる勾配を確保する。

アウトラインを「上から下」に書くとき、情報の優先順位も「上ほど重要」にします。

```
H1 / リード     → 結論の予告（P）
H2（1番目）     → 最も重要な論点
H2（2番目）     → 次に重要
…
H2（最後）      → 補足・FAQ・関連
```

健太さんが途中でタブを閉じた場合、「上側だけ読んでも核心に触れる」。逆ピラミッドの勾配を、アウトライン段階で確保します。

---

## アウトラインと執筆の分離、設計と施工

> この節の要点：設計（アウトライン）と施工（本文）を分離する。骨格があれば本文は各H2のPREPを埋める作業に集中できる。

工場では、設計図と製造は分かれています。Web記事も同じです。

| フェーズ | 作業 | 成果物 |
|---|---|---|
| 「設計」 | アウトライン | 導管設計図 |
| 「施工」 | 本文執筆 | 水が流れる状態 |
| 「検査」 | 構造確認（第1章） | 詰まり・漏れのチェック |

アウトラインが完成していれば、本文は「各H2のPREPを埋める作業」に集中できます。迷いが減り、Must Not への抵触も防げます。

自動車整備士が分解図を見てから作業に入るように、あなたもアウトラインで全体像を把握してから本文を書きます。

---

## 共同執筆・レビューでの使い方

> この節の要点：チームではアウトラインを合意形成の資料に。本文の議論の前に設計図で合意し、手戻りを減らす。

チームで書く場合、アウトラインは「合意形成の資料」になります。

- ディレクター：問い・出口・Must/Must Not を承認
- ライター：H2・PREP骨格を提案
- 編集者：見出しだけ読んで通り道を検証

「本文の議論の前に、設計図で合意する」。それが、後工程の手戻りを減らす導管設計です。

---

### アウトライン作成のポイント

- アウトライン＝「導管の設計図」。本文の前に引く
- 6ステップ：問い・出口 → Must/Not → H2 → PREP骨格 → リスト/表 → 検証
- 逆ピラミッド。重要なH2を上に
- 設計（アウトライン）と施工（本文）を分離する
- チームでは設計図で先に合意する

### アウトライン作成でよくある間違い

| 間違い | 問題 | 改善の方向 |
|---|---|---|
| アウトラインをスキップ | 執筆中に迷子・脱線 | 最低H2＋Pだけでも先に書く |
| 見出しが「背景」「まとめ」 | 標識として機能しない | 内容がわかる見出しに |
| PREP骨格がない | H2ごとの返球がぶれる | 各H2にP一行を必ず |
| アウトラインを固定しすぎ | 執筆中の良い発見を捨てる | 骨格は更新してよい。問いと出口は維持 |
