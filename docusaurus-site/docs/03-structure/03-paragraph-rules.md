# 3-3 段落・文の長さと改行のルール

紙の原稿をそのままWebに載せて、自分がその場で読む気を失ってタブを閉じたことはありませんか。段落は文章の塊ではなく、情報が流れる「導管の最小単位」です。整備士が配管の口径を合わせるように、読者の脳にかかる負荷（認知ストレス）を最小化する長さと区切りを設計すれば、検索・SNS・AIのどの入口から来ても、スマホでも呼吸しながら読める記事になります。

## 段落は「流れの区切り」である

> この節の要点：段落は1つの論点を1つの呼吸で読める長さに区切る。長い段落は導管の詰まりであり、スキャン読みでタブを閉じさせる。

紙の書籍では、1段落が10行を超えることも珍しくありません。Webでは、それが「導管の詰まり」になります。

第2章で、スマホでは1画面に3〜5行しか見えないと述べました。長い段落は、「終わりが見えないトンネル」です。スキャン読みでは、トンネルの入口を見た瞬間にタブを閉じます。

> 「段落の役割は、1つの論点を、1つの呼吸で読める長さに区切ることである。」

工場ラインの比喩で言えば、段落は「工程と工程の間」。部品が一度止まり、次の処理に渡る地点です。1工程に複数の加工を詰め込むと、品質が落ち、ラインが遅れます。

---

## 1段落1論点、導管の基本単位

> この節の要点：1段落＝1論点（または1論点の1側面）。複数の話題を1段落に詰め込むと認知コストが上がる。

第3-2節で、「1見出し1論点」を原則にしました。段落でも同じです。

「1段落＝1論点」（または1論点の1側面）

```
✓ 段落1：副業を始める前に、就業規則を確認する理由
✓ 段落2：確認すべき具体的な項目（競業避止・兼業届）
✓ 段落3：確認後の次のステップへのつなぎ

✗ 1段落に：就業規則の話＋副業の種類＋確定申告＋おすすめツール
```

後者は、「1本の導管に異なる流体を混在」させている状態です。読者の脳は、話題の切り替えのたびに「認知コスト」を払います。

---

## 文の長さ、60文字を目安に

> この節の要点：1文60字以内を目安に、Web読者の1呼吸に合わせた文の長さを設計する。

本書の文体ルール（`templates/style-guide.md`）では、「1文60文字以内」を目安としています。これは、Web読者の「1呼吸」に合わせた設計です。

| 文の長さ | 読者の体験 |
|---|---|
| 40字前後 | 軽く読める。スマホ向き |
| 60字前後 | 許容範囲。情報1単位として処理しやすい |
| 80字超 | 主語と述語の距離が離れ、意味の保持が難しくなる |
| 100字超 | 2文に分割すべきサイン |

長い文は、「導管の曲がり角がきつい」状態です。流体（情報）が減速し、読者は「今、何の話？」と立ち止まります。

### 文を短くする実務テクニック

- 「接続詞で文を分ける」（「しかし」「また」で切る）
- 「修飾語を別文に」（「〜で、〜の場合、〜」→ 2文に）
- 「リストに逃がす」（並列情報は箇条書きへ。第3-4節）

---

## 段落の長さ、3〜4文、スマホで3〜5行

> この節の要点：1段落3〜4文、スマホで3〜5行を目安に。執筆後はスマホプレビューで視覚的な塊を確認する。

実務的な目安です。

| 指標 | 目安 |
|---|---|
| 1段落の文数 | 「3〜4文」 |
| スマホでの表示 | 「3〜5行」（画面幅による） |
| 1文の字数 | 「40〜60字」 |

執筆後、「スマホプレビュー」で段落の塊を確認してください。指でなぞったとき、「1スワイプで段落が完結する」感覚が理想です。

### 長い段落の分割サイン

- 2つ以上の「。」があるのに、話題が変わっている
- 「また」「なお」「一方で」で後半が別論点になっている
- スマホで5行を超える

### 段落構造の見える化

段落の区切りは、HTMLの `<p>` タグで明示します。

```html
<h2>始める前に確認：就業規則で副業は許可されているか</h2>
<p>副業を始める前に、就業規則を確認する必要があります。</p>
<p>確認すべき項目は、競業避止条項と兼業届の要否です。</p>
<p>確認が済んだら、副業の種類選びに進みましょう。</p>
```

「ブラウザでの表示結果（見た目）」：

- 各段落が独立した塊として表示され、論点の切り替えが視覚的にわかる
- スマホでは1段落が3〜5行に収まり、1スワイプで読み切れる
- 段落間の空白が「呼吸の間」になり、次の論点への準備になる

寿司職人が握りの間を意識するように、あなたも段落間の余白を「おもてなし」の設計として扱います。

## 改行と空白、導管の「余白設計」

> この節の要点：段落間・見出し前・リスト前後の空白は、読者が次の情報を受け取る準備をする「余白設計」である。

改行（段落間の空白）は、「視覚的な呼吸」です。詰め込みすぎた導管は、読者の脳に圧力をかけます。

| 要素 | 設計の考え方 |
|---|---|
| 段落間 | 1論点の終わりを明示。次の論点への準備 |
| 見出し前 | 関所への接近。前セクションとの区切り |
| リスト前後 | 箇条書きは前後に導入・締めの1文を |

「空白は、情報の否定ではない。」 余白は、読者が「次の情報を受け取る準備」をする時間です。構造の美学（第3-6節）において、余白は「削ぎ落としの結果」として生まれるものでもあります。

## PREPと段落の対応

> この節の要点：H2セクション内でPREPの各要素を段落に割り当て、返球フォームを完成させる。

1つのH2セクション内で、PREP返球フォームを段落に割り当てる例です。

| PREP | 段落の役割 | 例 |
|---|---|---|
| P | 第1段落：結論・要点 | 「初心者は、まず在宅副業を1つ選び、就業規則を確認してから登録すべきです。」 |
| R | 第2段落：理由 | 「いきなり大がかりな副業は、時間と不安で続かないためです。」 |
| E | 第3段落：具体例 | 「例えば、クラウドソーシングのライティングは…」 |
| P | 第4段落：再確認・次への橋 | 「まずは1つに絞り、今週末に登録まで進めてください。」 |

段落数＝PREPの要素数、とは限りません。Eが長い場合はリスト（第3-4節）に分岐させ、「導管を枝分かれ」させてもよいです。

## 認知ストレスを測る、自己チェック

> この節の要点：公開前に段落の主題・文の長さ・スマホ表示・逆ピラミッドの勾配をチェックし、導管の詰まりを検査する。

公開前に、次の問いを立ててください。

```
□ 各段落に、一つの主題だけがあるか
□ 60字を大幅に超える文が、連続していないか
□ スマホで、段落が5行を超えていないか
□ 段落の順序を入れ替えても、意味が大きく崩れないか
  （逆ピラミッド。重要なものが先にあるか）
```

最後の項目は、「導管の勾配」の確認です。後半の段落を先に読んでも、核心に触れられる構成。それが、ジャンプ読みへの配慮です。

自動車整備士が点検リストで異音を探すように、あなたも公開前に段落の「詰まり」を一つずつ確認します。

---

### 段落設計のポイント

- 段落は「1論点」の単位。長い段落は導管の詰まり
- 1文60字以内、1段落3〜4文を目安に
- 改行・空白は「余白設計」。読者の呼吸のため
- PREPの各要素を段落に対応させ、返球フォームを完成させる
- スマホプレビューで、視覚的な塊を確認する

### 段落設計でよくある間違い

| 間違い | 問題 | 改善の方向 |
|---|---|---|
| 紙の原稿をそのまま載せる | 段落が長大 | Web向けに段落を分割 |
| 改行で意味を区切らない | 文字の塊 | 論点ごとに`<p>`を分ける |
| 短くしすぎて断片化 | 流れが途切れる | 1段落3文程度を維持 |
| 同じ長さの段落の連続 | 単調 | リストや表でリズムを変える |
