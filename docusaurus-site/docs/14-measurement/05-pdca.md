# 14-5 PDCAサイクルの回し方

一度改善して終わりにすると、同じ故障が繰り返されます。公開後、自分が読者として読み返した体験を起点に、第6章の月次60分ルーティンを四半期・年間のサイクルへ拡張します。計器は採点ではなく、「読者としての自分」が留まるかを確かめる道具として、第6章・第11章・第14章のKPIを一本のループに接続します。

## PDCAとは何か

> この節の要点：PlanはKPIと戦略、Doは執筆とリライト、Checkは精密検査、Actは改善ログとカレンダー更新である。第6-6節の月次ルーティンがその原型。

PDCAは、Plan（計画）→ Do（実行）→ Check（確認）→ Act（改善）のサイクルです。Webライティングでは、次のように読み替えます。

| 段階 | Webライティングでの意味 | 本書での対応 |
|---|---|---|
| Plan | 何を測り、何を直すか決める | KPI設計（14-1）、戦略（第12章） |
| Do | 記事を書く・直す・公開する | 執筆（第3・4章）、リライト（第11章） |
| Check | 第2の返球を読む | 精密検査（第6章）、GSC・GA4（14-2・14-3） |
| Act | 次の計画に反映する | 改善ログ、四半期PDCA、カレンダー更新（第12章） |

PDCAは、新しい概念ではありません。第6-6節の月次60分ルーティンは、すでにミニPDCAです。第14章では、それを四半期・年間のサイクルに拡張します。

---

## 本書全体のPDCAマップ

> この節の要点：第2章から第14章までが一本のPDCAループである。設計士は1本書いて終わりではなく、更新し続ける。

本編と応用編を横断すると、PDCAは次のループになります。

```
【Plan】第2章 問い・ペルソナ
    第3章 構成・Must
    第12章 クラスター・カレンダー
    第14章 KPIツリー
        ↓
【Do】第3・4章 執筆
    第5章 Web最適化（検索・SNS・AI引用）
    第7章 証明書
    第8〜10章 声・モバイル・アクセシビリティ
    第13章 ワークフロー
        ↓
【Check】第6章 精密検査（月次）
    第14章 GSC・GA4・ヒートマップ
        ↓
【Act】第11章 リライト・更新
    第14章 四半期PDCA・KPI見直し
        ↓
（Planへ戻る：ペルソナ・クエリ・戦略を更新）
```

設計士は、1本書いて終わりではありません。第7章の誓い3「更新し続ける」が、このループの動力です。

---

## 月次PDCA（第6章と統合）

> この節の要点：月次は第6-6節の60分精密検査をそのまま使う。Plan 5分・Doは月中・Check 60分・Act 10分の4段階に対応づける。

月次は、第6-6節の60分精密検査をそのまま使います。名称をPDCAに対応させると次のようになります。

### Plan（月初5分）

```
□ 今月の北極星KPIは何か（14-1節）
□ 先月のActから、今月のリライト候補は決まっているか
□ 重点3記事は誰が担当するか（第13-2節）
```

### Do（月中）

```
□ リライト3本の執筆・公開（第11章）
□ 新規記事の公開（第12章カレンダーに沿って）
□ 証明書の更新（第7-4節）
```

### Check（月末60分＝第6-6節）

```
フェーズ1：全体異常（10分）
フェーズ2：重点3本の精密検査（30分）
フェーズ3：改善ログ更新（10分）
フェーズ4：先月改善の再試運転（10分）
```

### Act（月末10分）

```
□ 来月のリライト3本を確定
□ 想定外クエリから新規記事候補を1件メモ
□ KPIダッシュボードを更新
```

月次PDCAをチームで回すときは、第13-2節の役割分担を明確にします。ライターはDo、ディレクターはCheckのファシリテート、編集者はActの優先度判断、という分担が一般的です。

## 四半期PDCA（第14章の核心）

> この節の要点：四半期2〜3時間でポートフォリオ全体を見直す。北極星KPI・クラスター健康度・リライト効果・カニバリを集計し、次四半期を確定する。

四半期PDCAは、ポートフォリオ全体を見直す時間です。月次では見えない傾向が見えます。年4回、2〜3時間を確保します。

### Plan（四半期初）

| 項目 | 内容 |
|---|---|
| 北極星KPIの達成状況 | 達成 / 未達と理由 |
| クラスター別レビュー | 第12章のハブ・詳細の健康度 |
| 今四半期の重点テーマ | 新規3本・リライト12本（月3本）の枠 |
| Won't | 今四半期やらないこと |

### Do（四半期中）

月次PDCAを3回回す。第13章のワークフローに沿って執筆・公開・リライトを継続。

### Check（四半期末）

```
□ 北極星KPIの四半期推移
□ クラスター別：表示・外門の通過（CTR）・CV寄与
□ リライト効果の集計（再試運転成功/失敗）
□ カニバリ・鮮度の四半期診断（第11-3・11-4節）
□ ヒートマップ：重点5記事のスクロール変化（14-4節）
□ ステークホルダー報告用サマリー（第12-5節）
```

### Act（四半期末）

```
□ KPIツリーの見直し（指標が機能していたか）
□ ペルソナ・語彙表の更新（第2章・第8章）
□ 次四半期カレンダーの確定（第12-3節）
□ 全面リライト・統合の計画（1〜2本）
□ チームのワークフロー改善（第13章）
```

## 改善ログの設計

> この節の要点：CheckとActの記録が残らないとPDCAは形骸化する。症状・原因レイヤー・アクション・再試運転日・結果を1行で残す。

PDCAが形骸化する原因の多くは、CheckとActの記録が残らないことです。第6-6節のスプレッドシートを拡張します。

| 列 | 例 |
|---|---|
| 日付 | 2026-06-15 |
| 記事URL | /blog/side-job/ |
| 症状 | 外門通過 0.9%、玄関で引き返す 71% |
| 原因レイヤー | 防波堤 |
| アクション | リードに「バレる」1文追加 |
| 種類 | 部分リライト（第11章） |
| 再試運転日 | 2026-07-13 |
| 結果 | 外門通過 1.5%、玄関を通過 65% → 成功 |
| 次のAct | H2-2の関所を次月点検 |

このログが、四半期PDCAのCheckの入力になります。個人でもチームでも、1行の習慣が組織の学習を蓄積します。

## PDCAが回らないときの診断

> この節の要点：PDCAが止まるのは意志ではなく段取りの問題である。Plan過大・Do不足・Check面倒・Act未記録を自己診断し、第13章のワークフローに組み込む。

| 症状 | 原因 | 対処 |
|---|---|---|
| Planが巨大すぎる | KPI・計画が多すぎ | 北極星1つ＋サポート3つ（14-1節） |
| Doに時間がない | 新規ばかり、リライトなし | 月3本リライトをカレンダーに固定 |
| Checkが面倒 | ルーティン未習慣化 | 第6-6節60分を同じ日に固定 |
| Actが書かれない | ログの型がない | 改善ログの列を固定 |
| 数字だけ見る | 自分が読者としての体験を忘れる | Checkの冒頭で読み返しを先に行う |
| 失敗を隠す | 再試運転失敗を記録しない | 失敗もログに。診断に戻る |

整備士が点検リストを守らない工場は、故障が蓄積します。PDCAは意志の問題ではなく、段取りの問題です。第13章のワークフローに組み込めば、習慣になります。

---

## 設計士としてのPDCA

> この節の要点：PDCAをKPI達成の圧力だけに使うと釣りtitleに走る。読者の問いに応え続けるための工具として回す。

最後に、姿勢の話です。PDCAをKPI達成の圧力に使うと、釣りtitleや数字の水増しに走ります。第7章の証明書を毀損します。

設計士のPDCAは、次の問いで始めます。

```
読者の問いに、まだ十分に答えているか。
預かった時間を、まだ無駄にしていないか。
正しいと、まだ宣言できるか。
```

数字は、その問いへの第2の返球です。責めるためではなく、応え続けるために回します。

月次の精密検査。四半期のポートフォリオ見直し。失敗の記録と再試運転。それが、第6章から第14章まで一貫する、設計士の改善サイクルです。

---

## よくある間違い

> この節の要点：年1回だけデータ閲覧、Actなしの次Plan、成功だけ記録、KPI未達で記事を責める、個人だけで回すを避ける。

| 間違い | 改善 |
|---|---|
| 年1回だけデータを見る | 月次60分を習慣化（第6-6節） |
| Actなしで次のPlan | 改善ログに必ず1行 |
| 成功だけ記録 | 再試運転失敗も診断に戻る |
| KPI未達で記事を責める | レイヤー・設計を疑う |
| PDCAを個人だけで回す | 第13章の役割分担でチーム化 |
