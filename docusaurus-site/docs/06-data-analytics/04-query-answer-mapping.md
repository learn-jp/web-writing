# 6-4 問いと答えのずれを特定する

執筆時に想定した問いと、Search Consoleのクエリが一致していると思い込んでいませんか。あなた自身が検索したとき、クリックする前に判断した言葉と、記事が約束した言葉。型番合わせの精密検査なしでは、宛名違いの返球が続き、リライトの起点も見えません。

---

## 型番合わせ、想定の問いと実際の問い

> この節の要点：執筆時の想定問いとSearch Consoleのクエリを型番合わせする。ズレがリライトの起点。

第2章で、キーワードは問いの断片だと述べました。執筆時に想定した問いと、公開後にSearch Consoleに現れるクエリ。このズレが、第2の返球の核心です。

```
執筆時の想定：「副業 始め方 初心者」
実際のクエリ：「副業 バレる」「副業 確定申告」
```

自動車整備士が注文書の型番と、倉庫の在庫ラベルを突き合わせるように。

| 照合項目 | 執筆側 | データ側（Search Console） |
|---|---|---|
| 主キーワード | 第2章の問い設計 | クエリ（クリック・表示） |
| 約束 | Must / H1 | 選ばれ方・去り方 |
| 構造 | H2の並び | スクロール・止まった位置 |
| ラベル | title・meta | 検索結果での選ばれ方 |

ズレが見つかったら、それがリライトの起点です（第11章）。

---

## クエリ分析の4ステップ

> この節の要点：ページ指定→想定内/外分類→表示多・選ばれにくい→自分がタブを閉じる、の4ステップ。

### ステップ1：Search Consoleでページを指定

Search Console → 検索結果 → ページURLでフィルタ → クエリタブ。

### ステップ2：想定内と想定外に分類

| 分類 | 判断 | 対応 |
|---|---|---|
| 想定内 | 執筆時の問いと一致 | 現構成を維持・強化 |
| 想定外（関連） | 近いが別の問い | H2追加、または別記事化 |
| 想定外（無関係） | Mustとズレ | ラベル修正 or リライト方針転換 |

### ステップ3：表示は多いが選ばれにくいクエリを特定

表示は多いがクリックされないクエリ。物流には載っているが、外門が弱い、または意図が微妙に違う。

title・metaに、そのクエリの言葉を自然に織り込めるか検討（第5-4節）。釣りにはしない（第4章）。

### ステップ4：自分が開いてすぐタブを閉じるクエリを特定

自分が開いてすぐタブを閉じる体験と照らす。防波堤または導管の不適合。

リードに、その問いの言葉でボールを引き取る一文を足す（第4章）。または、H2で答えを早める（第3章）。

---

## 記事内の関所、自分がどこで止まったか

> この節の要点：H2単位で止まる＝関所の詰まり。ヒートマップとHTML構造で、自分が検索したときの体験と照合する。

Analyticsのスクロールレポートやヒートマップツールで、自分がどのH2の前後で読むのをやめたかを見ます。ヒートマップの読み方は[6-6 精密検査の実務フロー](./06-inspection-workflow.md)を参照してください。H2の直前で色が急に薄くなるなら、自分がそこでタブを閉じた体験と照らして、関所の詰まりを疑います。

```
H2-1：副業の選び方        ← 通過率 85%
H2-2：就業規則の確認      ← 通過率 40%  ★ 関所で詰まり
H2-3：登録手順            ← 通過率 15%
```

H2-2で詰まる典型例を、HTMLと表示で確認しましょう。

### 関所で詰まりやすい構造（去りやすい）

```html
<h2>就業規則の確認</h2>
<p>
  副業を始める前に確認すべきことが多くあります。会社の就業規則には
  副業禁止の条項がある場合もあり、違反すると懲戒処分の対象になることも
  あります。また、競業避止義務や秘密保持義務についても確認が必要で、
  さらに税務上の手続きについても事前に調べておくとよいでしょう。
</p>
```

ブラウザでの表示結果（見た目）：

- 見出しのあとに長い段落が一続きで並ぶ
- スマホでは文字の塊として見える
- スキャン段階で「ここまで読む価値があるか」が判断できない
- ヒートマップ上、H2-2の直下で色が急に薄くなる傾向が出る

### 関所を通過しやすい構造

```html
<h2>就業規則の確認</h2>
<p>結論：副業前に、就業規則の「副業禁止条項」の有無を確認してください。</p>
<ul>
  <li>副業禁止条項の有無</li>
  <li>競業避止義務の範囲</li>
  <li>事前届出の要否</li>
</ul>
```

ブラウザでの表示結果（見た目）：

- 見出し直下に結論が置かれ、スキャンで答えが拾える
- リストで確認項目が一目でわかる
- ジャンプ読者が「就業規則の確認」だけ読んでも意味が通る
- ヒートマップ上、H2-2を通過してH2-3へ色が続く傾向が出る

H2-2で詰まる → 見出しが抽象的、段落が長い、前段との接続が弱い（第3章・第4章）。  
自動車整備士が3番工程で部品が止まると特定するのと同じ精密検査です。

寿司職人が特定のネタで客の箸が止まるのを見て、次の一貫の順番を変えるように、関所の詰まりは次の改善の手がかりになります。

## 問い×答えマトリクス

> この節の要点：クエリと現記事の答えをマトリクス化し、リライト・新規・Won'tを判断する。

| クエリ（問い） | 現記事の答え | 適合 | 次のアクション |
|---|---|---|---|
| 副業 始め方 初心者 | H2-1〜3でカバー | ○ | 維持・強化 |
| 副業 バレる | 軽く触れるのみ | △ | H2追加 or 別記事 |
| 副業 確定申告 | 未カバー | × | 別記事（ジャーニー） |

1記事で全部答えようとしない。第2章のMust / Must Not、第3章の削ぎ落としと同じ判断です。

### ポイント

- Search Consoleのクエリ＝実際の問い。想定と照合する
- 表示多・選ばれにくい → 外門。自分がタブを閉じる → 防波堤・導管
- ヒートマップでH2単位で止まる＝関所の詰まり（6-6節参照）
- 問い×答えマトリクスで、リライト vs 新規を判断

### よくある間違い

| 間違い | 問題 | 改善の方向 |
|---|---|---|
| 想定KWだけ見る | 実際の問いを見逃す | Search Consoleのクエリを必ず確認 |
| 無関係クエリで記事を膨らます | 焦点がぼやける | 別記事化を検討 |
| クエリを全部追う | 段取りが崩れる | マトリクスで優先付け |
| 離脱位置を見ない | 関所特定できない | 自分がどこで止まったかをスクロール分析・ヒートマップで確認（6-6節） |
