# 6-6 精密検査の実務フロー

Search ConsoleとAnalyticsを開くつもりが、忙しくて後回しになっていませんか。まず、あなた自身が検索結果を眺め、クリックする前に判断した経験を思い出してください。計器は、その体験を振り返るための道具です。診断機セットと月次60分ルーティンを固定しないと、予兆を逃し、改善だけが止まります。

---

## 検査工具セット

> この節の要点：Search Console＋GA4が診断機セット。ヒートマップは関所詰まりの補助工具。

| 工具 | 主な用途 | 見る第2の返球 |
|---|---|---|
| Search Console | 検索パフォーマンス | 表示、クリック率、クエリ、順位 |
| Analytics（GA4） | サイト内の自分の体験 | 即去り、読み続け、エンゲージメント、流入 |
| ヒートマップ（任意） | スクロール・クリック | 関所での詰まり |
| スプレッドシート | 記録・優先度管理 | 改善前後の比較 |

無料のSearch Console＋GA4だけで、本章の故障診断は可能です。高価な工具より、点検の段取りが重要です。

### ヒートマップとは何か

ヒートマップは、自分がページ上で目を止め、クリックし、どこまでスクロールしたかを色の濃淡で可視化するツールです。赤（注目が集中）から青（ほとんど見ていない）のグラデーションで、あなた自身が検索して記事を開いたときの体験を振り返る補助になります。

初心者向けに言い換えると、自分が記事を読んだとき、どこで足が止まり、どこでタブを閉じたかを思い出す手がかりを、ヒートマップが色で示してくれます。自動車整備士が診断機で内部を映像化するように、ヒートマップは自分の読者体験を画面の上に映し出す工具です。

Search ConsoleとAnalyticsでおおまかな異常は把握できます。より細かく関所の詰まりを見たいときに、ヒートマップを追加します。寿司職人が板の上を見て次のネタの順番を決めるように、ヒートマップは次の改善の段取りを決める補助工具です。

## 月次精密検査、60分ルーティン

> この節の要点：全体異常→記事別精密→記録→前月効果確認の4フェーズを毎月60分で固定。

### フェーズ1：全体の異常確認（10分）

Search Console → 過去28日 vs 前28日を比較。

```
□ 表示回数：±20%以上の変動はないか
□ 平均クリック率：低下しているページはないか
□ クリック：急減記事はないか
```

異常あり → 第6-2節の予兆パターンへ。

### フェーズ2：記事別の精密検査（30分）

今月の重点記事3本（第6-5節で選定）について：

```
1. Search Console：クエリタブ → 想定内/外を分類（第6-4節）
2. Search Console：選ばれ方・表示 → 外門の判定
3. Analytics：即去り・読み続け → 防波堤・導管の判定
4. 問い×答えマトリクスを1行更新
5. 優先度と今月のアクションを1行メモ
```

ヒートマップを使う場合は、フェーズ2の3のあとに、関所（H2）前後の色の変化を確認します。

### フェーズ3：改善の記録（10分）

スプレッドシート例：

| 月 | 記事 | 症状 | 原因レイヤー | アクション | 次月確認 |
|---|---|---|---|---|---|
| 6月 | /side-job/ | 選ばれ↓ | 外門 | title改稿 | 7月再確認 |

### フェーズ4：前月改善の効果確認（10分）

先月リライトした記事の第2の返球の変化を確認。

```
改善前 選ばれ方 1.1% → 改善後 1.9%  → 外門改善、効果あり
改善前 即去り 72% → 改善後 68%   → 微改善、H2-2を次点検
```

再試運転。自動車整備士が修理後にエンジンをかけるのと同じです。

## 四半期の深掘り検査（任意）

> この節の要点：月次で続く異常やハブ記事は四半期に競合・リンク・鮮度・全面リライト要否を深掘り。

月次で異常が続く記事、またはビジネス上重要なハブ記事（第5-5節）について、四半期に一度：

- 競合の検索結果の確認（外門の相対評価）
- 内部リンクの見直し（物流）
- 情報の鮮度・更新日（E-E-A-T）
- 全面リライトの要否（第11章）

---

## チーム・個人での役割分担

> この節の要点：検査→診断→修理→再試運転の段取り。一人でも役割分担の型は同じ。

| 役割 | 担当 | 作業 |
|---|---|---|
| 設計士（ライター） | 問い×答えの判定、リライト執筆 | マトリクス、本文改善 |
| 技術 | 構造・インデックス確認 | クロール、構造化データ |
| 編集 | 優先度の最終決定 | 第6-5節の承認 |

一人で回す場合も、検査（データ）→ 診断（原因）→ 修理（リライト）→ 再試運転の段取りは同じです。

---

## 第1章から第7章の比喩の階段

> この節の要点：第6章は出荷後の精密検査。第7章の証明書へ続く比喩の階段を確認する。

第6章が全体のどこに位置するか、一度確認しておきましょう。

```
第1章  手紙を書く（構造の礼儀）
第2章  問いを読む（宛名）
第3章  導管を設計する（段取り）
第4章  玄関を磨く（入口で去らせない）
第5章  物流を整える（通信規格）
第6章  精密検査（第2の返球を診断する）
第7章  証明書を発行する（正当性の宣言）
```

出荷して終わりではない。第2の返球を精密検査し、改善を継続する。自動車整備士の定期点検と同じです。寿司職人が毎日板を磨き、握りの反応を見て次の段取りを調整するように、第6章は出荷後のおもてなしを続ける章です。第7章では、その上に正当性の証明書を載せ、本書の思想を完成させます。

### ポイント

- Search Console＋GA4＝診断機セット。月次60分ルーティン
- ヒートマップ＝自分がどこで止まったかを振り返る補助工具。関所の詰まりを可視化する
- 全体異常 → 記事別精密 → 記録 → 前月効果確認
- 改善前後の比較＝再試運転
- 第6章で精密検査の型が身につく。第7章の証明書へ続く

### よくある間違い

| 間違い | 問題 | 改善の方向 |
|---|---|---|
| 工具だけ入れて使わない | 予兆を逃す | 月次ルーティンをカレンダー固定 |
| 毎回違う手順 | 比較不能 | フェーズ1〜4を固定 |
| 記録しない | 効果がわからない | スプレッドシート1行 |
| 検査だけで修理しない | 改善ゼロ | 今月3本のアクション必須 |
