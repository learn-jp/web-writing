# 4-1 見出しの役割と種類、スクリーニングゲートとして

第3章で見出しを設計したあなたは、すでに「論理の骨格」を持っています。けれども、論理が正しくても、自分が入口でタブを閉じれば、導管は空のままです。第4章は、その設計図に「人間の心」を載せる章です。小売店の看板のように、見出しは検索結果を見てクリックする前に「この関所を通る価値があるか？」と判断する、最初のスクリーニングゲート。検索・SNS・AIのどの入口から来ても、誠実なゲートが中へ招き入れます。

## 第3章の「関所」と第4章の「ゲート」の違い

> この節の要点：第3章は論理構造（関所）、第4章は表現（ゲート）。論点は同じでも、看板が読者の足を止めるかどうかを決める。

第3章で見出しを設計したあなたは、すでに「論理の骨格」を持っています。H2の並び、PREPの骨格、見出しだけで通り道が通るか。導管の設計図は、そこで完成しました。

第4章は、その設計図に「人間の心」を載せる章です。論理が正しくても、自分が入口でタブを閉じれば、第1章から繰り返してきた「離脱＝消滅」のまま、導管は空のままです。

第3章が答えた問い：「この記事の論理構造は、正しいか？」  
第4章が答える問い：「この関所を、自分は通りたいと思うか？」

自動車整備士の比喩を続けます。第3章は「ラインの設計」。部品がどの工程を経由するか。第4章は「各工程の入口」。「ここに入る価値がある」と作業者（読者）に伝える看板と照明です。

導管が完璧でも、入口が暗く、看板が読めなければ、部品は入口の前で止まります。Webでは、それが離脱。第1章で述べた、タブを閉じた瞬間の消滅です。

> 見出しは、自分が立ち止まり、「この関所を通る価値があるか？」を判断するための、最初のスクリーニングゲートである。

---

## スクリーニングゲートは一瞬で審査される

> この節の要点：見出しの前で、自分は①問いとの関連②答えがありそうか③読む価値があるかを一瞬で審査する。

あなたが書いた見出しの前で、自分は立ち止まります。第2章で、Webではスキャンが基本だと述べました。見出しは、スキャンのたびに訪れる関門です。

自分の頭の中では、次の審査が一瞬で行われます。

```
① これは、自分が投げた問い（ボール）に関係あるか？
② 通った先に、求めている答えがありそうか？
③ 読むのに、時間と気力を使う価値があるか？
```

3つすべてに「Yes」。その関所を通過し、段落へ進みます。1つでも「No」。スキップ、またはタブを閉じる。

第3章の見出し「就業規則について」と、第4章の見出し「始める前に確認：就業規則で副業は許可されているか」。論理構造（関所の位置）は同じでも、ゲートの通過率は天と地ほど違います。

| 第3章の視点（設計） | 第4章の視点（表現） |
|---|---|
| 関所の位置は正しいか | ゲートの看板は読めるか |
| 1見出し1論点か | 通過したいと思わせるか |
| 階層は論理的か | 一瞬で判断できるか |
| 骨格として機能するか | タブを閉じる前に足を止められるか |

## 見出しは3つのレイヤーに同時に届く

> この節の要点：1つの見出しは人間の読者・ジャンプ読み・検索エンジン・AIに同時に届く。H1＝外門、H2＝内門、構造の印＝配送ラベル。

あなたが書いた1つの見出しは、4つの受け取り手に同時に届きます。人間の読者、記事内のジャンプ読み、検索エンジン、そしてChatGPT・GeminiなどのAI。それぞれに、見出しの役割が異なります。

### レイヤー1：検索結果・SNSタイムライン（H1＝記事タイトル）

ゲートの種類：外門。「この記事に入るか、入らないか」

読者は、まだ記事の中にいません。検索結果、SNSのリンク、AIの回答内リンク、通知。導管の外から、あなたの玄関を見ています。

### レイヤー2：記事内のH2・H3

ゲートの種類：内門。「この関所を通るか、スキップするか」

読者は記事に入りました。しかし、すべての関所を通る義務はない（ジャンプ読み）。各H2は、独立したスクリーニングゲートです。

### レイヤー3：コンピューター（構造の印）、検索エンジンとAIへのマッピング

ゲートの種類：配達の可否。検索エンジン、読み上げ、AI引用（ChatGPT・Gemini等）

第1章・第3章の領域。見出し・title・meta は、人間のゲート（レイヤー1・2）と同じ約束を、機械の知性に伝える配送ラベルです。

検索エンジンもAIも、問いを理解し、最適な答えを選ぶ知性です。H1〜H4の階層、title タグ、meta description から情報のマッピング（構造化）を組み立て、「このページは、どの問いに、どの順序で答えているか」を理解しようとします。構造が整った見出しは、AIが記事を要約・引用するときにも内容が歪みにくくなります。

```
人間のゲート（H1・リード）  →  入る／通る／タブを閉じる
機械のマッピング（構造の印） →  問いと答えの対応が正しいか
自分の選択（開いてすぐ戻る／読み続ける）    →  問いに答えられたかの事実（第2章）
```

3つは別系統ではありません。誠実なゲートは、正しいマッピングと、自分が開いてすぐ閉じない設計（つまり、問いへの適合）に収束します。第4章では人間のゲートに集中しますが、キーワードの自然な配置（第5章で詳述）は、外門の発見性と正当性の証明の両方に触れます。

### 3レイヤーをHTMLで見る

同じ記事でも、見出しの設計が「玄関の看板」になります。

```html
<title>副業の始め方｜初心者が今週末に登録まで進む3ステップ</title>
<h1>副業の始め方｜初心者が今週末に登録まで進む3ステップ</h1>
<p>結論：最初の一歩は、就業規則の確認です。</p>
<h2>始める前に確認：就業規則で副業は許可されているか</h2>
<p>就業規則を確認してください。</p>
<h2>初心者向け｜在宅で週末だけ試せる副業3選</h2>
<p>週末だけ試せる選択肢を3つ紹介します。</p>
```

「ブラウザでの表示結果（見た目）」：

- 検索結果では title が外門の看板として表示され、前半に核心が見える
- 記事内では H1 が玄関の表札、H2 が内門の看板として機能する
- 各H2だけジャンプして読める（ジャンプ読みへの配慮）
- 検索エンジン・AIも、見出し階層から問いと答えの対応を理解しやすい

寿司職人がネタの順番を決めるように、あなたは見出しの順番と文言で、読者がどこに足を止めるかを設計します。

## 検索意図の型ごとにゲートの見せ方を変える

> この節の要点：Know / Do / Go / Buy / 共感型に応じて、ゲートの約束（ここを通れば○○がわかる/できる/着く/選べる）を変える。

第2章の検索意図（Know / Do / Go / Buy）に応じて、ゲートの見せ方が変わります。あなたのペルソナが投げた問いの型を確認し、対応するゲート設計を選んでください。

### 答え型（Know向け）

ゲートの約束：「ここを通れば、○○がわかる」

```
✓ 「インボイス制度とは？登録義務と開始時期を整理」
✗ 「インボイス制度について」（通過理由が不明）
```

設計のコツ：問いの言葉を含め、答えの一部を見出しに載せる。

---

### 手順型（Do向け）

ゲートの約束：「ここを通れば、○○できるようになる」

```
✓ 「クラウドソーシング登録｜初心者が30分で完了する手順」
✗ 「登録方法」（誰向け？どれくらいかかる？）
```

設計のコツ：完了イメージ（30分で完了）と対象（初心者）を明示。

---

### 到達型（Go向け）

ゲートの約束：「ここを通れば、求めていた場所に着く」

```
✓ 「楽天 公式ログインページへの行き方（2026年最新）」
```

設計のコツ：行き先を具体的に。迷わせない。

---

### 判断型（Buy向け）

ゲートの約束：「ここを通れば、選ぶ基準がわかる」

```
✓ 「ノートPCの選び方｜用途別おすすめ5機種を比較」
```

設計のコツ：比較・選び方の軸を見せる。押し売り感を出さない。

---

### 共感型（SNS・入口向け）

ゲートの約束：「ここを通れば、自分ごととして読める」

```
✓ 「『副業、何から始めれば？』と検索したあなたへ」
```

設計のコツ：問いの言葉をそのまま借りる。第2章のペルソナの声。

---

## H1とH2は外門と内門で役割が異なる

> この節の要点：H1＝外門、リード＝玄関ホール、H2＝内門、H3＝内門の小関。外門だけ通過して、リードでタブを閉じるケースに注意。

あなたが設計する見出し階層は、玄関の外門から内門まで、段階的に誘導します。

| 要素 | 外門 / 内門 | ゲートの問い |
|---|---|---|
| H1（タイトル） | 外門 | この玄関から入る価値があるか？ |
| リード文 | 玄関のホール | 中に進んで大丈夫か？（第4-3節） |
| H2 | 内門 | この関所を通る価値があるか？ |
| H3 | 内門の小関 | この細部まで読むか？ |

H1で外門を通過したあと、リードでタブを閉じるケースは少なくありません（第4-3節）。H2のゲート設計は、ジャンプ読みと、タブを閉じさせない設計の両方に効きます。

## 第3章の設計名を第4章のゲート文言に言い換える

> この節の要点：アウトラインの論理名を、読者向けのゲート文言に言い換える。論点は同じでも看板が通過率を決める。

執筆の順序は、次の通りです。あなたが第3章で決めた論理名を、第4章で読者向けのゲート文言に言い換えてください。

```
第3章：アウトラインで H2 の「論理名」を決める
        ↓
第4章：各 H2 を「スクリーニングゲート」として言い換える
        ↓
本文：PREP で返球を完成させる
```

副業記事の例

| 第3章（設計） | 第4章（表現・ゲート） |
|---|---|
| H2：副業の種類 | H2：初心者向け｜在宅で週末だけ試せる副業3選 |
| H2：就業規則 | H2：始める前に確認：就業規則で副業は許可されているか |
| H2：登録手順 | H2：今週末に登録まで進む4ステップ |

論点は同じ。ゲートの看板が、読者の足を止めるかどうかを決めます。自動車整備士が部品のラベルを正確に貼るように、あなたは見出しに「ここに何があるか」を明示します。

---

### ポイント

- 見出し＝スクリーニングゲート。一瞬で通る価値があるかを判断される
- 第3章の関所＋第4章の看板＝通過率の高い入り口
- H1＝外門、H2＝内門、リード＝玄関ホール
- 意図の型（Know/Do/Go/Buy/共感）ごとに、ゲートの約束を変える
- アウトラインの論理名を、読者向けのゲート文言に言い換える

### よくある間違い

| 間違い | 読者の体験 | 改善の方向 |
|---|---|---|
| 第3章の見出しをそのまま公開 | 骨格は良いが、ゲートが通過されない | 第4章の視点で言い換え |
| クリックばかり狙う H1 | 外門は通過、リードでタブを閉じる | 約束と中身を一致させる |
| 全H2が同じ語尾 | ゲートが単調、スキャンで飛ばされる | 約束の型は揃え、表現に変化 |
| キーワードだけの H1 | 審査①は通過、②③で脱落 | 答えの一部または約束を追加 |
