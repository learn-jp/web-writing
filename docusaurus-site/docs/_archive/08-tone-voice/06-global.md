# 8-6 多言語・グローバル展開時の注意

8-1節から8-5節までは、主に日本語のWeb文章を想定しました。サイトを英語化する、海外向けメディアを立ち上げる、在住外国人向けにページを追加する。「日本語版を機械翻訳すれば、とりあえずグローバル対応」と考えず、トーン設計の難所を押さえてください。多言語展開は、第5章の検索を世界規模の発見インフラとして設計する考え方（hreflang、URL設計）とも接続します。ここでは、声とトーンの観点に絞ります。

## 翻訳とローカライズ、ボイスは同じ

> この節の要点：翻訳は言語の対応、ローカライズは文化の適応。ボイスは共通、トーンは現地で調整する。

| 作業 | 目的 | ボイス・トーン |
|---|---|---|
| 翻訳（Translation） | 言語の対応 | 原文のトーンを可能な限り維持 |
| ローカライズ（Localization） | 文化・法制度・単位の適応 | トーンを現地に合わせて調整 |
| トランスクリエーション | 意図の再執筆 | ボイスは維持、表現は現地で再設計 |

寿司屋が海外店舗を出すとき、ネタの鮮度と説明の誠実さ（ボイス）は同じでも、箸の渡し方やメニューの例え（トーン）は現地の食文化に合わせます。Webも同じです。第7章の証明書（著者、出典、更新）の構造は、言語を問わず維持します。

## 敬体・常体の問題は、言語ごとに再設計する

> この節の要点：敬体・常体は日本語特有の道具。英語では formal / neutral / conversational など別の軸で距離感を設計する。

8-2節の敬体・常体は、日本語特有のトーン道具です。英語では、formal / neutral / conversational など、別の軸で距離感を設計します。

| 日本語 | 英語の距離感の例 | 注意 |
|---|---|---|
| 敬体（です・ます） | Neutral polite（We recommend…） | 過剰な Please note の連打 |
| 常体（だ・である） | Direct（Start by checking…） | 命令調と誤解されない |
| 共感表現（8-5節） | Acknowledgment（If you're worried about…） | 文化によっては過剰に感情的 |

ガイドライン（8-4節）は、言語ごとの「デフォルト文体」を1行ずつ定義します。翻訳者・現地ライターが、日本語版の敬体を英語の casual に置き換える、といった事故を防ぎます。

## 語彙と比喩、第8-3節の言い換え表を言語別に

> この節の要点：言い換え表は言語ペアごとに持つ。和製英語や比喩は、現地読者に届くか確認する。

8-3節の言い換え表は、言語ペアごとに持ちます。カタカナ語は英語にそのまま残せないことが多く、和製英語（サラリーマン、ハウトゥの直訳など）も再検討が必要です。

| 日本語（表層） | 直訳の罠 | ローカライズ例 |
|---|---|---|
| 就業規則 | work rules（不自然） | employee handbook / company policy |
| 副業 | side job（軽い） | moonlighting / secondary employment |
| 検索エンジン | そのまま可 | search engine（初出定義は各言語で） |

比喩（整備士、寿司職人）も、現地読者に届くか確認します。自動車整備の比喩は米欧では通じやすい一方、例えを増やしすぎると本文が長くなり、第9章で扱うモバイルでの読み続けと矛盾します。

## 法制度・YMYL、第7-5節は国ごとに別記事

> この節の要点：YMYLの中身は国・地域で異なる。日本語記事の翻訳だけでは、証明書の欄が偽情報になる。

副業の届け出、医療情報、金融商品。YMYLの中身は国・地域で異なります。日本語記事を翻訳しただけでは、証明書の欄が偽情報になります。

```
✗ 日本の就業規則の記述を英語に翻訳し、
   「In Japan…」の注釈なしでグローバル向けトップに掲載

✓ 日本向け／米国向け／EU向けでURLまたはhreflangを分け、
   各国の法令名・相談先を現地監修者が確認
```

整備記録簿のフォーマット（著者・根拠・更新）は共通でも、記載する法令と数値は現地版です。第7-4節の監修者欄も、言語圏ごとに必要なら分けます。

## 検索とURL、第5章との接続

> この節の要点：hreflangとURL設計で、読者を正しいトーンの言語版へ誘導する。クエリ分析は言語別に行う。

多言語サイトでは、検索を世界規模の発見インフラとして設計し、各言語版の対応を検索エンジンに伝える必要があります（第5章）。トーンの観点では、次を確認します。

| 項目 | トーン・ボイス上の意味 |
|---|---|
| hreflang | 言語別URLの対応。読者を正しいトーンの版へ |
| タイトル・meta | 各言語で自然な見出し（第4章・第5-3節） |
| 内部リンク | 言語をまたいでリンクしない（読者の混乱） |
| クエリ分析（第6章） | 言語ごとに第2の返球を読む |

日本語版で効いた共感表現が、英語版のクエリでは別の不安を示すことがあります。8-3節と同様、語彙表は言語別に更新します。

## チーム体制、翻訳者に渡すパック

> この節の要点：原文だけ渡すとボイスが失われる。ガイドライン・用語集・良い例・YMYL監修フローを翻訳者パックに含める。

外注翻訳者に、原文だけ渡すとボイスが失われます。8-4節のガイドラインに加え、次を渡します。

1. ボイスステートメント（各言語版または英語共通版）
2. 禁則語・推奨語（言語別）
3. 良い例1本（現地語で書いた模範段落があると理想）
4. YMYL該当箇所の監修フロー
5. 用語集（製品名、固有名詞の訳語統一）

寿司屋が海外店の板長に、塩の量と説明の順序を引き継ぐように、声のレシピは言語を超えて引き継ぎます。

---

## グローバルでも、店は一つ

> この節の要点：多言語はボイスを薄める口実にならない。第7章の更新宣言は、言語版ごとに適用する。

### この節の整理

- 翻訳≠ローカライズ。ボイスは共通、トーンは文化で調整
- 敬体・常体は言語ごとに再設計（英語の formal/neutral 等）
- YMYL・法令は国別記事。証明書の欄は現地監修
- ガイドライン・用語集・良い例を翻訳者パックに含める

### よくある間違い

| 間違い | 問題 | 改善の方向 |
|---|---|---|
| 機械翻訳のみ | トーン崩壊、YMYLリスク | 人間レビュー＋用語集 |
| 日本語比喩の直訳 | 読者に届かない | 現地で比喩を選び直す |
| 英語版だけ古い | 信頼の不一致 | 言語別更新日（7-4節） |
| hreflang未設定 | 誤言語版が表示 | 第5章の設計とセット |
