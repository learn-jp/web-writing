# 7-3 専門性は、用語を並べることではない

Expertise（専門性）は、E-E-A-Tの4要素のひとつです。しかし、多くの初心者がここで誤解します。「専門用語を多く使えば、専門性が上がる」と。本章では、整備士と寿司職人の比喩から、本当の専門性とは何かを見ていきます。

## 整備士は、専門用語で客を黙らせない

> この節の要点：本当の権威性とは、読者の問いに、現場の知恵で、具体的かつ責任を持って応えることである。

整備工場に、こんな整備士を想像してください。

「ローターとパッドの摩擦係数が閾値を超えており、キャリパーのピストンシールに起因する。」

客は、不安を抱えて来店したのに、黙って頷くだけになります。理解したのか、信頼したのか、わかりません。そして、見積もりだけ信じて契約する。それはAuthority（権威）ではなく、情報の非対称による従属です。

優れた自動車整備士は、こう説明します。

```
「ブレーキを踏むと、左右で音が違いますね。
  左前のパッドが薄くなっています。
  このままだと、ディスクも傷つく可能性があります。
  今日交換すれば、部品代と工賃で〇〇円、1時間ほどです。
  来週以降だと、ディスク交換も必要になり、〇〇円増えます。」
```

専門用語は、裏側にあります。表に出すのは、客の問い（不安）に対する、具体的で責任ある答えです。

Webライティングも、同じです。

> 本当の権威性（Authoritativeness）とは、読者の問いに、現場の知恵で、具体的かつ責任を持って応えることである。

寿司職人がカウンター越しに「今日は脂の乗った中トロです。少し塩で」と伝えるように、専門性は相手の問いに届く言葉で示します。

---

## 専門用語の羅列＝空の証明書

> この節の要点：専門用語の羅列はExpertiseではない。ペルソナの問いの言葉で直接答えることが、真の専門性である。

世の中には、専門用語を多く使えばExpertiseが上がるという誤解があります。

```
✗ 「E-E-A-Tの観点から、SERPのクリック率を改善し、
    クローラビリティを最適化することで、インデックス効率が向上します」
```

読者、ペルソナの健太さんは、副業の始め方を知りたいのに、辞書を読まされている気分です。スキャン段階で消滅します（第1章・第4章）。SNSで要約されても、AIが引用しても、届くのは専門用語の羅列だけです。

```
✓ 「副業を始める前に、就業規則を確認してください。
    多くの会社では、届け出が必要です。
    確認方法は、社内ポータルの『就業規則』、
    または総務への問い合わせです。」
```

専門用語（就業規則、届け出）が出てきても、健太さんの問いに直接答えている。これがExpertiseです。

---

## 権威性の3条件、整備士の説明から学ぶ

> この節の要点：権威性は声の大きさではなく、問いに届く精度である。具体性・責任・問いへの直結の3条件を満たす。

自動車整備士が客に説明するとき、優れた返答には共通の条件があります。Web記事にも、そのまま当てはまります。

| 条件 | 整備士の例 | Web記事の例 |
|---|---|---|
| 具体性 | 左前パッド、〇〇円、1時間 | 数字、手順、期間、条件 |
| 責任 | このままだとディスクも傷つく | デメリット、例外、限界を書く |
| 問いへの直結 | 客の「音が気になる」に答える | ペルソナの問いの言葉で始める |

権威性は、声の大きさではない。問いに届く精度です。

第2章のMust / Must Not、第3章のPREP、第4章の防波堤。すべて、この3条件を満たすための設計でした。E-E-A-Tは、別枠の検索エンジン向け作業ではなく、設計の延長です。

---

## 「わかるように書く」は、専門性の放棄ではない

> この節の要点：平易な言葉で書くことは、専門性を翻訳する高度な技術である。ペルソナの問いの高さに、ちょうど届く返球を設計する。

「専門家向けに書けば、権威性が出る」。これも誤解です。

自動車整備士が客にわかる言葉で説明するのは、専門性を捨てているのではありません。専門性を翻訳しているのです。複雑な故障を、客の不安に届く言葉に変換する。それは、高度な技術です。

Webでも同じです。

- 平易な言葉 ＝ 誰でも書ける、ではない
- 平易な言葉 ＝ 問いの深度に合わせた翻訳

ペルソナの知識量（第2章）を見誤れば、上すぎても下すぎても不適合です。Expertiseとは、相手の問いの高さに、ちょうど届く返球を設計する能力です。寿司職人が客の好みに合わせて握り方を変えるように、設計士も読者の問いの高さに合わせて言葉を選びます。

---

## 責任を持って応える、わからないと言う勇気

> この節の要点：わからないことをわからないと言うことは、Trustworthinessの核心である。限界と前提を書くことが、証明書の誠実さを上げる。

自動車整備士が「原因は特定できません。専門店に紹介します」と言えるのは、弱さではなく信頼です。わからないことをわからないと言う。Trustworthiness（信頼性）の核心です。

Web記事でも同じです。

```
✓ 「2024年時点の情報です。制度改正がある場合は、
    国税庁の公式ページ（リンク）で最新を確認してください。」
✓ 「個人差があります。医師への相談をおすすめします。」
```

限界と前提を書くこと。それは、権威性を下げるのではなく、証明書の誠実さを上げます。

---

## 現場の知恵、一次情報として刻む

> この節の要点：ネット情報の再包装では証明書の欄は埋まらない。現場の知恵と一次情報だけが、あなたにしか書けない段落になる。

自動車整備士のExpertiseは、マニュアルだけから来ません。「同じ症状を10台見て、3台はこう直した」。そういう現場の知恵です。

Web記事のExperience / Expertiseも、一次情報から来ます。

- 自分で試した結果
- インタビューした専門家の発言（出典明示）
- 自社のデータ（匿名化・許可の範囲で）
- 失敗した施策と、その理由

ネットで見た情報の再包装は、証明書の欄を埋められません。現場、あなたの経験から来た知恵だけが、あなたにしか書けない段落になります。

---

### ポイント

- Expertise ≠ 専門用語の羅列。問いへの具体的・責任ある応答
- 権威性＝声の大きさではなく、届く精度
- 平易な言葉＝専門性の翻訳
- わからない、限界があるを書く＝Trustworthiness
- 一次情報・現場の知恵を本文に刻む

### よくある間違い

| 間違い | 問題 | 改善の方向 |
|---|---|---|
| 専門用語で威圧 | 自分が一瞬でタブを閉じる | ペルソナの言葉に翻訳 |
| 一般論だけ | 誰でも書ける | 一次体験・具体例 |
| デメリットを書かない | 信頼を損なう | 限界・例外を明記 |
| 権威を借りるだけ | 空のExpertise | 自分の応答として再構成 |
