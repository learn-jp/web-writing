# 9-4 タップしやすいCTAの書き方

人差し指の幅は1cm前後で、長いボタン文言は隣の要素と近づき、誤タップを招きます。SNSアプリ内ブラウザや検索結果からの遷移でも、自分は親指一本で次の行動を決めます。短く、具体的に、指一本で意図が通じるCTAの文言を書けば、第5章 Web最適化で設計した行動目的まで、返球を届けられます。

## タップは、指の太さ分の操作

> この節の要点：スマホはクリックではなくタップ。CTAの文言の長さはライターが決め、短く具体的なラベルが一目でわかる小さなスイッチを選ぶ発想で設計する。

第2章（[2-4 デバイスと画面サイズ](../02-reader-media/04-device-context.md)）で触れた通り、スマホはクリックではなくタップです。人差し指の幅は1cm前後。リンクやボタンは離して配置するのがデザイン側の話ですが、CTAの文言の長さはライターが決めます。

長い文言は、

- ボタンが横に伸び、隣の要素と近づく
- 2行に折り返され、タップ領域が読みにくくなる
- 「何をタップすればよいか」が一瞬でわからない

という問題を生みます。狭い整備ピットでは、大きなレバーは使わず、ラベルが一目でわかる小さなスイッチを選ぶ。CTAも同じ発想です。

---

## 良いCTAの三条件

> この節の要点：短い（4〜8字）、具体的（何が起きるかがわかる）、問い・Mustと一致している。CTAの三条件。

### 条件1：短い（4〜8字が目安、最大12字程度）

| 長い（避ける） | 短い（推奨） |
|---|---|
| 詳細資料をこちらからダウンロードしてください | 資料をダウンロード |
| 無料トライアルに今すぐ登録する | 無料で試す |
| お問い合わせフォームはこちら | 問い合わせる |

寿司職人がメニューに「本日のおすすめ握り十貫コース」を並べるより、「おまかせ十貫」と短く書く方が、客の指（目）が止まりやすいのと同じです。

### 条件2：具体的（何が起きるかがわかる）

「こちら」「詳細はこちら」だけでは、タップ後の体験が想像できません。

```
❌ こちらをクリック
❌ 詳細はこちら
✅ 見積もりを依頼する
✅ チェックリスト（PDF）を取得
```

第2章のDo意図（手順を実行したい読者）には、次のアクションが一行でわかるCTAが必須です。

### 条件3：問い・Mustと一致している

CTAは、記事のMust（約束）の延長です。副業の記事で「就業規則チェックリスト」のMustなら、CTAは「チェックリストをダウンロード」。問いとズレたCTAは、返球の最後で別のボールを投げるようなものです。

---

## リンクテキスト（アンカーテキスト）のモバイル向けルール

> この節の要点：本文中のリンクもタップ対象。「こちら」単独を避け、リンク先の内容が想像できる文言に。モバイルのCTA設計は第10章のアクセシビリティとも接続する。

本文中のリンクも、タップ対象です。

| ルール | 例 |
|---|---|
| 「こちら」単独を避ける | ❌ 詳細はこちら → ✅ 副業の届け出ルールを確認 |
| リンク先の内容が想像できる | ✅ 2024年版の就業規則ガイド（PDF） |
| 1リンク1目的 | 1段落にCTAリンクを3つ並べない |

スクリーンリーダー利用者（第10章で詳述）にも、リンクテキスト単体で意味が通じることが重要です。モバイルファーストのCTA設計は、第10章のアクセシビリティとも接続します。

---

## CTAの配置：ファーストビューと記事末

> この節の要点：ファーストビュー内のCTAは答えの予告のあとに置く。記事末のCTAは本文で価値を届けたあと、具体的に次の行動を促す。

### ファーストビュー内のCTA

資料請求型の記事では、リード直後に主CTAを置くことがあります。ただし、ファーストビューをCTAだけで埋めない（第9-3節）。答えの予告のあと、自然な流れでCTAを置きます。

```
H1
リード（問いへの適合＋答えの予告）
[主CTA：資料をダウンロード]
最初のH2
```

### 記事末のCTA

本文で価値を届けたあと、次の行動を促します。ハウトゥ記事なら「チェックリストを保存」、比較記事なら「比較表（PDF）を取得」。

整備士が点検報告のあと「次回の予約はこちら」と短く案内するように、記事末のCTAは押し付けがましくなく、具体的に。

---

## デザイナー・エンジニアとの協議ポイント

> この節の要点：CTAの文言はライター、サイズ・色・余白はデザイン、実装はエンジニア。執筆時に文言案・行先・配置の意図を共有する。

CTAの文言はライター、ボタンのサイズ・色・余白はデザイン担当、リンクの実装はエンジニア。モバイルファーストでは、次を執筆時に共有しておくと齟齬が減ります。

```
□ 主CTAの文言案（4〜8字）
□ タップ後の行先（フォーム、PDF、別ページ）
□ ファーストビューにCTAを置くか
□ 副CTA（テキストリンク）の有無
```

「ボタンはデザインの仕事」と切り捨てず、文言と配置の意図を伝える。それが、狭い画面での返球の完成度を上げます。

---

### ポイント

- スマホのCTAは短く（4〜8字）、具体的に
- 「こちら」単独、長い敬語句は避ける
- Must・問いと一致した次の行動を示す
- デザイン担当と文言・配置を共有

### よくある間違い

| 間違い | 問題 | 改善の方向 |
|---|---|---|
| CTAが15字以上 | 折り返し・誤タップ | 動詞＋目的語に圧縮 |
| 本文中に「こちら」連発 | リンク先が不明 | リンク先の内容をテキストに |
| ファーストビューがCTAのみ | 答えの予告がない | リードで価値を示してからCTA |
| PC用の長いボタン文言を流用 | スマホで読みにくい | モバイル用に文言を別案 |
