# 9-1 モバイルファーストとは

スマホで読みにくいと感じたことがあるなら、原因はあなたの文章力だけではないかもしれません。検索結果からのタップ、SNSのリンクプレビュー、AI回答に引用されたURLからの遷移。いずれも最初に見える画面はスマホであることが多く、第5章のWeb最適化（検索・SNS・AI引用）で整えた外門も、狭い画面で初めて試されます。段落の切り方、結論の位置、見出しの密度は、後からではなく最初から決めれば、どの画面でも同じ返球を届けられます。

## 最小の整備ピットから設計する

> この節の要点：狭いピットで工具配置と作業順序が整っていれば、広いピットでもそのまま使える。モバイルファーストも同様に、最小の画面から返球を設計し、広い画面へ展開する。

自動車整備士の工場には、大小さまざまな作業場（ピット）があります。狭いピットで工具の配置、作業順序、安全動線が整っていれば、広いピットに移しても基本設計はそのまま使えます。逆に、広いピットだけを想定して組み立てた段取りを、後から狭いピットに押し込むと、工具が届かず、作業が滞ります。

Webライティングも同じです。

```
従来の発想（デスクトップファースト）
  広い画面で執筆 → あとからスマホ用に縮小 → 詰まり・スクロールせず戻る

モバイルファースト
  狭い画面で設計 → 広い画面へ自然に展開 → どこでも読める
```

第2章（[2-4 デバイスと画面サイズの影響](../02-reader-media/04-device-context.md)）で述べたように、日本のWebアクセスの多くはすでにスマホが過半です。あなた自身も、通勤電車、休憩時間、寝る前のベッドの上で記事を開いているはずです。SNSのタイムラインからタップしたときほど、通知や乗り換えで中断されやすい文脈で開きます。

モバイルファーストとは、技術用語というより、執筆の起点を「自分の手の中の画面」に置く姿勢です。

---

## 「あとから縮小」が失敗する理由

> この節の要点：PCで書いた長文をそのままスマホに載せると、段落の膨張、結論の埋没、表の崩れが同時に起きる。寿司を握り直すのではなく、最初から客の口の大きさ（画面）を想定する。

| 問題 | スマホでの体感 | 第2章との接続 |
|---|---|---|
| 段落が長大に見える | 1画面に3〜5行しか見えない | スキャンしてすぐ戻る判断が早まる |
| 結論が下に沈む | スクロール前に答えが見えない | ファーストビューで消滅 |
| 表・横並びが崩れる | 情報が読めない | 問いへの返球が途切れる |

寿司職人が大きな板で10貫分のネタを並べ、客の前に出す直前に小皿に詰め替えるようなものです。握りの形、シャリの量、出す順番は、最初から客の口の大きさ（画面）を想定して決める方が、自然に整います。

## 本書の比喩との接続

> この節の要点：第2章のデバイス文脈から第5章の物流まで、本編で学んだ設計を「実際の封筒サイズ」に落とす工程が第9章である。

モバイルファーストは、本編で学んだ設計を「実際の封筒サイズ」に落とす工程です。

| 本編の章 | 比喩 | 第9章での再適用 |
|---|---|---|
| 第2章 | 問い・返球・デバイス | スマホ文脈（移動中・中断されやすい）を起点に |
| 第3章 | 導管 | 段落・見出しを短い画面向けに再調整 |
| 第4章 | 玄関 | ファーストビュー（スクロール前）に答えの予告 |
| 第5章 | 物流 | 表示速度も「届くまでの時間」として設計。OGP・titleはSNS・AI引用の外門 |

第7章までで、手紙・問い・導管・玄関・物流・精密検査・証明書を学びました。第8章で声を整えたあと、第9章は「届け先の封筒」を最初から狭いサイズで設計する章です。

## モバイルファーストの三原則

> この節の要点：一度に見える量、スクロール前の答えの予告、指一本で意図が通じるCTA（執筆の起点をスマホに移す三原則。）

執筆の起点をスマホに移すとき、次の三つを頭に置いてください。

### 原則1：一度に見える量を前提に書く

スマホでは1画面に3〜5行程度。段落は3〜4文、1段落1主題（第3章の原則）を、より厳密に守ります。

### 原則2：スクロール前に「答えの予告」を置く

第4章の玄関（リード・H1直下）を、スクロールなしで見える範囲に圧縮します。結論ファーストは、モバイルでは「必須」に近い設計です。

### 原則3：操作は指一本分を想定する

リンク・ボタンの文言は短く、タップの意図が明確に（第9-4節）。デザインは担当者と協議しつつ、ライターが書くCTAの文言は、狭い画面でも誤タップしない長さにします。

---

## 整備士と寿司職人の視点

> この節の要点：モバイル向けの短さは情報の削減ではなく、狭いピットで作業できるよう段取りを最初から整えること。第3章の優先順位づけが実戦投入される。

自動車整備士が車両の重量バランスを考えるように、文章にも「読み込みの重さ」があります。寿司職人が「必要な分だけ」ネタを載せるように、モバイル向けのあなたの物語は、冗長な前置きを削ぎ落とします。

これは、情報を削るための削減ではありません。狭いピットで作業できるよう、段取りを最初から整えることです。第3章で学んだ「優先順位づけと削ぎ落とし」が、ここで実戦投入されます。

---

### ポイント

- モバイルファースト＝最初から狭い画面で設計する発想
- 「あとから縮小」は段落・結論・表の配置を後から直せない
- 第2章のデバイス文脈、第3章の導管、第4章の玄関を、スマホ起点で再適用
- 最小の整備ピットに収まれば、どの画面でも通用する

### よくある間違い

| 間違い | 問題 | 改善の方向 |
|---|---|---|
| PC執筆→公開後にスマホ確認 | 構造が固まってから直せない | 執筆中からスマホプレビューを挟む |
| モバイルファースト＝文字を短くするだけ | 導管・玄関の設計が抜ける | 段落・見出し・結論位置を再設計 |
| レスポンシブ＝ライターの仕事ではない | 文言・構成の問題が残る | CTA・表・リードはライターが責任を持つ |
| スマホは若者向け | アクセスの過半はスマホ | すべてのペルソナで主デバイスを確認 |
