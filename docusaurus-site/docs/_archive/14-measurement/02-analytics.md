# 14-2 アクセス解析の読み方（PV・滞在時間・直帰率）

公開後、自分が読者として記事を読み返した体験を、GA4の数字で確かめる。計器は採点表ではなく、「読者としての自分」が留まるかどうかを振り返る道具です。第14章では、同じ計器をポートフォリオ全体の視点で使います。

## 第6章からの接続

> この節の要点：第6章は記事の健康診断、本章は工場の生産ライン監視である。玄関で引き返す割合・読み続け時間・PVの読み方は同じだが、比較の単位が記事からクラスターへ広がる。

第6章では、主要指標の意味と、記事1本での読み方を学びました。第14章では、同じ計器をポートフォリオ全体の視点で使います。

| 指標 | 第6章（記事1本） | 第14章（組織レベル） |
|---|---|---|
| 直帰率（GA4） | その記事の防波堤判定 | 記事タイプ別のベンチマーク比較 |
| 滞在時間（GA4） | 導管の通過判定 | クラスター別のエンゲージメント |
| PV | 参考値 | 新規 vs 既存、流入元別の分解 |

精密検査の対象が1台から工場全体に広がっても、計器の取扱説明書は同じです。第6-3節を「記事の健康診断」、本章を「工場の生産ライン監視」と読み替えてください。

---

## PV（ページビュー）をどう読むか

> この節の要点：PVは単体ではアクション可能ではない。流入元・デバイス・新規/リピーター・ランディングページに分解して読む。

PVは「ページが表示された回数」です。最も見慣れる数字ですが、単体ではアクション可能ではありません（14-1節）。

PVを読むときは、必ず分解します。

```
PVの分解
  ├─ 流入元：オーガニック / 直接 / 参照 / SNS / AI引用（referral）
  ├─ デバイス：モバイル / PC（第9章）
  ├─ 新規 vs リピーター
  └─ ランディングページ別
```

| パターン | 疑うこと | 次の一手 |
|---|---|---|
| オーガニックPV↑、玄関で引き返す↑ | 物流は機能、防波堤が弱い | リード・H1の見直し（第4章） |
| 直接PV↑、読み続けが長い | リピーター・ブランド認知 | 内部リンク・関連記事強化（第5章 Web最適化） |
| SNS PV↑、玄関で引き返す↑ | シェア文と本文のズレ | 外門・ファーストビューの整合（第9章） |
| モバイルPV↑、玄関で引き返す↑ | ファーストビュー問題 | 第9章の短い画面設計 |
| 特定記事PV急減 | インデックス・順位・鮮度 | 第6-2節の予兆、第11章リライト |

寿司職人が「今日の客数」だけ見て満足しないように、PVは「誰が、どこから、何を見たか」の入口です。

## 滞在時間（エンゲージメント）をどう読むか

> この節の要点：滞在時間は長い＝良いではない。意図の型（第2章）とセットで読み、GA4のレポートを月次・四半期で使い分ける。

滞在時間は、自分がページに留まった時間の目安です。GA4では「エンゲージメント時間」「エンゲージメント率」も併用します。

| 状況 | 読み続け時間の読み方 |
|---|---|
| Know型ハウトゥ | 長めは答えが届いた可能性 |
| Go型（公式へ誘導） | 短くても目的達成の可能性 |
| リードが長い結論が遅い | 長いが不満（スキャンして戻る） |
| 関所（H2）で戻る | 特定段落の問題（第6-2節） |

第6章の問い×答えマトリクス（第6-4節）と組み合わせると、読み続け時間が短い原因が「意図不一致」か「結論の遅さ」かを切り分けできます。

### GA4で見るレポート（実務）

| レポート | 用途 | 第6章との対応 |
|---|---|---|
| ページとスクリーン | 記事別PV・エンゲージメント | 記事別精密検査 |
| ランディングページ | 入口記事で引き返す割合 | 外門・防波堤 |
| イベント | CTAクリック・スクロール | 行動目的（第1章） |
| ユーザーのアクイジション | 流入元別の質（検索・SNS・AI引用） | 入り口別の外門・防波堤（第5章 Web最適化） |

月次精密検査（第6-6節）のフェーズ2で、重点3記事についてこれらを確認します。第14章では、四半期にクラスター全体の傾向を見ます。

## 直帰率をどう読むか

> この節の要点：サイト全体の平均直帰を追わない。同タイプ記事との比較と、リライト前後の変化を重視する。

直帰率は「そのセッションで1ページだけ見て去った割合」です。第6章で、防波堤・意図の適合度の計器として学びました。

直帰率の罠は、サイト全体の平均を追うことです。ブログ型サイトでは、一ページだけ見て去るセッションが多くなる構造があります。重要なのは、同タイプ記事との比較と、改善前後の変化です。

```
玄関で引き返す割合の正しい比較
  ×  業界平均 65% だからうち 70% は悪い
  ○  同クラスター記事 A 45% vs B 72% → Bを第6章で診断
  ○  リライト前 71% → リライト後 65% → 防波堤改善の効果（第11章）
```

第11章の再試運転（28日後）では、玄関で引き返す割合（GA4直帰率）の前後比較が標準指標です。第14章のPDCA（14-5節）では、この比較を四半期レポートに集約します。

## Search ConsoleとAnalyticsの役割分担

> この節の要点：GSCは検索結果（外）、GA4はサイト内（内）の工具である。自分が検索から辿る旅に沿って2つを補完関係で使う。

| 工具 | 見える世界 | 主な指標 |
|---|---|---|
| Search Console | 検索結果（外の世界） | 表示、CTR、クエリ、順位 |
| Analytics（GA4） | サイト内（工房の中） | PV、直帰率、滞在時間、CV |
| ヒートマップ（14-4節） | 画面上の行動 | スクロール、クリック、注目 |

```
自分が検索から辿る旅
  検索結果（GSC：外門を通過したか）
      ↓
  ランディング（GA4：防波堤を通過したか）
      ↓
  本文・関所（GA4＋ヒートマップ：導管を通過したか）
      ↓
  CV・遷移（GA4：行動目的を達成したか）
```

整備士が診断機（GSC）と走行テスト（GA4）を使い分けるように、2つは補完関係です。

## 組織ダッシュボードの最小構成

> この節の要点：高価なBIがなくてもスプレッドシートで始められる。ダッシュボードの目的は「見る」ことではなく「今月のリライト3本を決める」こと。

高価なBIツールがなくても、スプレッドシートと無料ツールで始められます。

| シート | 更新頻度 | データ源 |
|---|---|---|
| 北極星KPI | 月次 | GA4、社内CVデータ |
| 記事別スナップショット | 月次 | GSC＋GA4（重点10記事） |
| 改善ログ | 随時 | 第6-6節フェーズ3 |
| 四半期PDCA | 四半期 | 14-5節 |

ダッシュボードの目的は「見る」ことではなく、「今月のリライト3本を決める」ことです（第6-5節、第11-2節）。数字の美しさより、次の一手の明確さを優先します。

## よくある間違い

> この節の要点：PVだけ週次報告、玄関で引き返す割合の業界平均比較、GSCとGA4の混同、全記事精査、アクションなしのデータ閲覧を避ける。

| 間違い | 改善 |
|---|---|
| PVだけ週次報告 | KPIツリーで北極星まで接続（14-1節） |
| 直帰率の業界平均比較 | 同タイプ記事・前後比較 |
| GSCとGA4を混同 | 外（検索）と内（サイト）で分ける |
| 全記事を毎月精査 | 重点3本＋異常記事（第6-6節） |
| データを見てアクションなし | 改善ログに1行必ず書く |
