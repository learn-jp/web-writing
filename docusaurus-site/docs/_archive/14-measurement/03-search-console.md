# 14-3 検索コンソールの活用

ポートフォリオ全体の戦略に接続します。記事の精密検査が積み上がって、ポートフォリオの地図が見える。それが第14章のSearch Console活用です。自分が検索結果から辿った体験を主軸に、GA4の流入元でSNS・直接・AI引用の質も横断的に見ます。

## 第6章からの接続

> この節の要点：Search Consoleは記事1本・クラスター・サイト全体の3レベルで使う。第6章のクエリ分析を組織レベルへ拡張する。

第6-4節では、想定の問いと実際のクエリを照合する問い×答えマトリクスを学びました。第6-6節では、月次精密検査のフェーズ2でクエリタブを開く手順を固定しました。

第14章では、同じ工具を3つのレベルで使います。

| レベル | 問い | 頻度 |
|---|---|---|
| 記事1本 | この記事に来ている問いは想定内か | 月次（第6章） |
| クラスター | ハブと詳細のクエリ分担は適切か | 四半期（第12章） |
| サイト全体 | オーガニックの成長・衰退はどこから。SNS・直接の入口はどうか | 四半期（14-5節） |

Search Consoleは、自分が検索結果から辿った体験を映す主計器です。SNSやAI引用の入口はGA4と併用し、入口ごとの外門・防波堤の故障を切り分けます。

---

## Search Consoleで見るべき4つのタブ

> この節の要点：検索パフォーマンス・ページ別・クエリ別・インデックスの4タブを、月次と四半期の固定ルーティンで開く。

### 1. 検索パフォーマンス（全体）

過去28日 vs 前28日で比較します。

```
□ 合計クリック：±20%以上の変動
□ 合計表示：物流の変化
□ 平均CTR（GSC）：外門全体の健康度
□ 平均掲載順位：参考（単体では判断しない）
```

異常があれば、どのページ・どのクエリから来ているかをドリルダウンします。

### 2. ページ別

記事URLごとの表示・クリック・CTR・順位です。月次精密検査の入口です。

| パターン | 第6-2節の予兆 | 優先度 |
|---|---|---|
| 表示多・外門の通過が弱い | 外門弱い | 高（工数小） |
| 表示減・順位横ばい | 鮮度・競合 | 中（第11-3節） |
| クリック多・玄関で引き返す（GA4と併用） | 防波堤 | 高 |

### 3. クエリ別

実際に来ている問いのリストです。第6-4節のマトリクスの入力データです。

| 分類 | 定義 | アクション |
|---|---|---|
| 想定内 | 執筆時の主KW・副KW | 適合度（○△×）を確認 |
| 想定外だが価値あり | 関連する別の問い | 新規記事 or H2追加（第11章） |
| 無関係 | Must Notに抵触 | Won't or リライトで意図を明確化 |

第8-7節でも触れたように、クエリは語彙表の更新源です。想定外クエリが増えたら、ブランドガイドラインの言い換え表を見直します。

### 4. インデックス・サイトマップ

物流（第5章）の健康確認です。四半期に1回は確認します。

```
□ インデックス未登録の重要URLはないか
□ サイトマップは最新か
□ カニバリ疑いのURLペア（第11-4節）
```

## ポートフォリオ視点のクエリ分析

> この節の要点：クエリを記事ごとに孤立分析しない。クラスター単位で束ね、カニバリ・ハブ弱化・詳細不足を検出する。

### トピッククラスターでの読み方（第12章接続）

```
ハブ記事「副業 始め方」
  ├─ クエリ：副業 始め方 / 副業 とは / 副業 種類
  └─ 役割：広い問いを受け、詳細へ送る

詳細記事「副業 確定申告」
  ├─ クエリ：副業 確定申告 / 副業 青色申告
  └─ 役割：特定の問いに深く答える
```

| 問題 | クエリのサイン | 対処 |
|---|---|---|
| カニバリ | 2URLが同じクエリで競合 | 第11-4節（統合・役割分担） |
| ハブが弱い | 詳細に直接流入、ハブの表示少 | ハブの外門・内部リンク |
| 詳細が不足 | ハブの想定外クエリが多い | 新規詳細記事（第12章） |

## 順位をどう扱うか

> この節の要点：順位は参考計器である。外門の通過（CTR）や適合度を先に疑い、順位だけで判断しない。

順位は参考計器です。同じ順位帯でも外門の通過（CTR）は大きく変わります。title・metaの吸引力（第4・5章）が順位より先に疑われるべき場合が多いです。

```
順位 8位・外門通過 0.5%  →  外門が弱い（直す価値大）
順位 15位・外門通過 3.0%  →  物流改善で表示増を狙う
順位 3位・玄関で引き返す 80%   →  防波堤の問題（順位は関係ない）
```

整備士が「走行は快適だが異音がある」車を、スピードだけで判断しないように、順位は文脈の一部です。

## 月次・四半期のSearch Consoleルーティン

> この節の要点：月次30分は第6-6節と統合、四半期60分は14-5節のPDCAと統合する。固定ルーティンでタブをランダムに開かない。

### 月次（第6-6節と統合、計30分）

```
フェーズ1（10分）：全体の異常確認
フェーズ2（20分）：重点3記事のページ＋クエリ分析
  → 問い×答えマトリクス更新
  → 今月のリライト候補を1〜3本メモ
```

### 四半期（14-5節 PDCAと統合、計60分）

```
□ クラスター別の表示・クリック推移
□ 想定外クエリのトレンド（新しい問いの出現）
□ カニバリ診断（第11-4節ワークシート）
□ 2年以上未更新×表示500以上のリスト（第11-3節）
□ 次四半期の新規記事テーマ候補（第12章カレンダーへ）
```

## データの限界と設計士の姿勢

> この節の要点：Search Consoleのデータは完全ではない。数字に振り回されず、読者の問いに応え続けるための工具として使う。

Search Consoleのデータは完全ではありません。サンプリング、遅延、プライバシー閾値の影響を受けます。数字に振り回されて、読者の問いを忘れることは、設計士の堕落です。

第7章で学んだ誓いを、測定にも適用します。

- 空の返球を返さない → 釣りtitleで外門の通過だけ稼がない
- 消滅を切り捨てない → 一ページだけ見て去る割合が高い＝設計を疑う（自分が読者として戻る場面を振り返る）
- 宣言し、更新し続ける → データで誤りが見えたら訂正（第7-4節）

測定は、採点のためではなく、自分が読者として読み返した体験を確かめ、問いに応え続けるための工具です。

---

## よくある間違い

> この節の要点：順位だけ追跡、孤立クエリ分析、想定外クエリの無視、GSCだけで玄関で引き返す傾向を判断、月次ルーティンなしを避ける。

| 間違い | 改善 |
|---|---|
| 順位だけ週次追跡 | 外門の通過・クエリ適合と束ねる |
| クエリを記事ごとに孤立分析 | クラスターで束ねる（第12章） |
| 想定外クエリを無視 | 新規記事・H2追加の候補に |
| GSCだけで玄関で引き返す傾向を判断 | GA4と併用（14-2節） |
| 月次ルーティンなし | 第6-6節の60分を固定 |
