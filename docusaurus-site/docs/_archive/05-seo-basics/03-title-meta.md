# 5-3 タイトル・メタディスクリプション。情報の配送ラベル

title と meta description を、H1やリードと別物として後から付けていませんか。検索結果で0.5秒の審査を受ける配送ラベルは、SNSのプレビューとAIの引用元としても機能します。第4章の外門と物流規格を一体で設計する必要があります。

---

## titleとmetaは、荷物の外側に貼る配送ラベルである

> この節の要点：title と meta は第4章の外門の検索結果版。SERP・SNSプレビュー・インデクサー・生成AIの四方に読まれる配送ラベル。

第4章で、H1とリードを外門と防波堤として設計しました。`<title>` と `<meta description>` は、その検索結果向けの公式ラベルです。人間が玄関で立ち止まる前に、検索結果の一覧で0.5秒の審査を受ける。ラベルが釣り文句なら、クリックされず消滅する。中身が問いに答えなければ、玄関を通過しても期待外れで去る（第2章）。ラベルと中身の一致は、通信規格であり、読者への誠実さでもあります。

工場に部品を納入するとき、ラベルを貼ります。

- 品名（何の部品か）
- 型番（識別子）
- 注意事項（取り扱い）
- 送り先の目安（どのライン向けか）

Webページのタイトルタグ（title）とメタディスクリプション（meta description）は、これに相当します。検索結果（SERP）に表示され、SNSでシェアされたときのプレビューにも使われ、インデクサーと生成AIも読み取ります。

| 要素 | 配送ラベルとしての役割 | 主な表示場所 |
|---|---|---|
| `<title>` | 品名・主ラベル | ブラウザタブ、検索結果の青いリンク |
| `<meta name="description">` | 補足説明・取り扱い | 検索結果の説明文（任意表示） |
| H1 | 倉庫内の正式名称 | 記事ページ内（第4章） |

第4章のH1（外門）と、title（配送ラベル）は一致させるのが基本。ただし、titleは文字数制約が厳しいため、短く最適化する場合があります。

## タイトルタグ（title）のHTMLと、検索結果での見え方

> この節の要点：title は主ラベルとして最も重いシグナル。HTMLとSERPでの見え方をセットで設計する。

title は、インデクサーにとって最も重いシグナルの一つです。このページの主題は何かの第一宣言。第3章のH1・第4章の外門と矛盾しないラベルを貼ってください。

### コード（HTML）

```html
<head>
  <title>副業の始め方｜初心者が今週末に登録まで進む3ステップ｜○○メディア</title>
</head>
<body>
  <h1>副業の始め方｜初心者が今週末に登録まで進む3ステップ</h1>
</body>
```

### ブラウザ・検索結果での表示結果（見た目）

- ブラウザタブ：「副業の始め方｜初心者が今週…」と表示（長い場合は省略）
- 検索結果：青いリンクとして title が表示される
- ページ内：H1 が別途、外門として表示される

寿司職人がカウンター越しに一言で心を掴むように、title は検索結果一覧での最初の一貫です。0.5秒で「自分向けか」を判断されます。

### title 設計の基本原則

1. 1ページ1 title（H1と同様）
2. 問い・キーワードを自然に含む（第2章のボール）
3. 約28〜32文字（日本語）を目安。SERPで切れないよう前半に核心
4. サイト名は末尾に `｜サイト名`（ブランド）
5. 釣り・過大表現を避ける（第4章）

### テンプレート例

```
[問い・キーワード]｜[具体性・約束]｜[サイト名]

例：
副業の始め方｜初心者が今週末に登録まで進む3ステップ｜○○メディア
```

### title と H1 の関係

| パターン | 使い分け |
|---|---|
| 同一 | シンプル。管理しやすい |
| title を短く最適化 | SERP向け。H1はやや長くても可 |
| title ≠ H1 | 意図的に分ける場合は、約束は一致させる |

```
title：副業の始め方｜今週末登録まで3ステップ
H1：  副業の始め方｜初心者が今週末に登録まで進む3ステップ
```

## メタディスクリプションのHTMLと、検索結果での見え方

> この節の要点：meta は第二関門。直接のランキング因子ではないが、検索結果で選ばれやすさとページ理解に効く。

### コード（HTML）

```html
<head>
  <meta name="description" content="副業を始めるなら、在宅で週末だけ試せる種類を1つ選び、就業規則を確認してから登録を。本記事では、選び方・確認事項・登録手順を3ステップで解説します。">
</head>
```

### ブラウザ・検索結果での表示結果（見た目）

```
┌─────────────────────────────────────────┐
│ 副業の始め方｜初心者が今週末に…｜○○    │  ← title（青リンク）
│ https://example.com/side-job/           │
│ 副業を始めるなら、在宅で週末だけ…       │  ← meta（説明文）
└─────────────────────────────────────────┘
```

読者の0.5秒審査（第4章）は、title と meta で始まります。自分が検索結果を眺め、クリックする前に判断した経験と同じです。ラベルでタブを閉じることもあります。クリック前の消滅です。

| ラベルの問題 | 結果 |
|---|---|
| title が切れて意味不明 | 審査②失敗 → スキップ |
| meta が空・自動生成 | 魅力不足 → 他結果へ |
| 釣り title、中身不一致 | クリック後に期待外れで去る → 消滅 |

### meta 設計の基本原則

1. 120〜160文字（日本語）を目安
2. 結論または約束を含む（第4章リードの圧縮版）
3. CTA（「詳しくはこちら」ではなく具体的内容）
4. キーワードの自然な含有。羅列しない
5. ページごとにユニーク。同じ説明のコピペ禁止

### テンプレート例

```
[結論1文]。[対象・条件]。[記事で得られること]。

例：
副業を始めるなら、在宅で週末だけ試せる種類を1つ選び、就業規則を確認してから登録を。本記事では、選び方・確認事項・登録手順を3ステップで解説します。
```

### meta は直接のランキング因子ではないが、選ばれやすさに効く

検索エンジンは、meta description を直接のランキング因子とは公式に述べています。しかし。

- 検索結果で選ばれる率（クリック率）に影響する
- インデクサーがページ理解の補助に使う場合がある
- 検索結果での見え方＝外門の第二関門

ラベルが読まれ、クリックされる。第4章のゲートと同じ設計思想です。

## 配送ラベルを作る5ステップ

> この節の要点：問い設計から逆算し、H1確定→title最適化→meta圧縮の順でラベルを作る。

ラベル設計は、問い設計から逆算します。整備士が部品番号を確認してからラベルを貼るように、順序を守りましょう。

1. 第2章：問い・ペルソナ・Must を確認
2. 第3章：H1（論理名）を確定
3. 第4章：H1（ゲート文言）を確定
4. title：H1をベースに28〜32字前後に最適化
5. meta：リード（150〜300字）を120〜160字に圧縮

執筆順：本文の前に title 案・meta 案を書くことを推奨（第4章リードと同時でも可）。

---

## 構造化データは、特殊な配送ラベルである

> この節の要点：JSON-LD 等は型付きの高度な通信規格。本文のFAQ・手順の明確さが前提。

JSON-LD などの構造化データは、インデクサーと生成AIに型付きの情報を渡す高度な通信規格です。FAQやHowToを本文で明確に書いておけば、検索のリッチリザルトだけでなく、ChatGPTやGeminiが引用しやすい構造にもなります。

- 記事（Article）
- FAQ
- HowTo
- パンくずリスト（BreadcrumbList）

ライターは、FAQやHowTo記事ならFAQ項目・手順を本文で明確に書いておく。技術側が構造化データに変換しやすくなります。詳細は技術ドキュメントと連携。

### ポイント

- title＝主ラベル、meta＝補足ラベル。SERPとインデクサー双方に
- title は28〜32字目安、前半に核心。H1・Mustと一致
- meta は120〜160字、リードの圧縮。ユニークに
- ラベルは第4章の外門の検索結果版。クリック前の消滅を防ぐ
- 構造化データは上級の通信規格（本文の明確さが前提）

### よくある間違い

| 間違い | 問題 | 改善の方向 |
|---|---|---|
| 全ページ同じ title | ラベル重複、判別不能 | ページごとにユニーク |
| キーワードだけの title | 通信規格として不十分 | 約束・具体性を追加 |
| meta を空のまま | SERPで魅力不足 | リードから圧縮 |
| title と H1 が矛盾 | インデクサー・読者混乱 | 約束を一致 |
