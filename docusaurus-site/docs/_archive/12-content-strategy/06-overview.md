# 12-6 章末まとめ・チェックリスト・演習

第12章では、1台の修理から車両全体の整備計画へ、1貫の握りからおまかせコースの献立へ。あなたの物語を体系で設計する方法を学びました。第11章が既存資産の修理なら、第12章はその前段階と並行工程です。

## 第12章のメッセージ（再確認）

> この節の要点：単発の記事ではなく体系で設計する。クラスター・カレンダー・優先順位・合意。それがあなたの物語戦略である。

第11章まで、既存記事を資産として修理する方法を学びました。第12章は、その前段階と並行工程。何を書き、どの順番で、誰と合意して進めるか。検索を入口にした需要だけでなく、SNS・AI引用の入口も含めて、読者のジャーニー全体に返球する整備計画と献立表を書く章でした。

## 本編・応用編との接続

> この節の要点：第2章→第12章（体系設計）→第13章（実行）→第6章・第11章（改善ループ）の流れ。

| 章 | 比喩・役割 | 第12章との関係 |
|---|---|---|
| 第2章 | ペルソナ・ジャーニー | クラスターの段階設計 |
| 第3章 | 導管・削ぎ落とし | ハブ/スポークのMust/Should |
| 第5章 | Web最適化（検索・SNS・AI引用）・クラスター基礎 | 12-2でサイト全体に拡張 |
| 第6章 | 精密検査・優先度 | カレンダー・リライト選定 |
| 第11章 | 修理・更新 | カレンダーのリライト枠 |
| 第12章 | 整備計画・献立 | 体系設計（本章） |
| 第13章 | ワークフロー | 計画の実行標準化 |

```
第2章 ペルソナ・ジャーニー
  ↓
第12章 クラスター設計 → コンテンツカレンダー → 優先順位 → 合意
  ↓
第13章 企画〜公開ワークフロー
  ↓
第6章 精密検査 → 第11章 リライト → カレンダー更新
```

## 章末まとめ

> この節の要点：第12章の8項目：体系設計、クラスター、カレンダー3種類、優先度、Must/Should、合意3資料、月初更新、1人運用。

1. あなたの物語戦略は、1記事ではなく体系の設計（整備計画・献立）
2. トピッククラスター＝ハブ（概観）＋スポーク（詳細）＋双方向リンク
3. コンテンツカレンダー＝新規・リライト・更新の3種類を載せる
4. 優先順位＝Impact × Urgency ÷ Effort（第6-5節の拡張）
5. Must/Should/Could/Won't で四半期計画の過積載を防ぐ
6. ステークホルダー合意＝クラスターマップ・カレンダー・根拠の3資料
7. 月初の精密検査でカレンダーを更新。計画は生きた書類
8. 1人運用でも「未来の自分」とデータをステークホルダーに

## チェックリスト

> この節の要点：四半期計画・月次運用・新規執筆前・四半期振り返りの4ブロックで確認項目を固定する。

### 四半期（計画策定）

- [ ] ペルソナとジャーニー（第2章）を確認した
- [ ] テーマ領域ごとにクラスターマップを作成した
- [ ] 既存記事の棚卸し（主KW・表示・役割）を実施した
- [ ] ギャップ（未執筆・カニバリ・孤立）をリスト化した
- [ ] 四半期Must/Should/Could/Won't を定義した
- [ ] 3ヶ月分のコンテンツカレンダー（新規・リライト・更新）を作成した
- [ ] ステークホルダー（または未来の自分）と合意記録を残した

### 月次（カレンダー運用）

- [ ] 第6章の精密検査を実施し、リライト3本を確定した
- [ ] カレンダーの延期・追加を理由付きで更新した
- [ ] 新規記事の優先順位をインパクト×労力で確認した
- [ ] 公開予定記事のクラスター内リンクを確認した（第5-5節）
- [ ] 前月公開記事の再試運転（28日）を実施した

### 新規記事執筆前

- [ ] クラスター内の役割（ハブ/スポーク）が明確
- [ ] 1記事1問い。カニバリチェック済み（第11-4節）
- [ ] ハブ↔スポークのリンク設計がある
- [ ] ジャーニー段階（認知/検討/決定/行動）を確認した

### 四半期振り返り

- [ ] Must達成率を確認した
- [ ] クラスター完成度（ハブ＋スポーク数）を更新した
- [ ] データ（第6章）から計画の修正点を抽出した
- [ ] 次四半期のMust/Won't を再定義した

## 演習

> この節の要点：テーマ領域1つについて3ヶ月分のあなたの物語計画を作成する。Mustは四半期5本以内、リライト枠月3本、Won'tを最初から書く。

課題：テーマ領域1つについて、3ヶ月分のあなたの物語計画を作成してください。

第2章のペルソナ・ジャーニー、第6章のデータ（または想定データ）、第11章のリライト視点を組み合わせると、計画の現実味が増します。

### 提出物

1. ペルソナ（簡潔）とテーマ領域の定義（1文）
2. クラスターマップ（ハブ1＋スポーク5以上。既存/新規/Won't を区別）
3. 3ヶ月分のコンテンツカレンダー（新規・リライト・更新の内訳）
4. 優先順位表（Must/Should/Could/Won't と根拠1行）
5. 合意記録（チーム or 1人運用の場合は「未来の自分」向けメモ）
6. ステークホルダー（または仮想ステークホルダー）一覧と関与範囲

ヒント：Must は四半期5本以内。リライト枠を月3本確保する。Won't を最初から書くと、合意が取りやすくなります。
