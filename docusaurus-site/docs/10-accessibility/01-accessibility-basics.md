# 10-1 Webアクセシビリティと文章の関係

段差のある入口だけの整備工房のように、特定の能力を持つ人だけを想定した設計は、問いに答える工房として成立しません。スロープと標識を最初から組み込めば、音声読者・スクリーンリーダー・AI要約も、第5章 Web最適化で整えた構造を正しく読み取れます。それは特別な配慮ではなく、全員に返球する設計責任です。

## アクセシビリティとは何か

> この節の要点：Webアクセシビリティは、障害の有無や一時的な制約に関わらず、誰もが情報にアクセスし、理解し、操作できる状態。ライターは知覚・理解・操作の三層で言葉と構造を担う。

Webアクセシビリティ（accessibility）とは、障害の有無や一時的な制約（目が疲れている、騒音の中で読んでいる、片手しか使えない）に関わらず、誰もが情報にアクセスし、理解し、操作できる状態を指します。

ライターにとって重要なのは、次の3層が重なることです。

| 層 | ライターが担う部分 | 例 |
|---|---|---|
| 知覚 | 文字・画像・色で情報が届くか | 平易な言葉、alt、色だけに頼らない表現 |
| 理解 | 内容が論理的に追えるか | 見出し階層、短い文、用語の説明 |
| 操作 | 次の行動に進めるか | リンク文言、CTA、手順の番号付け |

第3章で学んだ「導管設計」は、スクリーンリーダー（画面の文字や構造を音声で読み上げるソフト）利用の自分にとっても、同じく「標識のある通路」です。階層が乱れると、自分は迷い、AI要約や検索インデックスも正しく骨格を読み取れず、第1章で述べたように「消滅」します。

> アクセシビリティは、導管の先に置く「おまけの配慮」ではない。導管そのものを、全員が通れる幅と勾配で設計することである。

## 工房の比喩：スロープと標識は設計の一部

> この節の要点：段差のある入口、色だけの看板、口頭だけの説明、専門用語だらけの手順書：アクセシビリティは後付けの設備ではなく、最初から組み込む設計である。

本章の比喩は、整備工房です。

```
段差のある入口だけ     →  一部の読者が最初から入れない
色だけの看板           →  色覚特性のある人が標識を読めない
口頭だけの説明         →  聴覚に頼れない人が情報を失う
専門用語だらけの手順書 →  初めて来た人が作業台に辿り着けない
```

自動車整備士が国家資格を持つ理由のひとつは、「誰の車も安全基準で整備する」責任があるからです。Webの設計士も、問いに答える工房を、特定の身体能力を持つ人だけのものにしてはいけません。

寿司職人がカウンター越しに「今日は酢の効きが強めです」と伝えるように、情報は複数の経路（文字・音声・触覚・図）で届く余地を残します。それはサービスの演出ではなく、職人の誠実さです。

## なぜ「文章」のアクセシビリティが重要か

> この節の要点：HTMLやCSSは開発者の領域だが、ライターが書く言葉と構造が土台になる。見出し・リンク・alt・平易語・色に頼らない表現が、アクセシビリティの核心。

アクセシビリティと聞くと、開発者のHTMLやCSSの話だと思われがちです。確かに、ボタンのサイズやフォーカス表示は実装の領域です。

しかし、ライターが書く「言葉」と「構造」が、その土台になります。

| ライターの選択 | アクセシビリティへの影響 |
|---|---|
| 見出しを飾りではなくH2・H3で設計 | スクリーンリーダーが目次として読める（第3章） |
| リンク文言を「こちら」にしない | 音声だけでリンク先がわかる |
| 画像に意味のあるaltを書く | 視覚に頼れない読者が図表の内容を得る |
| 平易な言葉で書く | 認知負荷が高い読者も理解できる |
| 色だけで重要度を示さない | 色覚多様性のある読者も情報を失わない |

第7章で、専門性は用語の羅列ではなく問いへの応答だと述べました。アクセシビリティも同じです。「誰にでも読みやすい」は、内容を薄めることではなく、届け方を整えることです。

## 消滅との接続（第1章の回帰）

> この節の要点：アクセシビリティの障壁は、第1章で定義した引き返し（消滅）の一形態。文字が読めない、見出しがない、リンクが「こちら」だけ（いずれも自分が一瞬でタブを閉じる原因になる。）

第1章で、Webにおける引き返しは「自分の世界からあなたの物語が消えていくこと」と定義しました。

アクセシビリティの障壁は、引き返しの一形態です。

```
文字が小さすぎて読めない     →  一瞬でタブを閉じる
見出しがなくスキャンできない →  ジャンプ読みができず消滅
リンクが「詳細はこちら」だけ →  音声ユーザーが先に進めない
専門用語の壁                 →  スキャン段階で「自分向けではない」
```

入口が検索・SNS・AI引用のいずれでも、障壁による引き返しは「問いに答えられていない」という自分の判断として返ります（第1章・第2章）。構造が崩れていれば、引用されにくく、シェアされにくくなります。アクセシビリティを整えることは、Web最適化の小手先ではなく、音声・AI・クローラーを含め、自分が読者として辿り着ける工房の幅を広げる設計です。

## 誰のためか、と問い直す

> この節の要点：アクセシビリティの対象は「障害を持つ人」だけではない。通勤電車、片手操作、外国語話者、高齢、目の疲労。状況を含めた全読者が対象。

アクセシビリティの対象は、「障害を持つ人」だけではありません。次のような状況でも、同じ障壁に直面します。

- 通勤電車で音声を出せず、字幕や構造だけで読む
- 子どもを抱えながら片手でスマホを操作する
- 外国語が母語ではなく、平易な日本語のほうが理解しやすい
- 高齢になり、一度に処理できる情報量が減った
- 目が疲れて、コントラストの低い文字が読めない

もしあなたが「うちの読者は若いから大丈夫」と考えていたなら、工房の入口に「若者限定」と書いているのと同じです。問い（ボール）は、年齢や能力を選びません。

## 設計士の責務としてのアクセシビリティ

> この節の要点：アクセシビリティは開発任せではなく、言葉・見出し・altをライターが最初に設計する責務。公開前に「音声だけ・色なし・平易語で核心に辿り着けるか」を確認する。

| よくある誤解 | 実際 |
|---|---|
| 開発が直す問題 | 言葉・見出し・altはライターが最初に設計する |
| 後から足すスロープ | 最初から通路幅を確保する段取り |
| 内容を薄めること | 届け方を整えること。Expertiseは失わない（第7章） |
| 法律だけの話 | WCAG等は指針。本質は「全員に返球する」誠実さ |

自動車整備士が車検証を整備記録と照合するように、あなたも公開前に「この記事は、音声だけ・色なし・平易語で、核心に辿り着けるか」を確認します。それが、第10章以降の応用編における、設計士の基本姿勢です。

---

### ポイント

- アクセシビリティ＝工房にスロープと標識を組み込む設計責任
- 知覚・理解・操作の3層。ライターは言葉と構造を担う
- 障壁は引き返し（消滅）の一形態。第1章・第3章と接続する
- 対象は「一部の人」ではなく、状況を含めた全読者

### よくある間違い

| 間違い | 問題 | 改善の方向 |
|---|---|---|
| 開発任せにする | altも見出しも空のまま | 執筆段階から構造とaltを設計 |
| 後付けの親切 | 工房の段差は残る | アウトライン段階から平易語・階層を設計 |
| 内容を削りすぎる | 答えが薄くなる | 第7章のように問いへの応答は維持 |
| 対象読者を狭める | 自分が入口で戻る場面が増える | 状況多様性を前提に書く |
