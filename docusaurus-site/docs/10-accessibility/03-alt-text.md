# 10-3 代替テキスト（alt）の書き方

altはWeb最適化用のキーワード欄ではない。画像が伝える意味を、視覚に頼れない読者・音声読み上げ・AI要約に届ける「音声での説明板」です。altを空のまま公開しても、あなたの文章力が足りないわけではありません。第5章 Web最適化で整えた構造に、画像の意味を言葉で足せば、検索・SNS・AI引用のどの入口から来ても、図表の要点が届きます。

## altとは何か

> この節の要点：altはHTMLのimgタグに付ける、画像の文字による説明。スクリーンリーダーが読み上げ、画像が表示されない環境でも意味が残る。

alt（alternative text、代替テキスト）は、HTMLの `<img>` タグに付ける、画像の文字による説明です。

```html
<img src="brake-pad-worn.jpg" alt="摩耗したブレーキパッド。厚さが新品の半分以下になっている">
```

スクリーンリーダーは、altを読み上げます。画像が表示されない環境（回線が遅い、画像オフ設定）でも、altがあれば意味が残ります。検索インデックスやAI引用も、altと周辺テキストから画像の内容を理解します（第5章 Web最適化（検索・SNS・AI引用）の構造化の延長）。

> altは、画像の「キャプション」でも「ファイル名」でもない。画像が記事の中で担う役割を、言葉で再現するものである。

---

## 装飾と意味：altを書くか空にするか

> この節の要点：装飾に長いaltを付けると、スクリーンリーダー利用の自分が無意味な読み上げで止まる。

すべての画像に長いaltを書く必要はありません。

| 画像の種類 | altの方針 | 例 |
|---|---|---|
| 意味を持つ図・写真 | 内容を具体的に記述 | 「左前パッドの残厚約2mm。交換推奨ラインは3mm」 |
| 文章の一部として読むべき図表 | 表の要点を要約 | 「2024年副業開始者の届け出必要率：約62%（社労士調査）」 |
| 純粋な装飾 | 空（alt=""） | 背景模様、区切り線の画像 |
| テキストで既に説明済み | 短く、または空 | 直前の段落と重複しない |

装飾画像に長いaltを付けると、スクリーンリーダーの読者は無意味な読み上げに阻まれます。寿司職人が「盛り付けの飾り」まで客に説明し続けるようなものです。必要な情報だけを、必要な長さで。

---

## 良いaltの3条件

> この節の要点：画像の目的がわかる、記事の文脈に沿う、冗長な「画像です」を避ける。良いaltの三条件。

### 条件1：画像の目的がわかる

```
✗ alt="image001.jpg"
✗ alt="副業 SEO キーワード 最適化"  ← キーワード詰め込み（Web最適化の小手先）の悪例
✓ alt="クラウドソーシングの案件一覧画面。週5時間以内のフィルターが選択されている"
```

### 条件2：記事の文脈に沿う

同じ写真でも、記事の問いによってaltは変わります。

```
記事A（副業の始め方）：
alt="在宅でノートPCを使う人。リビングのデスクにモニター1台"

記事B（デスク環境）：
alt="モニター高さを目線に合わせたデスク。椅子は肘が90度になる位置"
```

### 条件3：冗長な「画像です」を避ける

スクリーンリーダーは「画像」と自動で知らせます。

```
✗ alt="画像：摩耗したブレーキパッドの写真"
✓ alt="摩耗したブレーキパッド。残厚約2mm"
```

## HTML例：意味のある画像と装飾

> この節の要点：手順スクリーンショット、比較図、装飾画像（それぞれaltとfigcaptionの使い分けを、HTML例で確認する。）

### 例1：手順を示すスクリーンショット

```html
<h2>クラウドソーシングに登録する</h2>
<p>まず、トップページの「新規登録」を選びます。</p>
<img src="signup-button.png"
     alt="サイト右上の青い「新規登録」ボタン。ログインボタンの左隣">
<p>メールアドレスとパスワードを入力し、確認メールのリンクを開きます。</p>
```

「ブラウザでの表示結果（見た目）」：

- 見出しの下にスクリーンショットが表示され、本文の手順と視覚が対応する
- 画像が読み込めなくても、altの文言が代替表示される
- スクリーンリーダーは「クラウドソーシングに登録する（見出し）」→ 段落 → 「サイト右上の青い…（画像）」の順で読み上げる

### 例2：比較図（before/after）

```html
<figure>
  <img src="brake-before-after.jpg"
       alt="左：残厚5mmの新品に近いパッド。右：残厚2mmで溝が浅い摩耗パッド">
  <figcaption>図1：交換前（右）と新品（左）の比較</figcaption>
</figure>
```

「ブラウザでの表示結果（見た目）」：

- 画像の下にキャプション（figcaption）が小さめの字で表示される
- altは画像単体の意味、figcaptionは記事内での番号と役割を補足
- 両方ある場合、スクリーンリーダーの挙動は環境により異なるため、altに核心を入れ、figcaptionは重複を避ける

### 例3：装飾画像

```html
<img src="decorative-wave.svg" alt="" role="presentation">
```

「ブラウザでの表示結果（見た目）」：

- セクション間の波形が視覚的な区切りとして表示される
- altが空のため、スクリーンリーダーは読み上げをスキップする
- 情報の流れが途切れない

## 図表・インフォグラフィックのalt

> この節の要点：複雑な図はaltだけでは足りない。本文または表で同じ情報をテキスト化し、altは要約に留める。

複雑な図は、altだけでは足りないことがあります。その場合は、本文または表で同じ情報をテキスト化します（第3章のリスト・表の使い分け）。

```
✗ 図だけ載せて「詳細は画像を参照」
✓ 図の要点を箇条書きで本文に書き、altは要約
```

自動車整備士が配線図を客に見せるとき、図だけ渡して終わりにはしません。「ここが問題の箇所です」と言葉で指し示す。altと本文の役割分担も同じです。

---

## altとあなたの物語の関係

> この節の要点：altを空にすると、視覚に頼れない読者は情報が欠落し、検索・AI引用も画像理解の機会を失う。意味のある画像にaltがない記事は、工房の半分に灯が点いていない状態。

画像は、あなたの物語の一部です。altを空にすると、

- 視覚に頼れない自分は、その段落で情報が欠落する
- スキャンした自分は、画像だけ見て戻り、テキストの答えに辿り着かない
- 検索・AI引用は、画像理解の機会を失う（図表の要点がテキスト化されていない）

第1章の消滅は、テキストだけの問題ではありません。意味のある画像にaltがない記事は、工房の半分に灯が点いていない状態です。

---

### ポイント

- alt＝画像の意味を言葉で再現。キーワード詰め込みではない
- 意味ある画像は具体的に、装飾は alt=""
- 文脈に合わせてaltを書く。同じ写真でも記事ごとに変えてよい
- 複雑な図は本文・表でも同情報を提供（第3章）

### よくある間違い

| 間違い | 問題 | 改善の方向 |
|---|---|---|
| alt未入力 | 情報の欠落 | 公開前に全画像を確認 |
| ファイル名のまま | 意味が伝わらない | 内容を1〜2文で記述 |
| キーワード羅列 | スパム的。読み上げが不自然 | 自然な日本語の説明 |
| 装飾に長文alt | 読み上げが冗長 | alt="" でスキップ |
| 図だけで本文なし | 非視覚ユーザーが理解不能 | テキストでも要点を記載 |
