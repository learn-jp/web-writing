# 第11章 リライトと更新

> 比喩の階段における位置：応用編（第8章〜）。本編第6章の精密検査で見つけた故障を「修理」し、第7章の証明書を更新し続ける章です。

> 第7章からの接続：正当性の証明書を発行した。しかし、一度きりの発行で終わりではない。第6章の精密検査でズレが見つかり、情報が古くなったとき、証明書も書き直す。第11章は、既存の記事を資産として磨き続ける工程です。

> この章で学ぶこと
> - リライトの種類（全面・部分・統合・分割）。オーバーホールと部分修理の判断
> - 第6章のデータからリライト対象を見つける方法
> - 情報の鮮度管理と更新日の設計（第7-4節の証明書更新）
> - カニバリゼーション（記事同士の競合）の解消
> - リライトの手順とチェックポイント、再試運転までの段取り

本章の核となるメッセージ

> 新規記事ばかり書いても、既存の記事は資産のまま眠る。第6章で診断し、第7章の証明書を更新し、第2の返球で効果を確かめる。それが、リライトと更新の設計です。
