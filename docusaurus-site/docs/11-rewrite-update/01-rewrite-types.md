# 11-1 リライトの種類（全面・部分・統合・分割）

[第6章](../06-data-analytics/)で精密検査を終えたあとに来るのが、修理です。Webライティングにおける修理がリライトであり、整備の現場と同じく、オイル交換とエンジンオーバーホールでは工数もリスクもまったく異なります。既存記事が思うように届いていなくても、全部を書き直す必要はありません。症状と原因レイヤー（第6章）を見て、必要な規模を選ぶ。それがこの節の出発点です。

## 4種類のリライト

> この節の要点：リライトには4種類ある。症状と原因レイヤーに応じて、部分修理かオーバーホールか、統合か分割かを選ぶ。全部を毎回分解する必要はない。

| 種類 | 内容 | 整備の対応 | 典型条件 |
|---|---|---|---|
| 部分リライト | 特定レイヤーのみ修正 | 部品交換・調整 | 外門のみ弱い、H2-1だけ不足 |
| 全面リライト | 構成から書き直し | オーバーホール | 問い自体が変わった、複数レイヤー故障 |
| 統合 | 複数記事を1本に | 重複部品の統合 | カニバリ、薄い記事群 |
| 分割 | 1記事を複数に | 機能ごとの分解 | 1記事に複数の問いが混在 |

第6-2節の予兆パターンと、第6-5節の優先度マトリクスが、どの種類を選ぶかの根拠になります。

---

## 部分リライト：最小の修理

> この節の要点：原因レイヤーが1〜2箇所に特定でき、他の部分が機能しているときは部分リライト。第6章の原則どおりの最小修理である。

部分リライトは、原因レイヤーが特定でき、他の部分が機能しているときに選びます。

| 症状（第6-2節） | 原因レイヤー | 部分リライトの例 |
|---|---|---|
| 表示↑ 外門の通過が弱い | 外門 | title・meta・H1の改稿 |
| クリック↑ 玄関で引き返す傾向 | 防波堤 | リード冒頭の問い宣言 |
| 特定H2で戻る | 関所 | そのH2の見出し・段落 |
| クエリ≠想定KW | 物流・型番 | キーワード配置、H2追加 |

第6-5節の判断表でも、工数が小さいレイヤー限定修正を優先するとありました。部分リライトは、その原則を実践する手段です。

```
部分リライトの条件
  □ 主KWと記事のMustは依然として一致
  □ 故障レイヤーが1〜2箇所に特定できる
  □ 他のH2・段落は問いに答えている
  □ 工数が現実的（数時間以内）
```

---

## 全面リライト：オーバーホール

> この節の要点：問い自体が変わった、複数レイヤーが同時に故障した、部分修正を重ねても直らない。そのとき全面リライト。エンジン全体を組み直すオーバーホールに相当する。

全面リライトは、エンジン全体を分解して組み直すオーバーホールに相当します。部分修理では直らない故障、または修理コストがオーバーホールを上回るときに選びます。

| 条件 | 例 |
|---|---|
| 問い（検索意図）自体が変わった | 「副業 始め方」→「副業 確定申告 2026」が主需要に |
| 複数レイヤーで同時故障 | 外門弱い＋関所で戻る＋情報が2年前 |
| ペルソナ・Mustの再設計が必要 | ターゲット読者が変わった |
| 部分修正を重ねても改善しない | 3回の部分リライト後も玄関で引き返す70%超 |

全面リライトは工数が大きい。第6-5節のImpact × Urgency ÷ Effort で、本当に必要かを確認してから着手します。ビジネス上重要なハブ記事（第5-5節）、表示数が多い記事ほど、全面リライトの投資対効果は高くなります。

全面リライトでも、URLを変えずに中身を入れ替える方法が一般的です。URL変更はリンク切れ・インデックス喪失のリスクがあるため、リダイレクト設計が必要な場合のみ検討します。

---

## 統合：重複を1本にまとめる

> この節の要点：似た問いに答える薄い記事が複数あると、読者もインデクサーも迷う。統合で1本の厚い記事にまとめ、カニバリの出発点を解消する。

似た問いに答える記事が複数あると、読者も「どれが本命か」迷います。検索インデックスやAI引用も、重複した薄い記事群より、1本の厚い答えを選びやすくなります。これがカニバリゼーション（第11-4節で詳述）の出発点です。

統合は、複数の薄い記事を1本の厚い記事にまとめる作業です。

```
統合前
  /blog/side-job-start/     … 副業の始め方（800字）
  /blog/side-job-tips/      … 副業のコツ（600字）
  /blog/side-job-beginner/  … 初心者向け副業（700字）

統合後
  /blog/side-job-guide/     … 副業完全ガイド（3,000字、旧3記事を301リダイレクト）
```

統合の判断基準：

- 主KWが重複している
- 各記事単体ではMustを満たせていない（薄い）
- 1本にまとめた方が、問いへの答えが完全になる

---

## 分割：1記事に複数の問いが混在

> この節の要点：1記事に複数の問いが詰め込まれ、どのクエリにも△回答になっているときは分割を検討する。統合の逆で、Must設計に沿って独立記事化する。

分割は統合の逆です。1記事に複数の問いが詰め込まれ、どのクエリにも△回答になっているときに検討します。

| 兆候 | 分割案 |
|---|---|
| Search Consoleのクエリが記事内で章ごとに分離 | 章ごとに独立記事化 |
| 一ページだけ見て去る傾向は強いが、特定H2だけ深く読み続けた | そのH2を別記事の核に |
| Must Notに抵触（1記事に複数テーマ） | 第2章のMust設計に沿って分割 |

分割後は、元記事から新記事へ内部リンクを張り、物流（第5-5節）を再設計します。

---

## 種類の選び方（フロー）

> この節の要点：第6章の精密検査結果から、カニバリ→部分→全面→新規の順で種類を判定する。症状だけ見て決めない。

```
第6章の精密検査で症状・原因レイヤーを特定
        ↓
カニバリがあるか？ → Yes → 統合 or 分割を検討（11-4節）
        ↓ No
原因レイヤーは1〜2箇所か？ → Yes → 部分リライト
        ↓ No
問い・Must・鮮度のいずれかが根本的にズレているか？ → Yes → 全面リライト
        ↓ No
新規記事の方が適切か？ → 第6-5節の判断表へ
```

---

### ポイント

- リライトは4種類：部分・全面・統合・分割
- 部分リライト＝部分修理。レイヤー限定、工数小、第6章の原則に沿う
- 全面リライト＝オーバーホール。複数故障・問い変化・部分修正無効のとき
- 統合・分割はカニバリや問い混在への対処
- 診断（第6章）なしに修理（リライト）に入らない

### よくある間違い

| 間違い | 問題 | 改善の方向 |
|---|---|---|
| すべて全面リライト | 工数爆発、改善ゼロ | 部分リライトを先に試す |
| 症状だけ見て種類を決める | 原因レイヤーを見逃す | 第6-2節の予兆→レイヤー |
| 統合せず新規を追加 | カニバリ悪化 | 11-4節で重複を整理 |
| URL変更を安易に | リンク・順位リスク | 原則URL維持、301は計画 |
