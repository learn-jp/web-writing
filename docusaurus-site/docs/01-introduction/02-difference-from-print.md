# 1-2 紙媒体との決定的な違い

雑誌や書籍で読み慣れた「完成された読み心地」をWebでもそのまま再現できると思っていたら、一度立ち止まってみてください。紙の原稿をそのまま載せたのに、スマホでは読みにくく、自分がその場で読む気を失ってタブを閉じてしまう。そんな経験はありませんか。原因は文章力だけではなく、媒体の違いにあります。構造をWeb向けに翻訳すれば、検索・SNS・AIのどの入口から来ても、小売店の棚札のように「自分向けだ」と伝わりやすくなります。この節では、紙とWebの決定的な差を整理し、手紙の型をWebに翻訳する方法を示します。

## 紙の文章は「完成された形」で届く

> この節の要点：紙の文章は編集・デザイン・印刷を経て「整えられた版面」として届く。ライターは完成品を書くだけで、構造の責任は専門家が担う。

雑誌や書籍の文章は、編集・校正・デザイン・印刷という工程を経て、読者の手元に届きます。

読者が触れるのは「すでに整えられた版面」です。

- 文字サイズは編集部が決めた
- 改ページの位置はデザイナーが決めた
- 見出しの大きさは組版で決まっている
- ページをめくる順番は物理的に一方向

ライターが書いた原稿は、多くの専門家の手を通して「読み物」に変換されます。読者はその変換後の完成品を読むだけです。

## Webの文章は「生の構造」がそのまま表示される

> この節の要点：Webではライターが書いた見出し・段落・リンクの構造がそのまま画面に反映される。手紙の型を整えないと、読者もコンピューターも混乱する。

Webでは事情が違います。

あなたが書いた見出しの階層、段落の区切り、リンクの有無。これらの「構造そのもの」が、ブラウザによって画面に反映されます。編集者やデザイナーが必ず介在するとは限りません。

手紙に例えるなら、こういう違いです。

| | 紙（雑誌・書籍） | Web |
|---|---|---|
| 届け方 | 封筒を開ければ、きれいに整形された手紙 | 封筒の中身がそのまま、読み手の環境で再配置される |
| 読む環境 | ほぼ一定（紙のサイズ・印刷の字体） | 千差万別（スマホ、PC、タブレット、読み上げソフト） |
| 読み方 | 上から下へ、順番に読む前提が強い | スキャン（流し読み）、ジャンプ（途中から読む）、離脱（タブを閉じる。第1-1参照） |
| 構造の責任 | 編集・デザイン工程が担う | 「ライターが最初から意識する必要がある」 |

Webでは、ライターが「手紙の型」を整えないと、受け取る側（読者もコンピューターも）が混乱します。これが紙との最も大きな違いです。

## 紙とWebの四つの決定的な違い

> この節の要点：画面サイズ・読み方・コンピューターの仲介・更新とリンク。この四つが紙とWebの決定的な差である。それぞれに「敬意のある書き方」がある。

### 違い1：画面サイズが読者ごとに異なる

同じ記事が、スマホでは縦長の細い画面に、PCでは横広の画面に表示されます。紙のように版面が固定されていません。

「敬意のある書き方」：最初の段落で結論を示し、見出しだけ読んでも全体像が掴める構成にする。

### 違い2：読者は記事を最初から最後まで読まない

ネット上の調査では、多くのユーザーがページの一部だけを読んでタブを閉じることが知られています。これは怠慢ではありません。情報が溢れる環境では、「選びながら読むのが合理的」です。

「敬意のある書き方」：見出し・リストで「ここに何があるか」を明示し、読者が自分で必要な部分を選べるようにする。

### 違い3：コンピューターが「仲介役」になる

紙の文章は、光を反射して直接目に入ります。Webの文章は、HTMLというマークアップ（印付け）を経由して表示されます。

検索エンジン（インターネット上の情報を索引し、ユーザーの問いに応じてページを選び出す仕組み。以降、本書では「検索エンジン」と表記します）は、このマークアップを読み、記事のテーマを推測します。現代の検索エンジンは、単なる索引機械ではなく「問いを理解し、最適な答えを選ぶ巨大なAI」でもあります。ChatGPTやGeminiも同様に、見出し・段落・title タグなどからページの構造を読み取ります。

ただし、因果の順序に注意してください。自分がSNS・検索・AIなどから情報を探す。その入口で「問いに答えられたか」が先に問われます。自分が開いてすぐ戻ったか、読み続けたかという選択がその答えを映し、検索エンジンやAIがそこから学習する。見出しは装飾ではなく「この先はこういう内容です」という宣言にする。画像には、画面に映らない読者のために代替テキストを書く。「印は、読者への配慮であり、その結果として発見の入口（検索を含む）にも正しく届く設計」である。

### 違い4：更新とリンクがWebでは前提になる

紙の記事は一度印刷すれば変わりません。Webの記事は更新でき、他の記事へリンクできます。

「敬意のある書き方」：情報が古くなったら更新する。読者が次に知りたくなりそうな情報へ、意味のあるリンクで導く。

## 「紙向きの文章」がWebで起きる問題

> この節の要点：紙の原稿をそのまま載せると、長いリード・見出し不足・長い段落・リンク不足などの症状が出る。これは文章力ではなく、媒体の違いを無視した構造の問題である。

紙の原稿をそのままWebに載せると、よく次のような症状が出ます。

症状1：リード文（導入）が長い

紙ではじっくり読む前提の冒頭が、Webでは「この記事、自分に関係ある？」と判断する前に読者を疲れさせます。

症状2：見出しが少ない、または曖昧

紙ではページのレイアウトが視覚的な区切りになります。Webでは見出しが唯一の「目次」になることが多いです。

症状3：段落が長い

紙の1段組でも読める長さの段落が、スマホの狭い画面では「文字の壁」に見えます。

症状4：「前の記事を参照」のみでリンクがない

紙では「○○号をご覧ください」で済みます。Webではクリック一つで辿れるリンクが読者への配慮です。

これらは文章力の問題ではなく、「媒体の違いを無視した構造の問題」です。

## 手紙の型をWebに翻訳する方法

> この節の要点：紙の良い文章（論理・表現・洞察）を捨てる必要はない。変えるべきは「届け方」であり、手紙の要素をWebの構造に翻訳することである。

紙の文章の良さ（丁寧な論理、豊かな表現、深い洞察）を捨てる必要はありません。変えるべきは「届け方」です。

手紙の要素と、Webでの対応を対応づけてみましょう。

| 手紙の要素 | Webでの対応 |
|---|---|
| 宛名（誰へ） | タイトル・リード文で「誰のための記事か」を明示 |
| 日付（いつ） | 公開日・更新日の表示、情報の鮮度 |
| 段落の区切り | `<p>` タグに相当する段落分け、一段落一主題 |
| 章立て | 見出し階層（H1 → H2 → H3） |
| 添付資料への言及 | リンク（内部リンク・外部リンク） |
| 署名・連絡先 | 著者情報、問い合わせ先、CTA（行動喚起） |

紙の良い文章をWebに載せるときは、「言葉」はそのままに、「型」を翻訳する。これがWebライティングの出発点です。

---

### 紙とWebの違いのポイント

- 紙は完成された版面が届く。Webは構造がそのまま表示される
- 読者は全部読まない。選べる構造を用意するのが敬意
- コンピューターが仲介する。マークアップ（構造）を正しく書く

### 紙とWebの違いでよくある間違い

| 間違い | 改善の方向 |
|---|---|
| 「紙でも読めるから、そのまま載せて問題ない」 | スマホ表示と流し読みを想定し、見出し・段落を再設計する |
| 「最後まで読んでくれるはず」 | 途中でタブを閉じることを前提に、各見出しブロックを独立して理解できるようにする |
| 「デザインが整えてくれる」 | 見出し階層やリストはライターが設計する。デザインは構造を活かす側 |
