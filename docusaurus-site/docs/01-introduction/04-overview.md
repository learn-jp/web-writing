# 1-4 Webライティングの全体像

第1章を読み終えた今、「で、次に何を学べばいいのか」と感じていませんか。本章では手紙の型・媒体の違い・三つの目的を押さえました。構造を整えれば、検索・SNS・AIのどの入口から来ても、読者の手元に届きやすくなります。整備士が工具を一本整えるところから始めるように、ここでは本書全体の地図を示し、今いる場所と、これから向かう方向を確認します。

## 本書が目指すスキルマップ

> この節の要点：本書は第1章の「構造の土台」から始まり、読者理解・表現・発見性・継続改善へと段階的に積み上がる。入門書として第1章から読むことを推奨する。

第1章で押さえた「土台」を起点に、本書では次のスキルを段階的に身につけていきます。

```
第1章  基礎（構造の考え方）          ← 今ここ
  ↓
第2章  読者とメディアの理解
第3章  情報設計と構成
第4章  見出しとリード文
  ↓
第5章  Web最適化と発見性（検索を入口に）
第6章  データの読み解きと精密化
第7章  信頼とE-E-A-T（正当性の証明）
第8章  トーン＆マナー
  ↓
第9章  モバイルファースト
第10章 アクセシビリティ
第11章 リライトと更新
  ↓
第12章  あなたの物語を体系で設計する
第13章  ワークフロー
第14章  測定と改善
```

入門書として第1章から読むことをおすすめします。すでに文章を書いている方も、「構造の観点から一度立ち返る」ことで、後半のWeb最適化（検索を入口に）や戦略の章がより実践的に活きてきます。

## Webライティングの五つの実践領域

> この節の要点：Webライティングは構造化・読者理解・表現・発見性・継続改善の五領域で成り立つ。各領域は本書の特定の章で深掘りされる。

本書全体を横断すると、Webライティングは次の5領域で成り立っています。

### 実践領域1：構造化（Structure）

コンピューターに正しく届ける「手紙の型」。検索エンジンやAIに、情報の「正しいマッピング」を渡すエンジニアリングでもある。

- 見出し階層、段落、リスト、リンク、代替テキスト
- 第3章・第9章・第10章で深掘り

### 実践領域2：読者理解（Audience）

誰が、どんな状態で、どう読むか。

- ペルソナ、読み方（スキャン・ジャンプ）、デバイス
- 第2章で深掘り

### 実践領域3：表現（Expression）

伝わる言葉と構成。

- 見出し、リード文、トーン、文体
- 第4章・第8章で深掘り

### 実践領域4：発見性（Discoverability）

読者が記事に辿り着ける設計。

- Web最適化（検索を入口に）、検索意図、キーワード、内部リンク
- 第5章・第6章（データによる精密化）で深掘り

### 実践領域5：継続改善（Improvement）

書いて終わりにしない仕組み。

- リライト、分析、あなたの物語の全体設計
- 第11章〜第14章で深掘り

## 執筆の基本サイクル

> この節の要点：実務の基本は「目的と読者→構成→本文→構造検証→公開→改善」のサイクル。初心者は③本文から始めがちだが、②構成を先に作ることを推奨する。

実務では、次のサイクルが基本になります。

```
① 目的と読者を決める
        ↓
② 構成（骨格）を作る        ← 手紙の型
        ↓
③ 本文を書く                ← 表現
        ↓
④ 構造を検証する            ← コンピューターへの配慮
        ↓
⑤ 公開する
        ↓
⑥ 数字とフィードバックで改善する
```

多くの初心者が③から始めてしまいます。しかし本書が推奨するのは、「②の構成を先に作る」ことです。

構成とは、手紙の宛名・段落・章立てに相当するものです。骨格があれば、本文は迷わず書けます。構造の検証（④）では、次の問いを立てます。

- 見出しだけ読んで、記事の全体像が掴めるか
- スマホで読んだとき、段落は長すぎないか
- リンクは「次に知りたいこと」につながっているか
- 画像だけ見えない状態でも、内容は伝わるか

これらはすべて、「読者への敬意のチェック」です。

## 技術的側面と人間的側面は両立する

> この節の要点：構造化は冷たい技術ではなく、人間的配慮の延長である。正しい見出し・代替テキスト・リンクは、すべて読者の時間と尊厳に触れる。

Webライティングを「コンピューターへの構造化」として捉えると、冷たい印象を受けるかもしれません。

しかし実際は逆です。

- 正しい見出し階層 → 読み上げソフトが読みやすくなる／検索エンジン・AIが意味地図を正しくマッピングできる
- 適切な代替テキスト → 画像が見えない読者にも内容が届く
- 意味のあるリンク → 読者が次の情報に迷わず辿り着ける
- 結論ファーストの構成 → 忙しい人の時間を尊重する／開いてすぐタブを閉じる前に、問いへの適合を示す

「技術的な正確さは、人間的な配慮の延長にある。」

手紙で宛名を書くのは、形式張りだからではなく、届けたい人への礼儀です。Webの構造も同じです。

## 本書を貫く比喩の地図（第1章〜第7章）

> この節の要点：第1章〜第7章は手紙・返球・導管・玄関・物流・精密検査・証明書という比喩で一連の物語としてつながる。人間への配慮と技術への誠実さは同じ設計行為の表裏である。

第1章から第7章まで、本書は「ひとつの物語」として読めるよう設計されています。比喩は章ごとに深まりますが、根は同じです。「読者の時間を預かる責任」と、「道具と段取りへの敬意」。

| 章 | 比喩 | 設計士が問うこと |
|---|---|---|
| 第1章 | 手紙 | 届け方（構造）は、礼儀か？ タブを閉じて消えないか？ |
| 第2章 | 問いと返球 | 誰が、なぜ、どんな問いを投げたか？ |
| 第3章 | 導管・工場ライン | 答えまで、詰まらず流れるか？ |
| 第4章 | 玄関・防波堤 | 入口で自分がタブを閉じないか？ 開いた瞬間に「自分向けだ」と思わせる設計をしたか？ |
| 第5章 | 物流・通信規格 | 問いに届くルート（検索を入口に）とラベルは正しいか？ |
| 第6章 | 精密検査 | 第2の返球を診断し、どこを・いつ直すか？ |
| 第7章 | 証明書 | 「正しい」と、世界に宣言できるか？ |

第1章で手紙の型を学び、第5章で物流を整え、第6章で「第2の返球を精密検査」し、第7章で「正当性を証明する」。この階段を登るとき、「人間への配慮」と「技術への誠実さ」は、対立しません。「同じ設計行為の表と裏」です。

## 第1章のメッセージ（再確認）

> この節の要点：Webの土台を作ることは読者への敬意である。構造・媒体の違い・三つの目的を押さえたうえで、第2章は手紙の「宛名」、つまり誰がどんな問いを投げたかを読み解く。

この章で伝えたかったことを、最後にもう一度まとめます。

> Webの土台を作ることは、読者への敬意である。

Webライティングは、美しい文章を書く技術であると同時に、コンピューターに正しく構造化して届ける技術です。紙の文章との違いを理解し、情報・共感・行動の目的を意識し、手紙の型をWebに翻訳する。これが、これからのすべての章の前提になります。

第2章では、この手紙の「宛名」。誰が、なぜ、どんな「問い（ボール）」を投げたのか。を読み解きます。構造の前に、または構造と並行して、必ず通る階段です。

## 第1章の章末まとめ

> この節の要点：第1章の核心は「表現と構造の両立」「紙とWebの違い」「離脱＝消滅」「三つの目的」「手紙の型」「構造化＝正当性の証明」の六つである。

1. 「Webライティングは「表現」と「構造」の両方」である。構造なくして、届くべき人に届かない。
2. 「紙とWebでは読む環境が違う」。Webではライター自身が構造の責任を持つ。
3. 「離脱＝消滅」。タブを閉じた瞬間、記事は自分の頭から消える。SNS・検索・AIのあらゆる入口で、自分が開いてすぐ戻れば「問いに答えられなかった」事実を映す。
4. 「文章には「情報・共感・行動」の目的がある」。主目的が構成を決める。
5. 「手紙の型を意識する」と、コンピューターと読者の両方に届く文章になる。
6. 「構造化は正当性を証明するエンジニアリング」。検索を入口にした小手先の技ではない。

## 第1章の公開前チェックリスト

> この節の要点：公開前に主目的・見出し・段落・スマホ表示・リンク・代替テキスト・Web向け構造を確認する。第1章の学びが身についているかのセルフチェックになる。

公開前に、次の項目を確認してください。第1章の学びが身についているかのセルフチェックにもなります。

- [ ] この記事の「主目的」（情報・共感・行動）を言葉にできる
- [ ] 「見出しだけ読んでも」記事の全体像が掴める
- [ ] 各段落に「一つの主題」がある
- [ ] スマホで読んだとき、「段落が長すぎない」
- [ ] リンクは「こちら」ではなく、「内容がわかるテキスト」になっている
- [ ] 画像に「代替テキスト（alt）」が設定されている（または装飾画像として適切にマークされている）
- [ ] 紙の原稿をそのまま載せていない（「Web向けに構造を見直した」）

## 第1章の演習

> この節の要点：身近な記事1本を「Web向き／紙向き」の観点で分析する。他人の記事を分析すると、紙向きの癖が客観的に観察しやすい。

課題：身近な記事（自社サイト、ニュース、ブログなど）を1本選び、「Web向き／紙向き」の観点で分析してください。

以下の観点でメモを取り、各項目を「Web向き ○ / △ / ×」で評価してみましょう。

| 観点 | 評価のポイント |
|---|---|
| 見出しの構造 | 見出しだけで内容が追えるか。階層は論理的か |
| 段落の長さ | スマホでも読みやすい長さか |
| 結論の位置 | 情報目的なのに、結論が早めに来ているか |
| リンク | 関連情報へ意味のあるリンクがあるか |
| 目的の明確さ | 情報・共感・行動のどれが主目的か、読み手に伝わるか |

ヒント：最初は自分が書いた記事より、「他人の記事」を分析する方が客観的に観察しやすいです。気になった点を「紙向きの癖」としてメモし、改善案を1つ書いてみてください。
