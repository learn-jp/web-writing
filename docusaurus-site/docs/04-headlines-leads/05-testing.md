# 4-5 見出し・リードのABテストと改善

入り口設計は、一度書いて終わりではありません。外門で選ばなかったか、防波堤でタブを閉じたか。自分の体験を手がかりに、ゲートと防波堤を継続的に改善する。それも設計士の仕事です。検索結果を見てクリックする前に判断したか、開いてすぐ閉じたか、どこまで読んだか。問いに答えられたかの事実から手がかりを得て、PDCAで入口を磨き続けます。

## タブを閉じた瞬間の手がかり

> この節の要点：検索結果で選ばれなかったか＝外門、開いてすぐ閉じたか＝防波堤〜不一致のシグナル。外門・防波堤・内門のどこで自分がタブを閉じたか、体験として手がかりになる。

第1章で、離脱はタブを閉じた瞬間に記事が自分の頭から消える、と述べました。第4章では、入口（H1とリード）が、その消滅の最大の要因になりやすい、とも述べました。

あなたが書いた記事の入口は、どの層で自分がタブを閉じるか。完全には見えませんが、体験として手がかりは残ります。

| 自分の体験 | 入口設計への示唆 |
|---|---|
| 検索結果で選ばなかった | 外門（H1・メタ）の吸引力 |
| 開いてすぐ閉じた | 外門通過後、防波堤（リード）でタブを閉じた？ |
| 読み続けた | 中に入り、導管を進めた |
| どこまで読んだか | どのH2（内門）でタブを閉じたか |
| どの入口から来たか | 検索 / SNS / AI のどれか |
| どの問いで来たか | どの問い（ボール）で来たか（検索経由の場合） |

自分が開いてすぐ閉じる場合は、外門の約束と防波堤・中身の不一致、または防波堤の弱さを疑います。

---

## ABテストで2つのゲートを競わせる

> この節の要点：同じ導管に対し入口だけ2パターン出して比較。1回に1要素、誠実さを維持する。

ABテストとは、同じ記事（導管）に対し、入口だけを2パターン出し、どちらがタブを閉じにくいかを比較する手法です。あなたが書いたH1やリードを、別バージョンと比較して改善できます。

### テストできる要素

| 要素 | 例 |
|---|---|
| H1（タイトル） | 「3ステップ」vs「完全ガイド」 |
| メタディスクリプション | 結論ファースト vs 問いかけ型 |
| リード文 | 共感型 vs 結論ファースト型 |
| ファーストビューのCTA | 有無、文言 |

テストの原則

- 1回に1要素。H1とリードを同時に変えない（どちらが効いたかわからない）
- 十分な样本。数日〜数週間、有意な差が出るまで
- 誠実さを維持。釣りゲートで検索結果だけ選ばれて、中身と合わない状態にしない

---

## 改善のPDCAで入口設計を回す

> この節の要点：Plan→Do→Check→Act。入口設計は最初から完璧にならない。継続的に改善する。

あなたの入口設計は、一度で完璧にならなくても構いません。PDCAサイクルで継続的に改善してください。

```
Plan   ：ペルソナの問い・出口から H1・リード案を設計
Do     ：公開
Check  ：検索結果での選ばれ方、自分が開いてすぐ閉じたか、どこまで読んだかを確認
Act    ：タブを閉じやすい層（外門/防波堤/内門）を特定し、言い換え
```

第14章で詳述しますが、入口設計は最初から完璧にならない。第1章コラムの「今日ひとつだけ整える」と同じです。寿司職人が毎日板を磨くように、あなたも入口を定期的に見直してください。

---

## 数字にない手がかりを定性で拾う

> この節の要点：ペルソナの声・5秒見せ・検索結果での見え方・コメントで、計測に表れない「タブを閉じる前」の手がかりを拾う。

計測だけでは足りない場合の、低コストの改善法です。

| 方法 | 得られる insight |
|---|---|
| ペルソナの声で読み返し | 防波堤で引っかかる箇所 |
| 同僚に5秒見せる | 外門で「自分向け？」の反応 |
| 検索結果での自記事の見え方確認 | 競合との差、切れ方 |
| コメント・問い合わせ | リードで答えられていない疑問 |

---

## H1・リード各10案で改善案を出す

> この節の要点：P（結論）を固定しH1を10案・リードを3案。量から質へ、上位2案でAB候補に。

演習（第4章末）と同じ手法を、実務で使います。あなたが次の手順で、入口の改善案を量産してください。

1. 第3章のP（結論）を1文固定
2. H1を10パターン。具体性、対象、数字、問いの言葉を変える
3. リードを3パターン。4型（第4-3節）から選ぶ
4. チームまたは自分でタブを閉じにくい順に並べ、上位2つをAB候補に

量から質へ。10案書けば、釣りゲートと控えめゲートの中間が見つかりやすくなります。自動車整備士が複数の診断手順を試すように、あなたも複数案から最適な入口を選びます。

---

## リライトは入口から優先する

> この節の要点：自分が開いてすぐ閉じる記事はH1・リード・最初のH2から疑う。中身は良いのに読まれない記事は、入口リライトのROIが高い。

第11章でリライト全般を扱います。入口設計の観点では、優先順位は高いです。

```
自分が開いてすぐ閉じる記事
  → まず H1・リード・最初の H2 を疑う
  → 導管（第3章）の問題より、入口の問題であることが多い

検索結果で選ばれにくい記事
  → 外門（H1・メタ）を複数案から再設計
```

中身は良いのに読まれない。玄関が閉じている記事。入口のリライトは、ROIが高い改善です。

---

### ポイント

- 検索結果での選ばれ方＝外門、開いてすぐ閉じたか＝防波堤〜不一致のシグナル
- 流入元（検索 / SNS / AI）ごとに入口の見え方が異なる
- ABテストは1要素ずつ、誠実さを維持
- PDCAで入口を継続改善
- 10案出し→上位2案でテスト
- 自分が開いてすぐ閉じる記事は、H1・リード・最初のH2から疑う

### よくある間違い

| 間違い | 問題 | 改善の方向 |
|---|---|---|
| 検索結果での選ばれ方だけ見る | 釣りで中身が伴わない | 開いてすぐ閉じたか、読み続けたかとセット |
| 一度決めっぱなし | 改善機会を逃す | 四半期ごとに入口見直し |
| 中身だけリライト | 入口が原因なのに | 自分が開いてすぐ閉じる体験から入口を疑う |
| テスト期間が短すぎ | 判断が早計 | 样本が足りるまで待つ |
