# 4-3 リード文、最初にして最大の防波堤

タイトルはクリックされるのに、自分がその場で読む気を失ってタブを閉じる。そんな経験はありませんか。リード文は導入の挨拶ではなく、離脱（タブを閉じる）を防ぐ「最初にして最大の防波堤」です。寿司職人が最初の一貫で客の不安を受け止めるように、投げられた問い（ボール）を引き取り、本文の導管へ安全に誘導する技術を学びます。検索・SNS・AIのどの入口から来ても、防波堤が機能すれば、読者は答えまで辿り着きやすくなります。

## 玄関に入った直後、ここでタブを閉じる

> この節の要点：多くの場合、第2層（リード）でタブを閉じる。防波堤は荒波を抑え、港（本文の導管）へ安全に誘導する。

第4-1節で、H1は外門だと述べました。外門を通過し、記事を開いた。玄関に入った瞬間です。

あなたが書いたリード文の前で、自分は足を止め、引き返す。ここから、第1章で述べた「タブを閉じる判断」との競争が、最も激しくなります。

第2章のレイヤーケーキを思い出してください。

```
第1層：タイトル（H1）  →  この記事、自分向け？     ← 外門
第2層：リード文        →  答えがありそう？中に進む？ ← ★ 防波堤
第3層：見出し（H2）    →  どこに答えがある？
第4層：本文           →  納得できる？
```

多くの場合、第2層でタブを閉じます。外門をくぐったのに、玄関ホールで足を止め、引き返す。タブを閉じる。

> リード文は、離脱（タブを閉じる）を防ぐための、最初にして最大の防波堤である。

防波堤の役割は、荒波（疑問・不安・時間のプレッシャー）を抑え、港（本文の導管）へ安全に誘導すること。第3章で設計した導管がどれほど完璧でも、防波堤がなければ、港に入らず、海に戻る。タブを閉じる。

SNS・検索・AIのどの入口から来た読者でも、リードで問いに答えられなければ、開いてすぐ戻ります。その事実が、発見の入口全体に伝わります（第2章）。逆に、リードでボールを引き取り、最初のH2まで読者が進めば、「問いに答えられた」という事実が生まれます。防波堤の設計は、読者体験の問題であり、その結果として発見性にも影響する設計でもあるのです。

---

## リード文には3つの使命がある

> この節の要点：ボールを引き取る、外門の約束を果たす、本文へ誘導する。3つの使命を同時に果たす。

あなたが書くリード文は、次の3つを同時に果たす必要があります。

### 使命1：ボールを引き取る（その問い、受け取りました）

読者は、問い（ボール）を投げてきました。リードの最初の数文で、キャッチしたことを示します。

```
✗ 「副業とは、本業以外で収入を得る活動のことです。」（定義から入る。問いを無視）
✓ 「『何から始めればいいかわからない』。副業を検討し始めた方へ、
    今週末に登録まで進める3ステップをまとめました。」
```

技術：第2章のペルソナの問いの言葉を借りる。第3章の出口を予告する。

---

### 使命2：外門の約束を果たす（中に、約束した答えがあります）

H1で「3ステップ」と約束したなら、リードで3ステップの存在を確認させる。釣りゲート（第4-2節）の逆。誠実な防波堤。

```
H1：「副業の始め方｜初心者が今週末に登録まで進む3ステップ」
リード：「本記事では、①副業の選び方 ②就業規則の確認 ③登録手順。
        この3つを、週末2時間で完了できる粒度で解説します。」
```

読者の審査②「答えがありそうか」に、即答します。

---

### 使命3：本文へ誘導する（この先に進んでください）

防波堤は、港の外に永遠に留まるものではありません。内側への流れを作ります。

- 最初のH2が何についてか、予告する
- 「詳しくは以下で」「まずは〇〇から」。次の一歩を示す
- 結論（P）をリード内に含める（結論ファースト。第4-4節）

---

## リード文には4つの型がある

> この節の要点：結論ファースト型・共感→結論型・問いかけ→答え型・シーン設定型。意図の型に合う防波堤の設計パターンを選ぶ。

第2章の意図の型に対応する、防波堤の設計パターンです。あなたのペルソナと記事の意図に合う型を選んでください。

### 型1：結論ファースト型（Know / Do）

構造：結論 → 理由の予告 → 本文への橋

```
【結論】初心者は、在宅副業を1つ選び、就業規則を確認してから登録すべきです。
【理由】いきなり大がかりな副業は、時間と不安で続かないためです。
【橋】以下では、選び方・確認事項・登録手順の順に解説します。
```

向いている記事：ハウツー、解説、比較の入口

---

### 型2：共感→結論型（SNS流入・共感型）

構造：共感 → 問いの言語化 → 結論 → 橋

```
「同僚は副業を始めたのに、自分は何もしていない」。そんな焦りから
この記事にたどり着いた方へ。結論から言うと、最初の一歩は
「在宅で週末だけ試せる副業を1つ選ぶ」ことです。以下で具体策を説明します。
```

向いている記事：SNSからの流入、不安の強いペルソナ

---

### 型3：問いかけ→答え型

構造：読者の疑問 → 「この記事では」→ 答えの予告

```
「副業、会社にバレない？」。始める前に最も多い不安です。
本記事では、就業規則の確認方法と、バレにくい副業の選び方を整理しました。
```

向いている記事：FAQ型、不安解消型

---

### 型4：シーン設定型

構造：読者の状況 → 記事の役割 → 橋

```
通勤電車でスマホを開き、「副業 始め方」を検索した。そんな30分のなかで
読めるよう、要点だけに絞って書きました。結論は、まず1つに絞って
今週末に登録まで進むこと。以下、3ステップで説明します。
```

向いている記事：スマホ・短時間読了想定（第2章のデバイス）

---

## リード文の長さは防波堤の高さになる

> この節の要点：150〜300字、3〜5文、1〜2段落。結論（P）を最初または2文目に置き、港が見える防波堤にする。

あなたが書くリード文の長さは、読者が港（本文）を見えるかどうかを左右します。

| 指標 | 目安 | 理由 |
|---|---|---|
| 文字数 | 150〜300字 | スマホでファーストビューに収まる |
| 文数 | 3〜5文 | 1呼吸で読める |
| 段落 | 1〜2段落 | 塊になりすぎない |

長いリードは、防波堤が長すぎて港が見えない状態。結論（P）がリードの最初または2文目にあるか確認してください。

### リード文のHTML構造

```html
<h1>副業の始め方｜初心者が今週末に登録まで進む3ステップ</h1>
<p>結論：最初の一歩は、就業規則の確認です。いきなり大がかりな副業は続きにくいため、在宅で週末だけ試せる種類を1つ選び、就業規則を確認してから登録しましょう。以下では、選び方・確認事項・登録手順の3つに分けて解説します。</p>
<h2>始める前に確認：就業規則で副業は許可されているか</h2>
```

「ブラウザでの表示結果（見た目）」：

- H1の直下にリードが表示され、ファーストビューで結論が見える
- スマホでは150〜300字が1画面に収まり、次のH2が少し見える
- リードだけ読んでも、記事全体の約束と構成がわかる
- 検索エンジン・AIも、リードから記事の主旨を理解しやすい

寿司職人が最初の一貫で「今日の流れ」を見せるように、あなたのリードは最初の数文で「この記事の流れ」を見せます。

---

## リード文は5ステップで書ける

> この節の要点：問い・出口・結論・型・橋の5ステップで150〜300字に収める。本文より先にリードを書く。

あなたがリード文を書くとき、次の手順に沿ってください。

1. ペルソナの問いを1文で書く（メモから引用）
2. 出口を1文で書く（第3章から引用）
3. H1の約束と一致する結論（P）を1文で書く
4. 型（結論ファースト / 共感 / 問いかけ / シーン）を選ぶ
5. 最初のH2への橋を1文追加し、150〜300字に収める

---

## 防波堤の失敗パターンはリードでタブを閉じさせる

> この節の要点：定義から入る・H1と矛盾・結論がない・長すぎ・煽りだけ。典型的な失敗パターンを公開前に確認する。

あなたが書いたリード文で、次の失敗が起きていないか確認してください。

| 失敗 | 何が起きるか | 読者の体験 |
|---|---|---|
| 定義・歴史から入る | 問いを引き取っていない | 自分向けじゃない → タブを閉じる |
| H1と矛盾 | 釣りゲートの続き | 信頼崩壊 → タブを閉じる |
| 結論がない | 審査②に答えられない | 長そう… → タブを閉じる |
| 長すぎる | 港が見えない | スキャンでタブを閉じる |
| 煽りだけ | 共感型の空振り | 反感 → タブを閉じる |

---

## 第3章の導管とリード文を接続する

> この節の要点：アウトラインのリード欄を第4章で必ず埋める。リード＝導管の入口ホール。本文より先に3案を書くことを推奨。

第3章で作ったアウトラインに、第4章でリードを設計します。

```
第3章アウトライン
  ├ H1（論理名）
  ├ リード：［空欄］          ← 第4章で設計
  ├ H2-1 …
  └ …

リード ＝ 導管の入口ホール
  →  ここに来て正解。中に答えがある。先はこう進む
  →  最初の H2 へ
```

アウトライン段階でリードを空欄にしていたなら、本章で必ず埋める。本文を書く前にリード3案（演習）を書くことを推奨します。自動車整備士が作業前に点検表を確認するように、あなたは公開前にリードの3使命を確認してください。

---

### ポイント

- リード＝最大の防波堤。第2層でタブを閉じるケースが最多
- 防波堤の失敗は、自分が開いてすぐ閉じる体験につながりうる。問いに答えられなければ、発見の入口（検索を含む）にもその事実が伝わる
- 3使命：ボールを引き取る、約束を果たす、本文へ誘導
- 4型：結論ファースト、共感→結論、問いかけ、シーン設定
- 150〜300字、結論は冒頭近く
- 本文より先にリードを書く（または3案から選ぶ）

### よくある間違い

| 間違い | 問題 | 改善の方向 |
|---|---|---|
| リードを後回し | 本文とトーンがズレる | アウトライン直後に執筆 |
| 前置きが長い | 防波堤が港を隠す | 結論を1文目に |
| ペルソナ不在 | 誰向けかわからない | 問いの言葉を借りる |
| H2への橋がない | 次の行動が不明 | 「以下では…」で予告 |
