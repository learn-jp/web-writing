# 7-1 E-E-A-Tとは、情報の正当性を証明する「証明書」

著者名や出典を後回しにしていませんか。でも、品質チェックリストを埋めるだけでは、読者はまだ「この人の言うことを信じていいか」と迷います。本章では、E-E-A-Tを検索・SNS・AI引用にも届く「証明書」として再定義します。整備士が記録簿に署名するように、あなたの現場の事実を、世界に向けて宣言する章です。

## 品質チェックリストから、証明書へ

> この節の要点：E-E-A-Tは著者欄を埋める作業ではない。整備記録簿のように、正しさを世界に宣言するための証明書である。

E-E-A-T（Experience, Expertise, Authoritativeness, Trustworthiness）とは、英語の略称です。日本語にほどくと、次の4つを指します。

| 略称 | 日本語の意味 | ひとことで言うと |
|---|---|---|
| Experience | 経験 | 実際に体験したか |
| Expertise | 専門性 | その分野を学び、技術を磨いたか |
| Authoritativeness | 権威性 | その分野で参照される存在か |
| Trustworthiness | 信頼性 | 誠実に、検証できる形で書いているか |

初心者の方は、まず「4つの欄を埋めた証明書」と覚えてください。検索エンジン向けの点数稼ぎではありません。あなたの物語が正しいと、読者・SNS・生成AIに対して宣言するための書類です。

自動車整備士の整備記録簿を想像してください。

```
車両番号、整備日、実施内容、使用部品、整備士名、資格番号、署名
```

この記録簿は、検索エンジンを喜ばせるためではありません。「この車は、基準に沿って整備された」と世界に宣言するための書類です。Web記事のE-E-A-Tも、同じ構造を持ちます。

| 整備記録簿 | Web記事のE-E-A-T |
|---|---|
| 誰が整備したか | 著者・監修者（Authoritativeness） |
| どんな資格・経験があるか | Experience / Expertise |
| 何をしたか（作業内容） | 本文の正確さ、一次情報 |
| いつ整備したか | 更新日、鮮度 |
| 根拠（部品番号・マニュアル参照） | 出典・引用（Trustworthiness） |

寿司職人がカウンター越しに「今日のネタは〇〇産です」と伝えるように、証明書は「何を、誰が、どう届けたか」を隠さず示す行為です。印付け（第1章）と通信規格（第5章）が整っていても、証明書が偽造なら、物流は止まり、読者は消滅します。

## 4つの要素、証明書の欄

> この節の要点：Experience / Expertise / Authoritativeness / Trustworthiness は、整備記録簿の各欄に相当する。略称の意味を、欄ごとに押さえる。

E-E-A-Tの4要素は、整備記録簿の欄に相当します。各欄が何を意味するか、順に見ていきましょう。

### Experience（経験）

欄の意味：私は、これを実際に経験した。

自動車整備士が「この症状、以前に何度も見た」と言えるように、現場で体を動かし、結果を見た事実です。体験談、オリジナル写真、失敗と修正の記録が、ここに載ります。

### Expertise（専門性）

欄の意味：私は、この分野について学び、技術を磨いた。

国家資格、長年の訓練、継続的な研鑽です。ただし、専門用語を並べることと混同してはいけません（第7-3節）。

### Authoritativeness（権威性）

欄の意味：この分野において、参照される存在である。

業界での認知、他者からの引用、メディア掲載、組織としての実績です。一人の整備士が、地域で「あの人に頼めば安心」と言われる状態に相当します。

### Trustworthiness（信頼性）

欄の意味：この情報は、誠実に、検証可能な形で提供されている。

出典の明示、利益相反の開示、HTTPS、連絡先、誤りの訂正です。証明書に嘘がないこと。寿司職人がネタの産地と鮮度を客に伝える誠実さと同根です。

## 三人の受け取り手、再び（第1章・第5章の回帰）

> この節の要点：証明書は読者・SNS・生成AIへの宣言である。一方だけへの偽装は、すべてへの裏切りになる。

第1章で、Webの手紙には受け取り手が二人いると述べました。第5章で、SNSと生成AIを加え三人に拡張しました。第7章の証明書は、三人すべてに届きます。

1. 人間の読者：証明書を読み、「この人の言うことを信じていいか」を判断する
2. SNS：要約・引用の文脈で、著者と出典が正しく伝わるかを検証する
3. 生成AIと検索エンジン（ChatGPT、Gemini、インデクサー）：証明書の整合性を読み、引用・インデックス上の信頼を更新する

E-E-A-Tを検索・AI対策だけにすると、読者への宣言が抜け落ちます。逆に、読者への誠実さだけで、記録（著者名・更新日・出典）を怠れば、SNS要約やAI引用でも信頼が崩れます。

> 証明書は、三人の受け取り手に同時に届く。どちらか一方への偽装は、すべてへの裏切りである。

## 本書の比喩の地図、最後のピース

> この節の要点：第1章から第7章まで積み上げた比喩の階段は、証明書で一本の設計思想として閉じる。

```
第1章  手紙        … 届け方の礼儀
第2章  問い        … 誰に、何に答えるか
第3章  導管        … 答えまでの段取り
第4章  玄関        … 入口で去らせない
第5章  物流        … 届け方のインフラ
第6章  精密検査    … 第2の返球を、診断せよ
第7章  証明書      … 正しいと、世界に宣言する  ← 今ここ
```

手紙を書き、段取りを整え、物流で届け、データで検査し、最後に正当性を証明する。これが、第1章から積み上げてきた設計の完成形です。自動車整備士が診断から記録簿の署名まで一貫して行うように、設計士も「正しいと宣言できるまで」責任を持ちます。

---

### ポイント

- E-E-A-T＝正当性の証明書。検索エンジン向けの品質チェックリストではない
- 4要素は、整備記録簿の欄に相当する
- 読者・SNS・生成AIの三方への宣言
- 第7章は、比喩の階段の最後のピース

### よくある間違い

| 間違い | 問題 | 改善の方向 |
|---|---|---|
| E-E-A-T＝著者欄を埋めるだけ | 空の証明書 | 経験・根拠を本文に織り込む |
| 検索エンジンだけ意識 | 読者への裏切り | 証明書＝読者への宣言と捉える |
| 権威性＝肩書きだけ | 中身が伴わない | 問いへの応答で示す（7-3節） |
| 一度書けば終わり | 鮮度が失われる | 更新・訂正を記録に残す |
