# 3-2 見出し階層（H1〜H4）の設計

「背景」「詳細」「まとめ」だけの見出しで記事を書いたことはありませんか。見出しは飾りやタイトルではなく、情報の「関所」であり「標識」です。読者の脳が迷わず答えに辿り着けるよう、H1〜H4の階層を導管上の設計要素として整えます。

## 見出しは「タイトル」ではない

> この節の要点：見出しは書き手のメモではなく、自分が一瞬で「この先に答えがあるか」を判断する標識である。

多くの記事で、見出しは「書き手のメモ」になっています。

```
「背景」
「詳細」
「まとめ」
「その他」
```

読者にとって、これらは「標識のない分岐点」です。「背景」で何がわかるのか、分岐先に何があるのか。一切読み取れません。工場のラインに「ここから右」と書かれていない標識を想像してください。作業者は立ち止まり、または間違った方向へ進みます。

第2章で、見出しは「情報の通り道の標識」だと述べました。第3章では、さらに踏み込みます。

> 「見出しは、情報の「関所」である。」  
> 「読者がここを通過するとき、何を得て、次にどこへ行けるかを制御する設計点である。」

関所。チェックポイント。とは、通過のたびに「方向と内容を確認する場所」です。見出しを読んだ瞬間、読者は無意識に次を判断します。

- この先に、自分が求めている答えがあるか？
- 読む価値があるか、スキップすべきか？

この判断が「一瞬」で行われる。だからこそ、見出しはタイトルではなく「標識」なのです。

---

## 工場ラインの比喩、情報の導管設計

> この節の要点：見出し階層は工場ラインの縦方向の設計図。入口・関所・出口を整え、詰まりと逆流を防ぐ。

第1章のコラムで触れた「整備士・エンジニア」の比喩（道具と段取りへの敬意）を、構成に適用します。

工場の生産ライン設計者は、次を考えます。

```
部品がどこから入り（入口）
  ↓ どの工程を経て（通過点・関所）
  ↓ どこへ出ていくか（出口）
```

「詰まり」を作らない。「逆流」をさせない。「不要な迂回」を省く。

Web記事の情報設計も同じです。

| 工場ライン | 情報の導管 |
|---|---|
| 原材料の投入口 | リード文・ファーストビュー |
| 工程・検査ポイント | H2・H3（関所） |
| コンベアの速度 | 段落の長さ・情報密度 |
| 分岐・合流 | リスト・リンク |
| 完成品の出口 | 結論・CTA・次の問いへの導線 |

見出し階層（H1〜H4）は、このラインの「縦方向の設計図」です。階層が乱れると、検索エンジン（インターネット上の情報を索引し、ユーザーの問いに応じてページを選び出す仕組み。以降、本書では「検索エンジン」と表記します）も読者も、「どの工程がどの工程の下位か」を判別できなくなります。部品が途中で行方不明になるのと同じで、自分はタブを閉じ、記事を忘れます。

---

## H1〜H4の役割、階層は深さではなく、関所の粒度

> この節の要点：H1〜H4は見た目の大きさではなく論理の骨格を伝える印。階層を飛ばさず、H1は1記事に1つ。

HTMLの見出しタグ（`<h1>`〜`<h4>`）は、「見た目の大きさ」のためではありません。第1章で述べたように、「論理の骨格を読者・検索エンジン・AIに伝える印」です。

| タグ | 導管上の役割 | 設計の問い |
|---|---|---|
| 「H1」 | 記事全体の「唯一の入口標識」 | この記事は、どの問いへの返球か？ |
| 「H2」 | 「主要な関所」。記事の幹線 | ここを通れば、どの論点が得られるか？ |
| 「H3」 | H2の「下位通過点」 | この論点の、どの部分か？ |
| 「H4」 | さらに細かい分岐（多用しない） | 本当に必要な粒度か？ |

### 見出し階層を飛ばさない理由

```
✗ H1 → H3（H2を飛ばす）
✗ H2 → H4（H3を飛ばす）
```

階層の飛び越しは、「標識の欠落」です。読み上げソフトは「見出しレベル3」と読みますが、レベル2がなかった。読者は「地図の中抜け」を体験します。

```
✓ H1 → H2 → H3 →（必要なら）H4
```

### H1は1記事に1つにする理由

H1は「記事全体の入口」です。複数のH1は、同じ工場に入口が2つあるようなもの。検索エンジンも読者も、「どれが本当のタイトルか」迷います。

### 見出し階層の構造の見える化

同じ内容でも、見出しの設計が「通り道」になります。

```html
<h1>副業の始め方（初心者向け）</h1>
<p>結論：最初の一歩は就業規則の確認です。</p>
<h2>会社に確認すること</h2>
<p>就業規則と副業の可否を確認してください。</p>
<h2>在宅で試せる副業の種類</h2>
<p>週末だけ試せる選択肢を3つ紹介します。</p>
<h3>クラウドソーシングのライティング</h3>
<p>初期費用0円で週末2時間から始められます。</p>
```

「ブラウザでの表示結果（見た目）」：

- H1が記事タイトルとして最上位に表示され、ページの主題が一目でわかる
- H2が主要な関所として目次の骨格になり、スキャンで全体像が掴める
- H3はH2の下位項目として、必要なときだけ細分化される
- 検索エンジン・AIも、見出しの階層から「問いと答えの対応」を理解しやすい

検索エンジンやAIは、見出しの印からページの論理構造を組み立てます。読者が構造を頼りにジャンプするのと同じ印が、発見の入口にも正しく届きます。

## 見出しを「標識」として書く、3つの条件

> この節の要点：良い見出しは単体で意味が通じ、答えの一部を含み、同階層で抽象度が揃っている。

効果的な見出し（標識）は、次の3条件を満たします。

### 標識条件1：単体で意味が通じる

見出しだけを縦に読んで、記事の「骨格」がわかること。第1章・第2章のチェックリストにもある項目です。

```
✗ 「方法」
✓ 「初心者が副業を始める3つのステップ」
```

### 標識条件2：答えの一部を含む（または明確な約束）

Know型の読者は、見出しで「答えの予告」を期待します。

```
✗ 「就業規則について」
✓ 「始める前に確認：就業規則で副業は許可されているか」
```

### 標識条件3：同階層の見出しは、並びの論理が一致する

H2同士は、「同じ抽象度」で並ぶ。

```
✓ H2：副業の種類を選ぶ
   H2：就業規則を確認する
   H2：最初の1件を受注する

✗ H2：副業の種類
   H2：なぜ副業が必要か（抽象度が違う）
   H2：クラウドソーシングの登録画面の見方（細かすぎる）
```

並びの論理が揃っていないと、導管の「枝」が太さも方向もバラバラになり、読者の脳が「切り替えコスト」を払います。

## 見出し階層の設計手順

> この節の要点：出口から逆算してH2の関所を決め、各H2をPREP返球として設計し、見出しだけ読んで通り道を検証する。

執筆前またはアウトライン段階で、次の手順を踏みます。

### 設計ステップ1：出口から逆算し、H2の関所を決める

第3-1節の「出口」（読者が到達すべき状態）から逆算し、そこに至る「主要な論点」をH2にする。

```
出口：今週末、1つ登録まで進む
  ↓ 逆算
H2：副業の種類を1つ選ぶ
H2：就業規則を確認する
H2：アカウント登録の手順
```

### 設計ステップ2：各H2をPREP返球フォームとして設計

各H2は、「1つの独立した返球」です。H2見出し＝そのセクションのP（Point）。

### 設計ステップ3：H3は「その論点の中の通過点」

H3は、H2の論点を「分解」するときだけ使う。分解が不要ならH3は不要。「階層は深くする必要はない」。

### 設計ステップ4：見出しだけを読んで、通り道が通るか確認

アウトライン完成後、「見出しだけ」を抽出し、読み上げる。第2章のジャンプ読みの読者が、「標識だけで目的地に着けるか」を確認します。

## 構造の印としての見出し、第1章との接続

> この節の要点：見出しは読者・検索エンジン・AIへの標識。太字や大文字での代用は論理の骨格を伝えられない。

第1章で、`<h2>` は手紙の「章立て」に相当すると述べました。ここに技術的な補足を加えます。

| やってはいけないこと | 起きること |
|---|---|
| 太字・大文字で見出しを代用 | 検索エンジン・AIは「強調された本文」としか読めない |
| 見出しの順序を飛ばす | 論理の深さが伝わらない |
| 見出しにキーワードだけ詰め込む | 標識としての意味が失われる |

「見出しは、読者・検索エンジン・AIの三者への標識」です。美しい字体や色はCSSの仕事。ライターが設計するのは、「関所としての文言と階層」です。

### タグ付けは小手先の技ではない、正当性のエンジニアリング

第5章で扱う `<title>` や `<meta description>` も、同じ思想の延長です。これらは、検索結果に表示される「配送ラベル」であり、「このページは、何について、誰のために書かれたか」を発見の入口に宣言する印です。

```
H1〜H4  →  記事内部の意味地図（論理の骨格）
title   →  ページ全体の公式名称（外門のラベル）
meta    →  検索結果での要約（外門の説明文）
```

印が本文と一致していれば、検索エンジンやAIは「問いと答えの対応」を正しくマッピングできます。印が釣り文句や空っぽのキーワードだけなら、第4章の「釣りゲート」と同じく「正当性の欠如」として、自分が開いてすぐタブを閉じる体験とセットで発見性に影響し得ます。

> 「構造化・タグ付けは、検索を入口にした小手先の技ではない。」  
> 「この情報は、本当にこの問いへの答えである」と証明する、エンジニアリング行為である。」

## スキャン・ジャンプ読みのための階層設計

> この節の要点：Web読者のスキャン・ジャンプ読みを前提に、H2だけで全体像が掴め、各セクションが単体で意味を持つ階層を設計する。

第2章で、Web読者は「スキャン」と「ジャンプ」が基本だと述べました。見出し階層は、この読み方を「前提に設計」します。

| 読み方 | 見出し階層への要求 |
|---|---|
| スキャン | H2だけで全体像が掴める |
| ジャンプ | 各H2セクションが単体で意味を持つ |
| タブを閉じさせない設計 | 最初のH2が早めに来る。ファーストビューに答えの予告 |

目次（Table of Contents）を自動生成するサイトでは、「H2・H3が目次そのもの」になります。目次として読めるか。それが、標識としての見出しの試金石です。

---

### 見出し階層設計のポイント

- 見出しはタイトルではなく、情報の「関所」と「標識」
- H1〜H4は見た目ではなく、「論理の骨格」を伝える印。title・meta は「正当性を証明する配送ラベル」
- 階層を飛ばさない。H1は1記事に1つ
- 良い見出し：単体で意味が通じ、答えの一部を含み、同階層で抽象度が揃う
- 出口から逆算してH2を決め、見出しだけ読んで通り道を検証する

### 見出し階層でよくある間違い

| 間違い | 問題 | 改善の方向 |
|---|---|---|
| 「背景」「まとめ」だけの見出し | 標識として機能しない | 内容がわかる文言に |
| H2が10個以上 | 関所が多すぎ、選択疲れ | 統合するか、シリーズ記事に分割 |
| 全H2が同じ構文 | 単調でスキャンしにくい | 並びの論理は揃え、表現に変化を |
| 見出しと本文が乖離 | 関所を過ぎても答えがない | H2＝P。本文で必ず届ける |
