# 3-6 情報の優先順位づけと削ぎ落とし

「せっかく書くなら、多く書こう」と思って記事が長くなりすぎたことはありませんか。構造の美学とは、情報を詰め込むことではない。不要なノイズを削ぎ落とし、読み手が心地よく答えに辿り着ける「情報の通り道」を作る設計思想です。

## 詰め込むほど、導管は詰まる

> この節の要点：情報の設計士の仕事は足すことだけではない。問いに答えない情報はノイズであり、勇気を持って外す。

「せっかく書くなら、多く書こう」  
「網羅性が大事だ」  
「文字数が多いほどWeb最適化（検索を入口に）に強い」

これらは、「半分正しく、半分危険」です。

第1章で、「とにかく文字数を増やせばいい」と検索には出ても、読者が途中で読む気を失う、と述べました。第2章で、Must Not（書かないこと）を決める、と述べました。第3-6節は、その「実行」（削ぎ落とし）です。

> 「情報の設計士の仕事は、足すことだけではない。」  
> 「読者の問いに答えるのに不要なものを、勇気を持って外すこと。それが構造の美学である。」

工場ラインで言えば、「不要な工程を省く」ことで、部品は速く、正確に出口へ向かいます。余計なバッファ、冗長な検査、使われない分岐。これらは「ノイズ」です。

寿司職人が不要な装飾を削ぎ落として本質だけを届けるように、あなたも問いに答えない情報を外します。

---

## 構造の美学、3つの原則

> この節の要点：問いに答えない情報はノイズ、同じことを2度言わない、出口までの距離＝記事の長さ。削ぎ落としの判断基準。

### 美学原則1：問いに答えない情報は、ノイズである

執筆中、「これも書いておこう」と思った段落を、次の問いで検査します。

```
この段落は、ペルソナの問いに答えているか？
答えを得た後の出口に、1ミリでも近づけるか？
```

Noなら、「削るか、別記事へ」（第2章のジャーニー。認知段階が違うなら別の返球）。

### 美学原則2：同じことを、2度言わない

PREPの最後のP（再確認）は「意図的な反復」です。それ以外の重複は「導管の重複」。同じ場所を2回通る迂回です。

- リードで言った結論を、H2で言い換えて繰り返す → 必要なら「短く参照」する程度に
- 表と本文が完全に同じ内容 → 表なら本文は要点のみ、またはその逆

### 美学原則3：出口までの距離＝記事の長さ

記事の適切な長さは、「問いの複雑さ」と「ペルソナの知識量」で決まります。文字数目標で水を足すと、「勾配が緩くなり」、読者は「まだ答え？」と疲れます。

| 意図の型 | 長さの目安（参考） | 削ぎやすいもの |
|---|---|---|
| Know（シンプル） | 1,500〜2,500字 | 歴史、過剰な背景 |
| Do（手順） | 2,000〜4,000字 | 関係ないトラブルシュート |
| Buy（比較） | 3,000〜5,000字 | 押し売り、根拠の薄い推し |

目安であり、「問いと出口」が先です。

## 優先順位づけのフレーム

> この節の要点：Must / Should / Could / Won't で残すものの優先順位を決め、削ぎ落としの前に境界を引く。

削ぎ落としの前に、「残すもの」の優先順位を決めます。

### 必須（Must）、削ってはいけない

- 問いへの「直接的な答え」（P）
- 納得に必要な「最小限の理由」（R）
- ペルソナの状況に合った「具体例」（E）
- 出口への「到達確認」（最後のP）

### 有用（Should）、スペースがあれば

- よくあるFAQ（不安の解消）
- 関連リンク（次の問いへの導線）
- 比較表の追加列

### 任意（Could）、別記事候補

- 発展的な話題
- 上級者向けのテクニック
- 業界の歴史・背景

### 除外（Won't）、Must Not

第2章のペルソナシートから。ここに書いたものは「勇気を持って削除」。

## 削ぎ落としの実務手順

> この節の要点：下書き完成後に問いテスト・H2の統合分割・導入結論の圧縮・書き手の都合を疑う4ステップで実務に落とし込む。

### 削ぎ落とし手順1：下書き完成後、1段落ずつ「問いテスト」

```
この段落を削除したら、読者は答えに到達できないか？
  → Yes（到達できる）→ 削除候補
  → No（到達できない）→ 残す
```

### 削ぎ落とし手順2：見出し（H2）の統合・分割

- H2が多すぎる（10超）→ 「統合」またはシリーズ化
- 1 H2が長すぎる（1,000字超）→ 「H3で分割」または別H2に

### 削ぎ落とし手順3：導入・結論の圧縮

- リードが長い → 「P（結論）を最初の2文に」
- まとめがH2の繰り返し → 「1段落に圧縮」し、次の行動（CTA）へ

### 削ぎ落とし手順4：「書き手の都合」を疑う

```
「ここで自社サービスを紹介したい」→ 問いに答えるか？
「このエピソードをどうしても入れたい」→ 出口に必要か？
```

書き手の都合で増えた情報は、「ノイズ」になりやすい。

## 心地よい通り道、読者体験としての美学

> この節の要点：構造の美学は見た目だけでなく読み終わったときの体感。最小のストレスで出口に着くことが成功。

構造の美学は、「見た目のきれいさ」だけではありません。「読み終わったときの体感」です。

| 削ぎ落とし前 | 削ぎ落とし後 |
|---|---|
| 「長い…まだ答え？」 | 「すぐ要点がわかった」 |
| 「どこが重要かわからない」 | 「見出しだけで追えた」 |
| 「同じ話が繰り返し」 | 「無駄がなく、信頼できる」 |

健太さんが記事を読み終え、「今週末、登録しよう」。その出口に、「最小のストレス」で着いた。それが、設計士としての成功です。

---

## 削ぎ落としとWeb最適化、誤解を解く

> この節の要点：発見の入口が評価するのは文字数ではなく問いへの答えの質。削ぎ落としはWeb最適化と両立する。

「文字数を減らすとWeb最適化的に不利では？」

検索エンジン（インターネット上の情報を索引し、ユーザーの問いに応じてページを選び出す仕組み。以降、本書では「検索エンジン」と表記します）やAIが評価するのは、「文字数」ではなく「問いへの答えの質」です（第5章・第6章で詳述）。冗長な記事は、読者が途中で読む気を失い、答えとして信頼されにくくなることもあります。

削ぎ落としは、「Web最適化との対立ではない」。問いに的確に答える記事が、SNSでも検索でもAIでも、長期的に選ばれる方向と一致します。読者への価値提供が、Web最適化の本質です。

---

## 第3章の統合、導管設計の全体像

> この節の要点：PREP→見出し→段落→リスト/表→アウトライン→削ぎ落とし。第2章の問いと出口の上に載る設計士としての技術。

本章で学んだことを、一つの流れにまとめます。

```
① PREP＝理想的な返球フォーム（第3-1）
        ↓
② 見出し＝関所・標識（第3-2）
        ↓
③ 段落＝流れの最小単位（第3-3）
        ↓
④ リスト・表＝分岐と合流（第3-4）
        ↓
⑤ アウトライン＝設計図（第3-5）
        ↓
⑥ 削ぎ落とし＝構造の美学（第3-6）
        ↓
   読者が、心地よく出口へ
```

第2章で決めた「問い」と「出口」。第3章で設計した「導管」。第4章以降で、入口（見出し・リード）の「表現」を磨いていきます。

---

### 情報の優先順位づけのポイント

- 構造の美学＝「詰め込まない」。ノイズを削ぎ、通り道を作る
- Must / Should / Could / Won't で優先順位を決める
- 下書き後に「問いテスト」。削除しても答えに到達できるか
- 心地よい通り道＝読者が最小ストレスで出口へ
- 削ぎ落としはWeb最適化と両立。問いへの的確さが本質

### 情報の優先順位づけでよくある間違い

| 間違い | 問題 | 改善の方向 |
|---|---|---|
| 削ることを恐れる | 冗長、タブを閉じやすい | Must以外は削除候補に |
| 全部Mustにする | 削れない | Should/Couldを明確に |
| 文字数を水増し | 勾配が緩い | 出口から逆算した必要量だけ |
| 削ぎすぎて根拠不足 | 信頼を失う | R+Eは最小限必要量を残す |
