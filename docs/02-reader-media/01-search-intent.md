# 2-1 検索と問い、検索意図を読み解く

第1章でWebライティングを「手紙」に例え、構造を届け方の礼儀として学びました。けれども、キーワードだけを見て記事を書き始めていませんか。Web上では手紙を送ってこず、「問い（ボール）」を投げます。その断片の裏側にある意図を読み解けなければ、どれほど整った手紙も宛名違いの返信になり、タブを閉じた瞬間に忘れ去られます。

## 第1章の手紙から、問い（ボール）へ

> この節の要点：第1章の手紙比喩を「問いと返球」へ発展させる。Web上では読者がキーワード・ハッシュタグ・プロンプトで「問い」を投げ、ライターはその意図を読み解いて返球する。

第1章では、Webライティングを「手紙」に例え、構造を「届け方の礼儀」として学びました。宛名、段落、章立て。そして、「閉じられた瞬間に消える」というWeb特有の緊張感。

本章は、その手紙の「宛名を決める」章です。Web上では、向こうから手紙は送られてきません。代わりに、「問い（ボール）」を投げます。キーワード、ハッシュタグ、AIへのプロンプト。その断片の裏側にある「意図」を読み解けなければ、どれほど整った手紙も「宛名違いの返信」になり、タブを閉じた瞬間に忘れ去られます。

## 検索とは、日常のあらゆる「問い」を解消する行為

> この節の要点：本書の「検索」は検索エンジンに限らない。SNS・AI・アプリ内探索も含め、読者が日常のあらゆる場面で問いを解消しようとする行為である。

本書でいう「検索」は、検索エンジンの検索窓だけを指しません。

```
検索エンジンへのキーワード入力
SNS のハッシュタグ検索（#在宅ワーク #副業）
AI への質問（「この契約書、問題ありますか？」）
アプリ内の情報探索（ECサイトの絞り込み、社内Wikiの検索）
```

これらは見た目こそ異なりますが、読者の行為は同じです。「日常のあらゆる場面で、自分の中にある『問い』を解消しようとしている」。それが、本書における検索の定義です。

第1章の「自動車整備士」の比喩を借りれば、検索とは読者が「問い（ボール）を投げる行為」であり、Webライティングとは「その問いに対して、納得のいく答えを設計して返す行為」です。プラットフォームが検索エンジンかInstagramかChatGPTかは、「投球フォームの違い」にすぎません。ボールの本質。読者の問い。は変わりません。

## 読者は「問い」を投げている

> この節の要点：キーワードは「投げられたボール」であり、断片的な単語の羅列ではない。キーワードだけを見て書くと「的外れな返球」が生まれ、読者がその場で読む気を失い、発見の機会も失われる。

第1章で、Webライティングを「手紙を書くこと」に例えました。では、Web上で読者は、あなたに手紙を送ってくるでしょうか。

通常、送ってきません。代わりに、読者は「どこかの問いの入り口」に文字を打ちます。

```
検索エンジン：「副業 始め方 初心者」
SNS：        #在宅ワーク #はじめて
AI：         「副業を始めたいのですが、会社にバレますか？」
アプリ：     「エアコン フィルター 掃除」（EC内検索）
```

一見、断片的な単語の羅列に見えます。しかし、それは断片ではありません。「投げられたボール」です。

> 検索とは、読者が「問い（ボール）」を投げる行為である。  
> Webライティングとは、そのボールを正確にキャッチし、納得のいく答えを返す対話である。

キーワードだけを見て記事を書き始める人は、ボールの「形」だけを手に取って、投げた相手の「意図」を見ていません。結果、「副業 始め方」と検索した人に、副業の歴史や著名人の成功談ばかりを返す。「的外れな返球」が生まれます。

自分はすぐにタブを閉じます。第1章で述べたように、Webにおける離脱は「途中でやめた」程度の出来事ではありません。「タブを閉じた瞬間、記事は自分の頭から消える」。

検索エンジン（インターネット上の情報を索引し、ユーザーの問いに応じてページを選び出す仕組み。以降、本書では「検索エンジン」と表記します）もAIも、この対話の「第三者」として関与します。因果の順序を正しく捉えましょう。自分がSNS・検索・AIから記事を開き、すぐに戻るのは「問いに答えられなかった」事実です。その結果が、発見の入口全体に伝わります。逆に、自分が読み続け、答えまで辿り着くのは、「問いに答えられた」事実です。

## 情報の設計士として、情報の通り道を設計する

> この節の要点：情報の設計士の役割は、プラットフォームの特性に応じつつ、読者が最もストレスなく答えに辿り着ける「情報の通り道」を設計することである。

第1章のコラムで触れたように、自動車整備士の仕事は、物理的な機械であろうとデジタルの情報であろうと、「構造を理解し、論理と段取りで『問い』に最適な答えを設計すること」です。

Webライター。より正確には、「情報の設計士」。の役割も同じ構造にあります。

> 検索先（プラットフォーム）が変わっても、読者が「問い（ボール）」を投げているという本質は変わらない。  
> 我々の役割は、プラットフォームの特性に応じつつ、読者が最もストレスなく答えに辿り着ける「情報の通り道」を設計することである。

工場のライン設計者が、部品が詰まらず次工程へ流れる経路を整えるように、情報の設計士は次のような「通り道」を整えます。

| 設計の要素 | 通り道としての機能 |
|---|---|
| 見出し階層 | 「どこに答えがあるか」を示す標識 |
| 段落・リスト | 答えへの段階的な接近路 |
| リンク | 次の問いへつながる分岐と合流 |
| リード文 | 入口での方向確認（「ここに来て正解です」） |
| プラットフォーム別の最適化 | SNSなら共感の入口、AIなら引用しやすい構造 |

### 通り道を示す構造の見える化

同じ内容でも、見出しの設計が「通り道」になります。

```html
<h1>副業の始め方（初心者向け）</h1>
<p>結論：最初の一歩は就業規則の確認です。</p>
<h2>会社に確認すること</h2>
<p>就業規則と副業の可否を確認してください。</p>
<h2>在宅で試せる副業の種類</h2>
<p>週末だけ試せる選択肢を3つ紹介します。</p>
```

「ブラウザでの表示結果（見た目）」：

- タイトルと各見出しが目次として機能し、スキャンで全体像が掴める
- 「会社に確認すること」だけジャンプして読める
- 検索エンジンも、見出しから「問いと答えの対応」を理解しやすい
- ChatGPTやGeminiなどのAIも、見出しと段落のペアを「1ターンの回答」として引用・要約しやすい（本章「AIにおける対話型の検索意図」参照）

構造は、第5章でいう「通信規格」であり、「正当性を証明するエンジニアリング」の出発点です（第3章・第5章）。読者がスキャンで辿る通り道と、AIが引用する単位は、同じ設計から生まれます。

## キーワードの裏側にある検索意図

> この節の要点：検索意図とは、読者が問いの入り口に文字を打った「理由」である。キーワードは宛名の手がかりにすぎず、「なぜ今この言葉を投げたのか」に答えられなければ宛名のない手紙のままである。

「検索意図（Search Intent）」とは、読者が「問いの入り口」（検索窓、ハッシュタグ、AIのプロンプト、アプリ内検索など）に文字を打った「理由」のことです。

「なぜ、この人は今、この言葉を投げたのか？」

この問いに答えられなければ、どれほど丁寧に構造化した手紙も、「宛名のない手紙」のままです。キーワードは宛名の「手がかり」にすぎません。

### キーワードと検索意図の違い

| 表面（キーワード） | 裏側（検索意図の例） |
|---|---|
| 副業 始め方 | 今すぐ始められる具体的な方法が知りたい。失敗したくない |
| エアコン 掃除 臭い | 自分で直せるか判断したい。業者に頼むべきか知りたい |
| 退職 引き継ぎ テンプレート | 明日までに書かなければならない。コピペできる形が欲しい |
| プログラミング 独学 | 本当に独学でいけるのか不安。何から手をつけるべきか |

## 検索意図の四つの型

> この節の要点：検索意図はKnow（知りたい）・Do（やりたい）・Go（行きたい）・Buy（買いたい・選びたい）の四型に整理できる。型ごとに返球のコツが異なる。

実務では、検索意図を大きく4つに分類すると整理しやすくなります。

### 型1：Know（知りたい）、「教えてほしい」ボール

「読者の状態」：概念、方法、原因、比較など、「情報」が欲しい。

「返球のコツ」：結論を早めに示し、根拠と手順を整理する。

「例」：「インボイス制度 とは」「パスワード 安全 作り方」

---

### 型2：Do（やりたい）、「一緒に動いてほしい」ボール

「読者の状態」：具体的な「行動」のやり方、手順、ツールの使い方が欲しい。

「返球のコツ」：ステップ形式、チェックリスト、画面付きの説明。

「例」：「Excel ピボットテーブル 作り方」「WordPress ブログ 開設」

---

### 型3：Go（行きたい）、「その場所へ連れて行ってほしい」ボール

「読者の状態」：特定の「サイト・店舗・ページ」に行きたい。

「返球のコツ」：読者が求める公式ページ・ログイン画面へ迷わず辿り着ける導線を設計する。

「例」：「楽天 ログイン」「スタバ モバイルオーダー」

---

### 型4：Buy（買いたい・選びたい）、「決めてほしい」ボール

「読者の状態」：購入・申込の「判断材料」が欲しい。

「返球のコツ」：比較表、選び方の基準、デメリットも含めた正直な情報。

「例」：「ノートPC おすすめ 2026」「CRM 比較 中小企業」

---

## SNSにおける共感・体験型の検索意図

> この節の要点：SNSのハッシュタグ検索では、正解を求める以前に共感や体験を求める読者がいる。体験・エピソード・温度感から入る返球が通り道になる。

Know / Do / Go / Buy だけでは、SNS上の読者行動を説明しきれないことがあります。ハッシュタグ検索では、読者は「正解を求める以前に、共感や体験を求めている」場合があります。

「返球のコツ」：

- 具体的な「体験・エピソード」から入る
- 「私もそうでした」という「温度感」
- ハッシュタグ・キャプションは、「問いの入口」として設計する

寿司職人がカウンター越しに一言で心を掴むように、SNSでは「わかる、その気持ち」という最初のキャッチが、本編への通り道になります。

## AIにおける対話型の検索意図

> この節の要点：AIへの質問は対話の連続である。一つの見出し・FAQ項目が「1ターン」になるよう設計し、次に聞かれそうなことを先回りする。

AIへの質問は、「1回きりの検索ではありません」。読者は文脈を積み上げながら、対話のなかで問いを磨いていきます。

「返球のコツ」：

- 「1つの記事・1つのFAQ項目が、対話の『1ターン』」になるよう設計する
- 見出しは「独立した問いと答え」のペアに近づける
- 「次に聞かれそうなこと」を見出しまたはFAQで「先回り」する

## 「なぜ投げたのか」を読み解く六つの問い

> この節の要点：執筆前に六つの問い（何が欲しい／なぜ今／知識量／答えの後／含まれないもの／プラットフォーム）に答える。これがボールをキャッチする前の構えである。

執筆前に、次の6つの問いをメモに書いてください。これは「ボールをキャッチする前の構え」です。

```
① この人は「何を知りたい／やりたい／行きたい／買いたい」のか？
② なぜ「今」問いを投げたのか？
③ どれくらい詳しく知っているか？
④ 答えを得たあと、どうなってほしいか？
⑤ 答えに「含まれていないこと」を求めていないか？
⑥ どのプラットフォームから来るか？
```

### 実例：「副業 始め方 初心者」

| 問い | 読み解き |
|---|---|
| ① 何が欲しい？ | 最初の一歩。抽象的なmotivationではなく具体策 |
| ② なぜ今？ | 本業に不安を感じ始めた |
| ③ 前提知識は？ | 副業の種類すら曖昧 |
| ④ 検索後に？ | 「自分にもできそう」と思い、1つ試してみたい |
| ⑤ 含まれないもの？ | 成功事例の羅列だけでは不十分 |

## 検索結果を覗く、プラットフォームごとの確認方法

> この節の要点：同じ問いが各プラットフォームでどう扱われているかを覗くことで、読者全体の投球傾向がわかる。丸写しではなく、意図の確認と通り道の設計のために使う。

ボールの軌道を読むもう一つの方法は、「読者が実際に使うプラットフォーム」で、同じ問いがどう扱われているかを覗くことです。

### 検索エンジン（SERP）での確認

「検索結果ページ（SERP：Search Engine Results Page）」では、同じキーワードで上位に並ぶ記事は、「多くの読者の検索意図に合っていた」可能性が高い返球の例です。

### SNS・AIでの確認

- 「SNS」：同じハッシュタグの投稿で、どんな「体験談・感情」が共感を集めているか
- 「AI」：同じテーマを質問したとき、どんな「追加質問」が続きやすいか

いずれも、読者全体の投球傾向を教えてくれる「練習場」です。上位記事や人気投稿を丸写しするためではありません。「意図の確認」と「通り道の設計」のために使います。

## 意図を外した返球でよくある失敗

> この節の要点：キーワード詰め込み・自分が書きたいこと優先・意図の型の取り違えは、第1章の「壊れた手紙」の多くが「意図の読み違え」から始まる典型例である。

| 失敗 | 何が起きているか | 読者の体験 |
|---|---|---|
| キーワードを見出しに詰め込む | ボールの形だけ真似した | 単語は合っているが、答えになっていない |
| 自分が書きたいことを書く | 相手の投球を見ずに返球した | 「知りたかったことと違う」と感じる |
| 意図の型を取り違える | Know向けにBuy向けの返球をした | 比較検討前の人に購入を迫られる |

第1章で「壊れた手紙」と呼んだ状態の多くは、実は「意図の読み違え」から始まっています。

## 手紙の比喩で検索意図を整理する

> この節の要点：手紙の宛名・挨拶・本文・結び・便種は、それぞれペルソナ・検索意図への共感・意図に合った答え・問い解消後の状態・プラットフォームに対応する。

| 手紙の要素 | 検索意図との対応 |
|---|---|
| 宛名 | ペルソナ（誰が投げたボールか） |
| 挨拶・書き出し | 検索意図への共感 |
| 本文 | 意図の型に合った答え |
| 結び | 問いを解消した後の状態への到達 |
| プラットフォーム | SNSなら共感の入口、AIなら引用しやすい段落 |

---

### 検索意図の読み解きのポイント

- 「検索」とは、検索エンジンに限らず、SNS・AI・アプリ内探索など、「日常のあらゆる問いを解消する行為」
- キーワードは「答え」ではなく、読者が投げた「ボール（問いの断片）」である
- Know / Do / Go / Buy に加え、SNSの「共感・体験型」、AIの「対話型」を意識する
- 執筆前の6つの問いが、キャッチの練習になる

### 検索意図の読み解きでよくある間違い

| 間違い | 届いてしまう体験 | 改善の方向 |
|---|---|---|
| キーワード密度を優先する | 単語は並ぶが、質問に答えていない | 6つの問いで意図を言語化してから執筆 |
| 検索意図を1つに決め打ちする | 初心者向けのはずが、上級者向けの返球になる | 前提知識（③）をペルソナとセットで確認 |
| 検索エンジンの結果だけを見る | SNS・AI経由の期待とズレる | 流入プラットフォームごとに入口を設計 |
