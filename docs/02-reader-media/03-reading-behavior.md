# 2-3 読者の読み方（スキャン・ジャンプ・離脱）

記事を公開したあと、「最後まで読んでもらえるはず」と思っていたのに、途中で自分がタブを閉じてしまう。そんな経験を、読者として思い出してみてください。Webではそもそも「通読」していない可能性があります。寿司職人が客の食べ方を想定して握るように、返球の質だけでなく、返球の受け取り方を想定して書く。検索・SNS・AIのどの入口から来ても、斜め読みでも答えが届く設計が、Webライティングの読者理解です。

## 返球を受け取ったあとの読者

> この節の要点：返球をしたあともが勝負である。Webでは能動的に選び、合わなければ自分がタブを閉じる。返球の受け取り方を想定して書くことが読者理解の核心である。

検索意図を読み解き、ペルソナに向けて記事を書いた。ボールはキャッチし、返球もした。

しかし、ここで終わりではありません。「読者の時間を預かった設計士」にとって、返球のあともが勝負です。

紙の手紙なら、受け取った人が封を開き、順番に読むかもしれません。Webでは、「読み方そのものが違います」。そして、「合わなければ自分がタブを閉じる」。

第1章で触れたように、Webでは「能動的」です。目次を飛ばし、見出しだけを拾い、気になった段落だけ読み、合わなければすぐタブを閉じます。

これは読者の「失礼」ではありません。「時間と注意が限られたなかで、必要な答えを探している」誠実な行動です。

> 返球の質だけでなく、「返球の受け取り方」を想定して書く。それがWebライティングの読者理解です。

## Web読者の三つの読み方

> この節の要点：Webの基本はスキャン（流し読み）・ジャンプ（飛び読み）・離脱（タブを閉じる）の三つ。それぞれに設計上の示唆がある。

### 読み方1：スキャン（流し読み）

「何をしているか」：見出し、リスト、画像キャプションだけを「視線でなぞる」。

「自分の心理」：「この記事、自分の質問に答えていそうか？」を「一瞬で」判断している。

「ライターへの示唆」：

- 見出しだけ読んでも、記事の骨格がわかるようにする（第1章のチェックリスト）
- 各見出しは「小さな答え」になっているとよい
- 重要な結論は、見出し直下の最初の2文に置く

スキャンは、ボールを受け取った直後の「一瞬のキャッチ」です。ここで「違う球だ」と思われたら、自分はタブを閉じます。

---

### 読み方2：ジャンプ（飛び読み）

「何をしているか」：目次や見出しから「必要な部分だけ」に飛ぶ。

「読者の心理」：「自分が知りたいところだけ読めばいい」と考えている。最初から最後まで読む義務感はない。

「ライターへの示唆」：

- 見出し階層（H2 → H3）を論理的に設計する
- 各セクションは「単体で意味が通る」ように書く（前の段落に依存しすぎない）
- 「詳しくは第3章で」ではなく、リンクテキストで行き先がわかるようにする

ジャンプは、長い返球のなかから「必要な部分だけ受け取る」読み方です。

---

### 読み方3：離脱（タブを閉じる）、自分の頭から消える

「何をしているか」：記事を読み始めたが、「途中または直後に」タブを閉じる。画面を離れ、タイトルも内容も思い出せなくなる。

第1章で強調した通り、Webにおける離脱は、紙の本を読みかけで閉じることとは「質が異なります」。本棚に残る本は、明日も再開できます。Webページは、閉じられた瞬間に「自分の認知空間から消える」。離脱は、ダッシュボード上の数字ではない。「返球が届く前に、対話が終わること」です。

「自分の心理」：「答えになっていない」「読むのが面倒」「信頼できない」と感じた。そして、「もう戻らない」選択をした。

「主な原因」（ライター側で対処できるもの）：

| 原因 | 読者の体験 | 設計士としての問い |
|---|---|---|
| 検索意図とズレ | 「知りたかったことと違う」 | 投げられたボールを正確にキャッチしたか？ |
| 結論が遅い | スキャン段階でタブを閉じる | タブを閉じる前に、答えの予告を見せたか？ |
| 段落が長すぎる | 読む気力が続かない | 一瞬の呼吸で通過できる導管か？ |
| 専門用語の説明なし | 「自分向けではない」と判断 | ペルソナの手元まで届く言葉か？ |
| 信頼性の欠如 | 出典がなく、感覚だけの記述 | 返球に、納得の根拠があるか？ |

> タブを閉じさせない設計は、数字を改善することではない。自分が答えまで辿り着けるようにすること。それが、情報の設計士への最大の敬意である。

## スキャン読みを助ける構造の見える化

> この節の要点：構造が曖昧だと、スキャン段階で自分がタブを閉じる。見出しの印が標識となり、流し読みで記事の価値を聴き分けられる。

スキャン読者は、見出しの「印」を頼りに記事を流し読みします。構造が曖昧だと、スキャン段階で自分はタブを閉じます。第1章と同様、コード（構造）と表示結果（見た目）をセットで確認しましょう。

### 構造が曖昧な場合（スキャンでタブを閉じやすい）

```html
<p>
  <strong>副業の始め方</strong><br><br>
  副業は今や選択肢のひとつです。<br><br>
  <strong>会社に確認すること</strong><br><br>
  就業規則を確認してください。
</p>
```

「ブラウザでの表示結果（見た目）」：

- すべてが「一続きの段落」に見える
- 見出しとして目次化されない
- スマホでは「文字の塊」として表示される
- 流し読みで「どこに答えがあるか」が選べない

---

### 構造が明確な場合（スキャン・ジャンプしやすい）

```html
<h1>副業の始め方（初心者向け）</h1>
<p>結論：最初の一歩は、就業規則の確認です。</p>
<h2>会社に確認すること</h2>
<p>就業規則を確認してください。</p>
<h2>在宅で試せる副業の種類</h2>
<p>週末だけ試せる選択肢を3つ紹介します。</p>
```

「ブラウザでの表示結果（見た目）」：

- タイトル、リード、見出しが視覚的に区切られる
- スマホでも「会社に確認すること」だけジャンプしやすい
- 目次（アウトライン）として機能し、スキャンで全体像が掴める
- 各H2が「小さな答え」として機能する

自動車整備士がエンジン音で異常を聴き分けるように、スキャン読者は「見出しの標識」で記事の価値を聴き分けます。標識がなければ、整備士も読者も、先へ進めません。

## 自分の選択が、発見性に伝わる

> この節の要点：自分が「開いてすぐ戻る」「読み続ける」「どこまで読むか」を選ぶ。それが問いと答えの適合度を映す鏡であり、SNS・検索・AIから来たとき、その結果は発見の入口全体に影響しうる。

第1章で触れた通り、離脱は「タブを閉じた瞬間、記事が自分の頭から消える」ことです。ここでは、その背後にある体験を整理します。

検索結果を見てクリックする前に判断したこと、開いてすぐ閉じたこと、読み続けたこと。自分の選択と、そのときの体験は次のとおりです。

| 自分の選択 | そのときの体験 | 発見の入口が読み取りうる意味 |
|---|---|---|
| 1ページだけ見てすぐ閉じる | 開いてすぐタブを閉じる | 「問いに答えられなかった」 |
| ページに読み続ける | 答えを探して留まる | 「答えとして有用だった」 |
| 必要なところまで読む | 必要な情報を探して進む | 「必要な情報に辿り着けた」 |

これらは、検索エンジンが「ランキングの唯一の決定因子」だと断言できるものではありません。アルゴリズムは複合的で、常に更新されます。しかし、因果の順序は明確です。自分の選択が先にあり、検索エンジンやAIがそこから学習する。「問いに答えられたかという事実は、適合度を映す鏡」。この理解は、設計士として不可欠です。

```
問い（SNS・検索・AI） → 記事（返球） → 自分の選択（受け取り方）
                                    ↓
                          問いに答えられたかの事実
                                    ↓
                          発見の入口への学習（第5章）
```

スキャンで開いてすぐ閉じた記事は、「レイヤーケーキの第1〜2層」。タイトルとリード。で「自分向けではない」と判断された可能性が高いです。

## F字パターンとレイヤーケーキ

> この節の要点：F字パターンはファーストビューと見出し冒頭に重要情報を置く示唆を与える。レイヤーケーキは読者がタイトル→リード→見出し→本文の層を突破しながら読むモデルである。

視線追跡（eye-tracking）の研究では、Web記事の読み方に傾向が見られます。

### F字パターンとは何か

画面上部を左から右へ読み、次第に左端だけを下方向にたどる。「F字型」の視線移動。

「示唆」：ファーストビュー（最初に見える範囲）と、各見出しの「左側・冒頭」に重要情報を置く。

### レイヤーケーキとは何か

読者は記事を「層」として読む。

```
第1層：タイトル → 「この記事、自分向け？」
第2層：リード文 → 「答えがありそう？」
第3層：見出し → 「どこに答えがある？」
第4層：本文 → 「納得できる？」
```

層を突破できなければ、次の層へ進みません。検索意図に合った返球を、「層ごとに」設計するイメージです。

## 検索意図の型ごとの読み方の違い

> この節の要点：Know・Do・Go・Buyそれぞれに典型的な読み方があり、設計のポイントが異なる。ペルソナとセットで「この人はどう読むか」を想像する。

| 意図の型 | 典型的な読み方 | 設計のポイント |
|---|---|---|
| Know | スキャン → 必要な段落だけジャンプ | 結論を早く、見出しで答えを示す |
| Do | 手順部分にジャンプ、そこを精読 | ステップ番号、チェックリスト、目次 |
| Go | 最短ルートを探す | 公式リンクを冒頭近くに、迷わせない |
| Buy | 比較表をスキャン、気になる項目だけ深読み | 比較表、Pros/Cons、選び方の基準 |

ペルソナとセットで、「この人はどう読むか」を想像してください。忙しい会社員の健太さんは、おそらくスキャンとジャンプが中心です。最初の一瞬で「自分向けだ」と思わせる層設計が必要になります。

## 手紙の比喩で読み方を考える

> この節の要点：Webの読者は実際に斜め読みをしている。「斜め読みでも答えが届く手紙」を書くことが、構造化の目的の一つである。

紙の手紙を、受け取った人が「斜め読み」したと想像してください。

- 宛名と最初の一行を読んで、自分向けか判断する → 「タイトルとリード」
- 見出しのような区切りがあれば、そこだけ読む → 「H2・H3」
- 長い段落は飛ばす → 「段落の長さ」

Webの読者は、実際に斜め読みをしています。「斜め読みでも答えが届く手紙」を書く。それが構造化の目的の一つです（第1章との接続）。

---

### Web読者の読み方のポイント

- Webでは「スキャン・ジャンプ・離脱（タブを閉じる）」が基本。最初から通読は少数
- 「離脱＝消滅」（第1章）。タブを閉じた瞬間、記事は自分の頭から消える
- 自分が「開いてすぐ戻る」「読み続ける」を選ぶことは、問いに答えられたかを映す。発見の入口（検索を含む）にその結果が伝わりうる
- スキャン対策：見出しだけで骨格がわかる構成。タブを閉じる前の「一瞬の判断」が勝負
- ジャンプ対策：各セクションが単体で意味を持つ
- 離脱対策：検索意図・結論の位置・段落長・信頼性。「設計の最終目的」

### Web読者の読み方でよくある間違い

| 間違い | 問題 | 改善の方向 |
|---|---|---|
| 序論が長い | スキャン段階でタブを閉じる | リードで結論または答えの予告 |
| 見出しが抽象的 | ジャンプ先が選べない | 見出しに「答えの一部」を入れる |
| 前の段落を読まないと意味が通じない | ジャンプ読者に不親切 | 各H2の冒頭で文脈を1文で補う |
| 離脱を「向こうの問題」とする | 改善機会を逃す | 意図・構成・信頼性を見直す |
