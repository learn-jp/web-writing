# 13-6 章末まとめ・チェックリスト・演習

第13章では、本編第1章〜第7章と応用編第8章〜第12章を、企画から公開・運用までの標準段取りに統合しました。本章のまとめは、工房の作業手順書として毎回同じ順序で回すための最終確認です。

## 第13章のメッセージ（再確認）

> この節の要点：腕前は章ごとに積み上がるが、段取りがなければ品質は再現できない。第13章は応用編の知見を1本の制作ラインに並べ替えた標準作業手順である。

第8章は声、第9章は画面、第10章は通路、第11章は修理、第12章は年間計画。第13章は、それらを1本の制作ラインに並べ替えた標準作業手順です。検索・SNS・AI引用のいずれを入口にしても、同じ5ステップと3段階レビューで品質を再現します。

## 章末まとめ

> この節の要点：5ステップ・RACI・最小ツール・3段階レビュー・公開後3リズム・改善ログを、8行に圧縮して確認する。

1. 5ステップ：企画→リサーチ→構成→執筆→校正。執筆から始めない
2. 各ステップに成果物と完了条件を設ける
3. ディレクター・ライター・編集者のRACIで承認を固定
4. ツールは工程ごとの最小セット。段取り表が主、道具が従
5. レビューは構成・執筆・校正の3段階。指摘はレイヤー＋優先度
6. 公開後は Day 0・Day 28・月次の3リズム
7. 改善ログ1枚で、制作とリライトを同じ表で管理
8. 年1回、ワークフロー自体を見直す

## チェックリスト

> この節の要点：プロジェクト開始・各ステップ完了・公開時・月次の4ブロックで確認項目を固定する。

### 記事プロジェクト開始時

- [ ] 企画シートにMust・成功指標・承認者がある
- [ ] 3役（または兼務ルール）とRACIが決まっている
- [ ] 公開予定日とレビュー3段階の日程がある

### 各ステップ完了時

- [ ] ステップ1：企画シート承認済み
- [ ] ステップ2：出典リスト・問い3つ以上
- [ ] ステップ3：H2＋PREP骨格、アウトライン承認
- [ ] ステップ4：本文ドラフト、外門・リード完成
- [ ] ステップ5：13-1節公開前チェックリスト完了

### 公開時

- [ ] 校正レビュー P0 ゼロ
- [ ] 証明書欄（更新日・出典・著者）完成
- [ ] 改善ログに1行追加
- [ ] 公開日+28日 再試運転をカレンダー登録

### 月次（チーム運用）

- [ ] 新規制作本数とリライト本数の工数配分を確認
- [ ] 前月公開記事のDay 28再試運転を実施
- [ ] ワークフロー上のボトルネック（レビュー遅延等）を1件記録

## 演習

> この節の要点：テーマ1本について、企画から公開後計画までをシミュレーションする。構成レビューでの差し戻し想定を1件書くと理解が深まる。

課題：テーマ1本について、企画から公開までをシミュレーションしてください（実際に公開しなくても可）。第2章〜第7章の演習と同じテーマ（例：副業始め方）を使うと、接続が確認しやすいです。

### 提出物

1. 企画シート（Must、ペルソナ、成功指標、承認者）
2. リサーチメモ（問い3つ、競合3本、出典リスト）
3. アウトライン（H2＋PREP骨格、外門案）
4. 本文抜粋（リード＋H2-1全文。または全文）
5. 校正チェックリスト（13-1節）の記入結果
6. RACI表（担当者名または兼務ルール）
7. 公開後計画（Day 0チェック、Day 28指標、改善ログ1行）

ヒント：構成レビューで差し戻しが起きた想定を1件書くと、13-4節の理解が深まります。公開後は外門の通過と玄関で引き返す傾向を「想定データ」で可です。
