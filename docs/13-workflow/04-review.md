# 13-4 レビューとフィードバックの受け方

第11-5節で、部分リライトは変更範囲を明記すると述べました。新規執筆のレビューも同じです。「なんとなく直して」は、執筆者が全面書き直しに入り、公開日だけが過ぎます。レビューとフィードバックは、5ステップの中で最も手戻りを生む工程です。形式を固定します。

## レビューの3段階

> この節の要点：構成・執筆・校正の3段階レビューで段階を固定する。公開直前に全部見るのは最もコストが高い。

| 段階 | タイミング | レビュアー | 目的 |
|---|---|---|---|
| 構成レビュー | ステップ3完了後 | 編集者 | H2の通り道、Must整合 |
| 執筆レビュー | ステップ4ドラフト後 | 編集者または同行 | リード、関所、トーン |
| 校正レビュー | ステップ5 | 編集者 + 必要なら法務・監修 | 証明書、法務、alt |

3段階を飛ばして「公開直前に全部見る」は、最もコストが高いパターンです。構成で止められる問題を、執筆後に直すと工数が3〜5倍になります。

---

## 構成レビューで見る項目

> この節の要点：アウトライン提出時に、想定問い・H2順序・Must・PREP骨格・外門案を確認する。差し戻しはレイヤーと触らない範囲を明記する。

| 項目 | OKの基準 | 参照 |
|---|---|---|
| 想定問い | 企画シートと1行一致 | 第2章 |
| H2の順序 | 見出しだけで出口まで追える | 第3-2節 |
| Must / Must Not | 禁止論点が含まれていない | 第3-5節 |
| PREP骨格 | 各H2に返球の骨がある | 第3-1節 |
| 外門案 | titleが問いと一致 | 第4章 |

差し戻し例（良い指示）：

```
【レイヤー】構成（H2-3）
【問題】Mustの「就業規則」に対応するH2がない
【指示】H2を1つ追加。就業規則確認の手順をPREP骨格まで書いて再提出
【触らない範囲】H2-1、H2-2
```

---

## 執筆レビューで見る項目

> この節の要点：リード・関所・トーン・専門語・内部リンクを確認する。「好み」ではなくガイドラインの行を引用して指摘する。

| 項目 | OKの基準 | 参照 |
|---|---|---|
| リード | 50〜150字、問い宣言 | 第4-3節 |
| 関所 | H2直下で要点が先に来る | 第3-3節 |
| トーン | ガイドラインの語彙・敬体 | 第8章 |
| 専門語 | 初出定義または平易語 | 第7-3節 |
| AI補助の事実確認 | 出典・数値・禁則語を人間が検証済み | 第8-4節 |
| 内部リンク | 関連記事へ意味のある文言 | 第5-5節 |

「文体が好みと違う」だけの指摘は、ライターが修正方針を決められません。ガイドラインのどの行に反するかを引用します（第8-4節）。

---

## 校正レビューで見る項目

> この節の要点：見出し階層・外門整合・証明書・alt・モバイルを点検する。校正のついでにH2追加は執筆ステップへ差し戻す。

| 項目 | OKの基準 | 参照 |
|---|---|---|
| 見出し階層 | H1→H2→H3の飛び級なし | 第3-2節 |
| title・meta・H1 | 整合、文字数目安。SNS・AI引用でも同じ約束が伝わるか | 第5-3節 |
| 証明書欄 | 更新日、出典、著者 | 第7-4節 |
| alt | 意味を伝える説明 | 第10-3節 |
| モバイル | ファーストビューで問いが見える | 第9-3節 |
| SNSプレビュー | title・OGPが約束どおり表示される | 第5-3節 |

校正レビューで新規論点（H2の追加など）が出た場合は、執筆ステップへ戻します。校正のついでに構成変更すると、公開ゲートが崩れます。

---

## フィードバックの書き方（レビュアー向け）

> この節の要点：指摘はレイヤー・場所・問題・指示の4要素をセットにする。P0〜P3で優先度を付け、締切内に直せる量にする。

レビューコメントは、次の4要素をセットにします。

| 要素 | 内容 |
|---|---|
| レイヤー | 外門 / 防波堤 / 関所 / 物流 / 証明書 / トーン |
| 場所 | H2名、段落、title 等 |
| 問題 | 読者・Must・ガイドラインのどれに抵触するか |
| 指示 | 追加・削除・書き換えの具体 action |

```
✗ 「リードが弱い」
✓ 【防波堤】リード：想定問い「バレないか」が宣言されていない。
   第2章ペルソナの不安1文を冒頭に追加してください。
```

優先度を付けると、執筆者が締切内に直せます。

| 優先度 | 意味 |
|---|---|
| P0 | 公開不可（事実誤り、Must違反、証明書空白） |
| P1 | 公開前に直す（外門、リード、alt） |
| P2 | 公開後1週間以内（表現の微調整） |
| P3 | 次回リライトで可（第11章） |

---

## フィードバックの受け方（ライター向け）

> この節の要点：P0を即修正し、P1をレイヤーごとにバッチ修正する。反映/却下を返信し、却下は根拠を添える。

フィードバックを受けたら、次の順で処理します。

```
1. P0を一覧化 → 即修正
2. P1をレイヤーごとにバッチ修正（外門まとめ、関所まとめ）
3. 反映した / 却下した をコメントに返信
4. 却下は理由必須（Must・出典・ガイドラインの根拠）
5. 校正チェックリストを再実行
```

「却下」は悪意ではありません。Mustとガイドラインが優先です。口頭で合意した変更は、企画シートまたはコメントに残します。残さないと、次のレビューで同じ指摘が繰り返されます。

---

## ステークホルダーレビュー（第12章との接続）

> この節の要点：法務・監修者・事業責任者には段階を分けて送付する。全員に同時送付すると矛盾した指摘が返る。

法務、監修者、事業責任者が関わる場合、タイミングを固定します。

| 関係者 | 推奨タイミング | 見る内容 |
|---|---|---|
| 監修者（Expertise） | 執筆レビュー後 | 事実、数値、専門表現 |
| 法務 | 校正レビュー | 表現、免責、利益相反 |
| 事業責任者 | 公開前 | Must、CTA、KPI |

全員にドラフト全文を同時送付すると、矛盾した指摘が返ります。段階を分け、前段の反映後に次を送ります（第12-5節）。

---

## レビュー記録テンプレート

> この節の要点：レビュー履歴を1枚に集約する。第11章のリライト時に「過去に何を直したか」を参照できる。

| 日付 | 段階 | レビュアー | P0 | P1 | 反映完了 | 公開可否 |
|---|---|---|---|---|---|---|
| 6/10 | 構成 | 編集A | 0 | 1 | 6/11 | 執筆へ |
| 6/14 | 執筆 | 編集A | 0 | 2 | 6/15 | 校正へ |
| 6/16 | 校正 | 編集A | 0 | 0 | 6/16 | 公開可 |

記録が残ると、第11章のリライト時に「過去に何を直したか」が参照できます。

---

### ポイント

- 構成・執筆・校正の3段階レビュー。直前一括は避ける
- 指摘はレイヤー・場所・問題・指示の4要素
- P0〜P3で優先度を付ける
- ライターは反映/却下を返信し、チェックリストを再実行

### よくある間違い

| 間違い | 問題 | 改善の方向 |
|---|---|---|
| 口頭だけの指摘 | 再発、担当者不在で迷子 | コメントまたはシートに残す |
| 好みだけの修正依頼 | ライターが動けない | ガイドライン行を引用 |
| 校正でH2追加 | 工数爆発 | 構成レビューへ差し戻し |
| P0なしに公開 | 証明書・事実リスク | 公開ゲートを編集者が担う |
