# 13-1 企画・リサーチ・構成・執筆・校正の5ステップ

第3章でアウトラインは導管の設計図であると述べました。執筆から入って手戻りが続く経験は、あなただけのものではありません。第13章は、その教訓をチームでも個人でも再現できる標準手順にまとめます。整備工房が受付→診断→部品手配→組み立て→最終点検の順を飛ばさないように、Web記事も企画→リサーチ→構成→執筆→校正の5工程で作ります。

## 5ステップの全体像

> この節の要点：1本の記事は、企画→リサーチ→構成→執筆→校正の5工程で作る。第1章〜第7章の順序を、現場の段取り表として固定する。

```
ステップ1 企画     … 何を・誰に・なぜ（第2章・第12章）
    ↓
ステップ2 リサーチ … 問い・競合・根拠（第2章・第5章 Web最適化・第7章）
    ↓
ステップ3 構成     … アウトライン・Must（第3章）
    ↓
ステップ4 執筆     … 本文・外門・物流（第4章・第5章 Web最適化（検索・SNS・AI引用））
    ↓
ステップ5 校正     … 構造・証明書・応用編チェック（第7章・第8〜10章）
    ↓
公開 → 運用（13-5節・第6章・第11章）
```

| ステップ | 主な成果物 | 参照章 | 目安工数（中記事） |
|---|---|---|---|
| 1 企画 | 企画シート1枚 | 第2章、第12章 | 30分 |
| 2 リサーチ | 問いリスト・競合メモ | 第2章、第5章 Web最適化、第7章 | 1〜2時間 |
| 3 構成 | アウトライン | 第3章 | 1〜2時間 |
| 4 執筆 | 本文ドラフト | 第4章、第5章 | 3〜6時間 |
| 5 校正 | 公開稿＋証明書欄 | 第7章、第8〜10章 | 1〜2時間 |

工数は記事の長さ・専門度・チーム人数で変わります。重要なのは、各ステップの「完了条件」を文書化し、次へ渡すことです。

---

## ステップ1：企画

> この節の要点：執筆の前に「この記事が存在する理由」を1枚の企画シートにまとめる。MustとMust Notを先に決め、リサーチの範囲を切る。

企画は、執筆の前に「この記事が存在する理由」を1枚にまとめる工程です。

| 項目 | 記入内容 | 参照 |
|---|---|---|
| 主目的 | 情報 / 共感 / 行動（第1-3節） | 第1章 |
| 想定問い | 読者が投げるボール1行 | 第2-1節 |
| ペルソナ | 誰が・どんな状態で読むか | 第2-2節 |
| Must / Must Not | 約束する内容・書かない内容 | 第3-5節 |
| カレンダー上の位置 | いつ公開するか | 第12章 |
| 成功指標 | 外門の通過、CV、問い合わせ等 | 第6章、第14章 |

企画シートがないままリサーチに入ると、情報収集が終わりません。Must Not を先に決めると、リサーチ段階で範囲が広がりにくくなります。

### 完了条件

- [ ] 主目的と想定問いが1行ずつ書けている
- [ ] ペルソナとMust/Must Notが合意されている（チームの場合）
- [ ] 公開予定日と成功指標が1つ以上ある

---

## ステップ2：リサーチ

> この節の要点：企画で決めた問いに答える材料を揃える工程である。キーワード羅列ではなく、意図・競合・根拠・内部リンク候補を整理する。

リサーチは、企画で決めた問いに答えるための材料を揃える工程です。キーワード羅列ではありません。

| リサーチ種別 | 内容 | 参照 |
|---|---|---|
| 意図調査 | 上位表示ページがどんな問いに答えているか | 第2-1節 |
| 語彙調査 | 読者が使う言葉・専門語の境界 | 第2-2節、第8-3節 |
| 競合確認 | 外門（title）・関所（H2）の型 | 第4章、第5章 |
| 根拠収集 | 出典・数値・制度の一次情報 | 第7-4節 |
| 内部リンク候補 | ハブ・関連記事 | 第5-5節 |

Search Console やキーワードツールは、すでに自社記事がある場合に有効です。新規テーマでは、検索結果の上位5件を読み、問い×答えの型をメモするだけでも十分です。

### 完了条件

- [ ] 想定問いを3つ以上、読者の言葉で書けている
- [ ] 競合または類似記事を3本以上読み、足りない角度を1つ特定した
- [ ] 引用予定の出典URLまたは文献をリスト化した
- [ ] 内部リンク候補を2本以上メモした

---

## ステップ3：構成

> この節の要点：第3-5節のアウトライン6ステップをワークフローの中核として実行する。執筆前に見出しだけで通り道を確認し、手戻りコストを最小化する。

構成は、第3-5節のアウトライン6ステップを、このワークフローの中核として実行します。

```
問いと出口 → Must確認 → H2の関所 → PREP骨格 → リスト・表の配置 → 見出し読み上げ検証
```

執筆前に、見出しだけを読んで通り道が通るか確認します（第3-2節）。ここで直すコストは、本文執筆後の10分の1以下です。

| 成果物 | 形式 |
|---|---|
| アウトライン | H1 + H2 + 各H2のPREPメモ |
| 優先順位 | Must / Should / Could の区分（第3-6節） |
| 外門案 | title・meta・H1のたたき（第5-3節） |

### 完了条件

- [ ] H2だけ読んで記事の流れが追える
- [ ] 各H2にPREPの骨（P/R/E/Pメモ）がある
- [ ] Must Not に抵触する論点がアウトラインに含まれていない
- [ ] 企画シートの成功指標に対応するH2がある

---

## ステップ4：執筆

> この節の要点：アウトラインに沿ってH2単位で本文を埋める。外門・関所・物流・表現・モバイルの5レイヤーを意識し、新論点はアウトラインへ戻す。

執筆は、アウトラインに沿って本文を書く工程です。いきなり整文から入らず、H2単位で下書きを埋めます。

| レイヤー | 執筆の焦点 | 参照 |
|---|---|---|
| 外門 | title・meta・H1・リード | 第4章、第5-3節 |
| 関所 | 各H2と直下段落 | 第3章 |
| 物流 | キーワード配置・内部リンク | 第5-4節、第5-5節 |
| 表現 | トーン・語彙 | 第8章 |
| モバイル | 段落長・ファーストビュー | 第9章 |

執筆中に新しい論点が浮かんだ場合は、本文に追記する前にアウトラインへ戻ります。導管なしに水を足すと、読者の出口が見えなくなります（第3章）。

### 完了条件

- [ ] アウトラインのH2がすべて本文化されている
- [ ] リードが想定問いを1文で宣言している（第4-3節）
- [ ] 画像・表・リストに配置計画どおりの要素がある
- [ ] 第7章形式の著者・出典欄の下書きがある

---

## ステップ5：校正

> この節の要点：校正は誤字脱字だけではない。構造・外門・証明書・トーン・モバイル・アクセシビリティを含む公開前の総合点検である。

校正は、誤字脱字だけではありません。本書では「公開前の総合点検」として定義します。

| 点検カテゴリ | 確認内容 | 参照 |
|---|---|---|
| 構造 | 見出し階層、段落、リスト | 第3章 |
| 外門・物流 | title/meta/H1、内部リンク、OGP | 第5章 Web最適化 |
| 証明書 | 更新日、出典、著者、利益相反 | 第7-4節 |
| トーン | ブランドガイド、敬体の統一 | 第8章 |
| モバイル | ファーストビュー、段落長 | 第9章 |
| アクセシビリティ | alt、平易語、色だけに頼らない表現 | 第10章 |

校正は執筆者一人のセルフチェックでも構いません。チームでは、編集者または別ライターによるレビュー（13-4節）をこのステップに組み込みます。

### 完了条件

- [ ] 13-1節の公開前チェックリスト（下記）をすべて確認した
- [ ] 証明書欄（更新日・出典・改訂内容）が埋まっている
- [ ] スマホ表示でファーストビューを確認した
- [ ] レビュー指摘がすべて反映または却下理由付きで記録された

---

## 公開前チェックリスト（5ステップ総合）

> この節の要点：公開ボタンの直前に、企画・構成・執筆・証明書の整合を一覧で確認する。感覚ではなくチェックリストで最終ゲートを通す。

公開ボタンの直前に、次を確認します。

### 企画・構成

- [ ] 企画シートのMustと本文が一致している
- [ ] 主目的（情報・共感・行動）が読者に伝わる構成になっている

### 執筆・構造

- [ ] 見出しだけで全体像が掴める
- [ ] 各段落に一つの主題がある
- [ ] title・meta・H1が整合している

### 証明書・応用編

- [ ] 出典・数値を検証した
- [ ] alt・リンク文言・平易語を確認した（第10章）
- [ ] トーンがガイドラインと一致している（第8章）

---

## 本編パイプラインとの対応図

> この節の要点：第1章〜第7章の学びと5ステップの工程を対応づける。本編は制作、第6章は公開後の精密検査に接続する。

```
第1章  手紙の型        → ステップ3〜4（構造・執筆）
第2章  問いと返球      → ステップ1〜2（企画・リサーチ）
第3章  導管            → ステップ3（構成）
第4章  玄関・防波堤    → ステップ4（外門・リード）
第5章  Web最適化（検索・SNS・AI引用） → ステップ2・4（リサーチ・執筆）
第6章  精密検査        → 公開後（13-5節）
第7章  証明書          → ステップ5（校正）
```

第8章〜第12章は、主にステップ4〜5と公開後運用に組み込まれます（13-3節、13-5節）。

---

### ポイント

- 5ステップ：企画→リサーチ→構成→執筆→校正。執筆から始めない
- 各ステップに成果物と完了条件を設ける
- 構成（ステップ3）で手戻りコストを最小化する
- 校正は誤字だけでなく、証明書と応用編チェックを含む
- 公開後は第6章・第11章の運用に接続する

### よくある間違い

| 間違い | 問題 | 改善の方向 |
|---|---|---|
| 執筆から開始 | Mustが未定、手戻り大 | 企画シート1枚を先に |
| リサーチ無限 | 公開日が遅れる | Must Notで範囲を切る |
| アウトライン省略 | 関所で自分が戻る | ステップ3を必須化 |
| 校正＝誤字のみ | 証明書・altが空白 | ステップ5の点検表を使う |
