# 12-1 あなたの物語戦略の全体像

しかし整備工場の責任は1台の修理で終わりません。何台を、いつ、どの順番で点検するか。1本ずつ直せても全体像が見えなければ、読者のジャーニーに穴が残ります。第12章は、その整備計画を書く章です。第5章 Web最適化で設計した物流を、サイト全体の体系として束ねていきます。

## 単発の記事から体系へ

> この節の要点：単位を「1記事」から「あなたの物語の体系」へ移す。ペルソナのジャーニー全体に答える設計が、コンテンツ戦略の出発点である。

本編第1章から第7章では、1通の手紙、1本の導管、1台分の物流を設計しました。第6章で精密検査、第11章で修理。いずれも「1記事」を単位にしています。

第12章では単位が変わります。単位は「1記事」ではなく「あなたの物語の体系」です。

| 視点 | 単発の記事 | 体系で設計 |
|---|---|---|
| 問い | このキーワードに答える | ペルソナのジャーニー全体に答える（[第2-6節](../02-reader-media/06-customer-journey.md)） |
| 構成 | 1本のPREP・逆ピラミッド | 複数記事のMust/Should/Could（[第3-6節](../03-structure/06-prioritization.md)） |
| リンク | 記事内の次の関所 | ハブとスポークの物流網（[第5-5節](../05-seo-basics/05-linking.md)） |
| 改善 | 故障した1台を修理 | 優先度に沿った整備計画（[第6-5節](../06-data-analytics/05-prioritization-engineering.md)） |
| 運用 | 公開して終わり | コンテンツカレンダーで継続 |

> あなたの物語戦略とは、読者のジャーニーに沿って、記事群の役割・順序・更新サイクルを設計することである。

## 整備計画とおまかせ献立

> この節の要点：整備計画とおまかせ献立は同じ構造（対象・サイクル・優先順位・在庫・記録。1台・1貫ではなく、全体を設計する。）

比喩を2つ並べて整理します。整備計画（対象・サイクル・優先順位・在庫・記録）と、おまかせ献立（客・流れ・順序・準備・記録）は同じ構造です。1貫の握りだけを考える板前も、1台だけ直す整備士も、全体の満足度をコントロールできません。あなたの物語も、1記事の良し悪しではなく、体系として設計します。

## あなたの物語戦略の5層

> この節の要点：第12章の5節は、整備計画の5枚の書類（クラスター・カレンダー・優先順位・合意・まとめに対応する。）

第12章で扱う5つの節は、整備計画の5枚の書類に対応します。

| 節 | 整備計画での対応 | 献立での対応 |
|---|---|---|
| 12-2 トピッククラスター | 車両の系統・部品構成 | コースの柱（ハブ）と各握り（スポーク） |
| 12-3 コンテンツカレンダー | 年間点検スケジュール | 旬のネタと提供タイミング |
| 12-4 優先順位づけ | 今月の整備3台 | 今日出す順番 |
| 12-5 ステークホルダー | 工場長・顧客との合意 | 店長・仕入れ先との段取り |
| 12-6 まとめ・演習 | 計画書の完成 | 3ヶ月分の献立表 |

## 本編・応用編との位置づけ

> この節の要点：第12章は第11章（修理）の上流、第13章（ワークフロー）の上流。「何を、いつ、なぜ書くか」を決める工程である。

```
本編
  第2章 ペルソナ・ジャーニー … 誰に、どの段階で返球するか
  第3章 構成・削ぎ落とし … 1記事の導管設計
  第5章 Web最適化（検索・SNS・AI引用） … 物流・クラスターの基礎
        ↓
応用編
  第6章 精密検査 … 第2の返球で故障を見つける
  第11章 リライト … 既存資産の修理
  第12章 あなたの物語戦略 … 体系の設計（本章）
  第13章 ワークフロー … 企画から公開の標準化
```

第12章は、第13章のワークフローの「何を書くか」を決める上流工程です。ワークフローが「どう書くか」の標準化なら、第12章は「何を、いつ、なぜ書くか」の設計です。

## 戦略がないときに起きること

> この節の要点：似た記事の乱立・更新停止・工数不足・方針ブレ・カニバリ増加。計画の欠如が原因になりやすい。新規追加前にクラスター全体を見る。

整備計画のない工場では、次の症状が出ます。あなたのサイトでも同じパターンが見られます。

| 症状 | 原因 | 体系設計での対処 |
|---|---|---|
| 似た記事が乱立 | クラスター未設計 | 12-2 ハブとスポークの役割分担 |
| 更新が止まる | カレンダー未設計 | 12-3 更新・新規・リライトの枠 |
| 工数が足りない | 優先順位なし | 12-4 インパクト×労力 |
| 方針がブレる | 合意形成不足 | 12-5 ステークホルダーとの共有 |
| カニバリが増える | 新規追加のみ | 11-4節＋12-2 統合を計画に組み込む |

第11-4節で学んだカニバリゼーションは、体系設計の欠如から生じることが多い。新規記事を書く前に、クラスター全体を見る習慣が、第12章の出発点です。

---

### ポイント

- あなたの物語戦略は、1記事ではなく体系の設計
- 比喩：整備計画（車両全体）とおまかせ献立（コース全体）
- 第2章ジャーニー、第3章削ぎ落とし、第5章 Web最適化、第6章優先度を統合
- 第11章（修理）の上流。第13章（ワークフロー）の上流
- カニバリ・更新停止・工数不足は、計画の欠如が原因になりやすい

### よくある間違い

| 間違い | 問題 | 改善の方向 |
|---|---|---|
| キーワードリストだけ作る | ジャーニーと役割が見えない | ペルソナ×段階でクラスター化 |
| 100記事計画を一度に書く | 実行不能、陳腐化 | 3ヶ月単位のカレンダー |
| 新規ばかり計画 | 既存資産が眠る | リライト枠を計画に組み込む |
| データを見ずに計画 | 想定と現実のズレ | 第6章の精密検査結果を反映 |
