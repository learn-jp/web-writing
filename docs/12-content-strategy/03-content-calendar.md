# 12-3 コンテンツカレンダーの作り方

次は「いつ書くか、いつ出すか」を決めます。コンテンツカレンダーは、新規・リライト・更新の3種類の作業を載せる年間献立表です。計画があれば、検索の季節やSNSのタイミングにも先回りでき、読者の問いが増える前に返球を用意できます。

## コンテンツカレンダーに載せる3種類の作業

> この節の要点：新規・リライト・更新の3種類を同じカレンダーに載せる。リライト枠を最初から確保し、既存資産の劣化を防ぐ。

| 種類 | 内容 | 整備の対応 | 頻度の目安 |
|---|---|---|---|
| 新規 | クラスターのギャップを埋める記事 | 新部品の取り付け | 月2〜4本（体制による） |
| リライト | 第11章の修理（部分・全面・統合・分割） | 故障修理・オーバーホール | 月3本（第6-6節） |
| 更新 | 数値・制度・リンクの軽微な修正 | 定期点検・消耗品交換 | 四半期または制度変更時 |

3種類を同じカレンダーに載せます。新規ばかり計画すると、既存資産（第11章）が眠り、鮮度が落ちます。リライト枠を最初から確保することが、整備計画の要点です。

## カレンダーの時間軸

> この節の要点：年間はテーマレベル、四半期は週単位の枠、月次は日付まで。3ヶ月単位で詳細化し、四半期ごとに見直す。

| 時間軸 | 用途 | 詳細度 |
|---|---|---|
| 年間 | 季節イベント、制度改正、大型テーマ | 月単位のテーマ |
| 四半期 | クラスターのギャップ埋め、大型リライト | 週単位の枠 |
| 月次 | 具体的な記事タイトル・担当・期限 | 日付まで |

最初から年間100記事の詳細計画を書く必要はありません。3ヶ月単位で詳細化し、四半期ごとに見直す。計画は生きた書類であり、第6章の精密検査結果で更新します。

## カレンダー1行の項目

> この節の要点：種別・クラスター・ジャーニー段階・主KW・担当・状態を1行に統一する。テンプレートで共有しやすくする。

1記事（または1リライト）あたり、次の項目を記入します。

```
コンテンツカレンダー行（テンプレート）

| 週 | 種別 | タイトル（案） | クラスター | ジャーニー段階 | 主KW | 担当 | 状態 | メモ |
```

| 項目 | 説明 |
|---|---|
| 種別 | 新規 / リライト / 更新 |
| クラスター | 12-2節のどのクラスターに属するか |
| ジャーニー段階 | 認知 / 検討 / 決定 / 行動（第2-6節） |
| 状態 | 企画中 / 執筆中 / レビュー / 公開済 / 延期 |

## 季節・イベントの織り込み

> この節の要点：制度改正・季節・業界イベント・自社イベントをカレンダーに先読みで織り込む。当日仕込みでは、検索・SNS・AI引用いずれの入り口でも効果が薄れる。

寿司職人は旬のネタを献立に反映します。あなたの物語も、読者の問いが増えるタイミングをカレンダーに織り込みます。

| タイミング | 例 | カレンダーでの扱い |
|---|---|---|
| 制度・法改正 | 確定申告シーズン、税制改正 | 関連スポークの更新・新規 |
| 季節 | 年末調整、新年度、夏休み | 季節KWのスポーク |
| 業界イベント | 展示会、製品発表 | 速報型スポーク（鮮度注意） |
| 自社イベント | キャンペーン、サービス刷新 | ハブまたはCTA記事 |

季節記事は、シーズン前に公開し、シーズン中にリライト・更新するサイクルを計画します。当日仕込みでは、検索でもSNSでもAI引用でも、読者の問いに先回りできません。

## 月次カレンダーの組み方（例）

> この節の要点：新規2本・リライト2本・更新1本が1人ライターの月次例。第6-6節の月次リライト3本と整合させる。

副業クラスターを担当する1人ライターの月次例です。

```
6月のコンテンツカレンダー（例）

| 週 | 種別 | タイトル | 優先理由 |
|---|---|---|---|
| W1 | リライト | 副業 始め方（ハブ） | 表示8,000・外門が弱い（第6章） |
| W2 | 新規 | 副業 確定申告 2026 | ギャップ・季節 |
| W3 | リライト | 副業 就業規則 | 2年未更新 |
| W4 | 更新 | 副業 種類 | リンク切れ修正 |
| W4 | 新規 | 副業 在宅 おすすめ | クラスター完成 |
```

新規2本、リライト2本、更新1本。第6-6節の「月次リライト3本」と整合させ、新規はクラスターのギャップ優先（12-4節）で選びます。

## カレンダーと第6章・第11章の接続

> この節の要点：月初の精密検査→カレンダー更新→月中執筆→月末前後比較のループ。計画は固定の約束ではなく段取りの共有ツール。

コンテンツカレンダーは、データと切り離しません。

```
月初：第6章の精密検査
  └ 異常記事・カニバリ・鮮度アラート
        ↓
カレンダー更新：リライト枠に反映
  └ 計画の新規を延期し、緊急リライトを挿入
        ↓
月中：執筆・公開（第13章ワークフロー）
        ↓
月末：改善記事の前後比較
  └ 翌月カレンダーの優先順位を調整
```

計画通りに進まない月があって当然です。整備計画も、入庫の急増で優先順位が変わります。カレンダーは「固定の約束」ではなく、「段取りの共有ツール」です。

## チーム運用のカレンダー

> この節の要点：週次15分・月次確定・四半期再評価・変更理由の記録。全員が同じ表を見て同じ段取りで動く。

複数人で執筆する場合、カレンダーは合意形成（12-5節）の中心資料になります。

| ルール | 内容 |
|---|---|
| 週次 | 来週の公開予定を15分で確認 |
| 月次 | 翌月カレンダーを確定、延期・追加を記録 |
| 四半期 | クラスター全体のギャップ再評価 |
| 変更 | 延期は理由を1行メモ（データ・リソース・優先度変更） |

共有ツール（スプレッドシート、Notion、Asana等）は問いません。全員が同じ表を見て、同じ段取りで動けることが重要です。

---

### ポイント

- コンテンツカレンダー＝新規・リライト・更新の3種類を載せる献立表
- 3ヶ月詳細＋四半期見直し。年間はテーマレベル
- 季節・制度・イベントを織り込む
- 第6章の精密検査結果で月次更新
- チームでは週次・月次・四半期の確認ルールを決める

### よくある間違い

| 間違い | 問題 | 改善の方向 |
|---|---|---|
| 新規だけ載せる | 既存資産が劣化 | リライト枠を最初から確保 |
| 細かすぎる年間計画 | 陳腐化、実行不能 | 3ヶ月単位で詳細化 |
| データを反映しない | 計画と現実のズレ | 月初の精密検査で更新 |
| 延期を記録しない | 同じ記事が繰り返し延期 | 理由付きでカレンダーに残す |
