# 9-6 章末まとめ・チェックリスト・演習

第9章では、最小の整備ピット（スマホ画面）を起点に返球を設計した。第2章のデバイス文脈から第6章の精密検査まで、本編の設計を狭い画面向けに再適用し、第10章のアクセシビリティへ進む準備を整える。

## 第9章のメッセージ（再確認）

> この節の要点：最小の整備ピットに収まる返球を書けば、どの画面でも読める。モバイルファーストは「あとから縮小」ではなく、「最初から狭い封筒で設計する」発想である。

第2章で触れた「スマホでボールを受け取る自分自身」を、執筆の起点に据えました。検索・SNS・AI引用のいずれから来ても、最初に見える画面は狭いことが多い。第3章の導管、第4章の玄関を、狭い画面向けに再調整し、CTAと読み込みの重さまで設計しました。

## 章末まとめ

> この節の要点：モバイルファーストの六つの学び：起点の発想、導管の再設計、ファーストビュー、CTA、読み込みの重さ、スマホプレビュー習慣。

1. モバイルファースト＝最初からスマホ画面で設計する（あとから縮小しない）
2. 段落3〜4文、H2間300〜500字、表はリスト化を検討
3. ファーストビューに問いへの適合、答えの予告、次関所の誘導
4. CTAは4〜8字、具体的に、Mustと一致
5. 文章量・画像・埋め込みは読み込みの重さとして設計
6. 執筆中からスマホプレビューを挟む習慣

## チェックリスト

> この節の要点：公開前に、構成・ファーストビュー・CTA・読み込みの四領域で、記事が最小の整備ピットに収まっているか確認する。

### 構成・導管（第3章の再適用）

- [ ] 各段落が3〜4文、1段落1主題になっている
- [ ] H2間が300〜500字程度で、流し読みで全体像が掴める
- [ ] 横長の表をリスト化または本文で要点を補足した
- [ ] 見出しだけスマホで流し読みし、意味が通じた

### ファーストビュー（第4章の玄関）

- [ ] スクロール前に問いへの適合が1文目でわかる
- [ ] リードに答えの予告（結論の核）がある
- [ ] 最初のH2が少し見える
- [ ] title・meta（第5章）とH1・リードが整合している

### CTA・操作

- [ ] 主CTAが4〜8字程度で、具体的
- [ ] 本文中のリンクが「こちら」単独になっていない
- [ ] スマホでCTAをタップし、意図した行先に届く

### 読み込みの重さ

- [ ] 総文字数がMustを満たすのに過不足ない
- [ ] 各画像に存在理由とalt（第10章）がある
- [ ] 不要な埋め込みをリンクに置き換えた
- [ ] スマホで体感ですぐに本文が見える（体感）

## 演習

> この節の要点：PC向けに書かれた記事1本を選び、モバイルファーストの観点で再構成案を作成する。構造から触る演習である。

課題：PC向けに書かれた記事（自社・他社・架空可）1本を選び、モバイルファーストの観点で再構成案を作成してください。

### 提出物

1. 対象記事URL（またはタイトル）
2. 現状の問題点（スマホプレビューで確認した事実を3つ以上）
3. 段落・H2の分割・統合案
4. ファーストビュー（リード）の書き直し案
5. CTA文言の改善案（あれば）
6. 削減またはリンク化する要素（画像・埋め込み等）

ヒント：第2章のペルソナとMustを再確認し、「スマホで通勤中に読む健太さん」など、具体的な文脈を想定してください。自動車整備士が最小ピットで工具配置を見直すように、構造から触る演習です。
