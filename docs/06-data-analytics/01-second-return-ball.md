# 6-1 公開後のデータは第2の返球

記事を公開したら対話は終わり、と考えていませんか。あなた自身が検索結果を眺め、クリックする前に判断した経験を思い出してください。タイトルで選び、開いてスキャンし、合わなければタブを閉じた。あの一連の体験こそ、第2の返球の出発点です。Search ConsoleやAnalyticsは、その体験を振り返るための計器であり、読者を観察するための道具ではありません。

---

## 第5章の出荷のあと、対話は続く

> この節の要点：公開後も対話は続く。第2の返球は読者・SNS・検索・AIからの答え合わせである。

第1章から第5章で、あなたは第1の返球を設計しました。

```
読者が問い（ボール）を投げる     ← 第2章
        ↓
あなたが答え（返球）を設計する   ← 第3章・第4章
        ↓
物流で届け方を整える             ← 第5章
        ↓
記事が公開される（出荷）
```

比喩の階段で言えば、第6章は精密検査（第6段）。出荷後、読者・SNS・検索・AIから返る第2の返球を、自動車整備士の予兆検知のように読み解く工程です（第6-2節以降）。

Webにおける対話は、公開後も続きます。あなた自身が読者として検索結果から記事を開き、スキャン段階でタブを閉じた経験と照らし合わせてください。SNSでシェアされず、AIが別ソースを引用する。それは「この返球、問いに合っていない」という返球です（第2章）。Search Consoleに表示されるクエリは、「実際には、こういう問いで来ている」という返球です。

> 公開後のデータは、読者・SNS・検索・生成AIがあなたに送り返してきた第2の返球である。

第2章で学んだボールの比喩を、そのまま拡張できます。

| 第1の返球（執筆） | 第2の返球（公開後） |
|---|---|
| あなたが問いに答える | 読者・SNS・検索・AIが答え合わせを返す |
| 設計対象：本文・構造 | 設計対象：改善の優先順位 |
| 手段：PREP、見出し、Web最適化（検索を入口に） | 手段：分析、リライト（第11章） |

---

## 第2の返球を無視すると、問いと答えのズレが積み上がる

> この節の要点：第2の返球を無視すると問いと答えのズレが積み上がる。数字ゲームではなく、自分の読者体験を振り返る行為。

自動車整備士が走行後の異音を無視すれば、小さな不具合が大きな故障になります。Web記事も同じです。

- 自分が開いてすぐタブを閉じる記事を放置 → 同じ問いへの候補として選ばれにくくなる（第2章・第5章）
- 表示はあるがクリックがない → 外門（title・meta）の設計ミス（第4章）
- クエリと本文がズレている → 宛名違いの返球が続く（第2章）

第2の返球を読むのは、数字を追う作業ではありません。あなた自身が検索したときの体験を振り返り、問いと答えのズレを直す行為です。第1章で述べた離脱＝消滅は、公開後も、自分が読者として再現できる体験として起き続けます。

寿司職人が握りを出したあと、客の表情や残り具合を見て次の一貫を調整するように、設計士も第2の返球を見て、次の改善を決めます。

---

## 第2の返球の主な種類

> この節の要点：表示・選ばれ方・去り方・クエリ・スクロール・順位は、第2の返球の種類と計器の地図（詳細は6-3節）。

| データ | 誰からの返球か | 何を伝えているか |
|---|---|---|
| 表示回数・選ばれ方 | 検索結果での見られた事実 | 外門（ラベル）の吸引力 |
| 去り方・読み続け | 自分が検索したときの体験 | 問いと答えの適合／不適合 |
| 検索クエリ（Search Console） | 検索エンジンの解釈 | 実際に来ている問いの言葉 |
| SNSシェア・リファラル | SNS・他メディア | 要約・引用に耐えるか、拡散の起点か |
| AI経由流入・引用ログ | 生成AI（ChatGPT、Gemini等） | 構造化・出典明示が機能しているか |
| スクロール・離脱位置 | 自分がどこまで読んだか | どの関所（H2）で止まったか |
| 順位の変動 | システムの評価 | 競合・鮮度・適合度の変化 |

これらは、第6章後半で故障診断の視点から読み解きます。

## 整備士の視点、走行後の報告書

> この節の要点：データは走行報告。精密検査→改善段取り→リライトのサイクルで対話を継続する。

自動車整備士は、車を納品したあとも、オーナーから「異音がする」「燃費が悪い」と報告を受けます。それをクレームだけで処理せず、次の点検の手がかりにします。

Webライティングも同じです。

```
公開（納品）
    ↓
データ（走行報告）
    ↓
精密検査（第6-2節以降）
    ↓
改善の段取り（第6-5節）
    ↓
リライト（第11章）
```

第2の返球を読める設計士は、一度書いて終わりにしない。対話を継続する設計士です。寿司職人が板の上の残りネタと客の反応を見て、次の段取りを決めるように、データは次の一貫の設計材料になります。

### ポイント

- 公開後のデータ＝第2の返球。対話は終わらない
- 去り方・クエリ・選ばれ方・SNS反応は、問いと答えの適合度を映す
- 無視すると、消滅と問いとのズレが積み上がる
- 分析は数字ゲームではなく、自分が読者として検索した体験を振り返る延長

### よくある間違い

| 間違い | 問題 | 改善の方向 |
|---|---|---|
| 公開して終わり | 第2の返球を無視 | 月次でSearch Console・Analyticsを確認 |
| PVだけ見る | 適合度がわからない | 去り方・クエリ・選ばれ方をセット |
| 順位だけ追う | 原因が特定できない | 問いと答えのズレを疑う |
| データを責めの材料に | 改善が止まる | 故障診断の材料として読む |
