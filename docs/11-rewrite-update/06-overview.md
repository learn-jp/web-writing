# 11-6 章末まとめ・チェックリスト・演習

第11章では、[第6章](../06-data-analytics/)の精密検査で見つけた故障を修理し、[第7章](../07-trust-eeat/)の証明書を更新し続ける方法を学びました。新規記事ばかり書いても既存の記事は資産のまま眠る：診断、修理、証明書更新、再試運転をセットにすることが、この章の核心です。

## 第11章のメッセージ（再確認）

> この節の要点：既存記事は資産である。第6章で診断し、第7章の証明書を更新し、第2の返球で効果を確かめる。オーバーホールと部分修理を使い分ける。

[第6章](../06-data-analytics/)は「どこを直すか」を見つける章でした。[第7章](../07-trust-eeat/)は「正しいと宣言する」章でした。第11章は、その宣言を維持するための修理と更新の章です。オーバーホール（全面）と部分修理（部分リライト）を使い分け、カニバリを解消し、鮮度を保ち、再試運転で効果を確かめます。

---

## 本編・応用編との接続

> この節の要点：第6章（精密検査）→ 第11章（修理）→ 第7章（証明書）→ 第6章（再試運転）の循環。診断と修理と証明書の順番を固定する。

| 章 | 比喩・役割 | 第11章との関係 |
|---|---|---|
| 第6章 | 精密検査 | リライト対象の発見、再試運転 |
| 第7章 | 証明書 | 更新日・出典・訂正の更新 |
| 第11章 | 修理・更新 | 診断結果を資産改善に変換 |

```
第6章 診断 → 第11章 修理 → 第7章 証明書更新 → 第6章 再試運転
```

[第7-6節](../07-trust-eeat/06-designers-way-of-life.md)の誓い3「更新し続ける」は、第11章の月次3本リライトで実行されます。

---

## 章末まとめ

> この節の要点：第11章の8項目：4種類のリライト、月次3本、鮮度L1/L2/L3、カニバリ解消、7ステップ、日付だけ更新禁止、28日再試運転。

1. リライトは4種類：部分・全面・統合・分割
2. 部分リライト＝部分修理、全面＝オーバーホール。症状と原因レイヤーで選ぶ
3. リライト対象は第6章の月次精密検査から。毎月3本
4. 鮮度は証明書の更新日欄。L1/L2/L3の3レベル
5. カニバリは統合・役割分担・内部リンク再設計で解消
6. 7ステップ：診断→計画→執筆→構造→証明書→公開→再試運転
7. 日付だけの更新は禁止。本文とセット
8. 28日後の再試運転で効果確認。効果なしは診断に戻る

## チェックリスト

> この節の要点：月次・公開前・公開後・四半期の4ブロックで、リライト運用の確認項目を固定する。

### 月次（第6章ルーティンに追加）

- [ ] Search Consoleで異常記事を第6-2節の予兆に分類
- [ ] 優先度マトリクスで今月のリライト3本を決定
- [ ] 重点記事の更新日・鮮度を確認（11-3節）
- [ ] カニバリ疑いのクエリ×URLを1件以上確認
- [ ] リライト計画書（種類・レイヤー・成功指標）を1本以上作成

### リライト公開前

- [ ] 第6章の診断成果物（症状・原因・マトリクス）がある
- [ ] リライト種類と変更範囲が計画と一致
- [ ] title・meta・H1・見出し階層を確認
- [ ] 更新日・改訂内容・出典を更新（第7-4節）
- [ ] 統合・分割時：301・内部リンクを確認

### 公開後

- [ ] 改善記録スプレッドシートに1行追加
- [ ] 28日後の再試運転をカレンダー登録
- [ ] 前月リライト記事の効果確認（第6-6節フェーズ4）

### 四半期

- [ ] 2年以上未更新×表示500以上の記事リスト
- [ ] カニバリ診断ワークシート（11-4節）
- [ ] 全面リライト・統合の計画（1〜2本）

## 演習

> この節の要点：低パフォーマンス記事1本について、第6章形式の診断からリライト計画書まで一気通貫で作成する。部分リライトから始める。

課題：低パフォーマンス記事1本について、リライト計画書を作成してください（Search Console・Analyticsがなくても、公開情報と想定データで可）。

[第6章](../06-data-analytics/)・[第7章](../07-trust-eeat/)の演習と同じ記事を使うと、精密検査→証明書監査→リライト計画の一連の流れを体験できます。

### 提出物

1. 対象記事URL（またはタイトル）
2. 第6章形式の診断（予兆パターン、原因レイヤー、問い×答えマトリクス3クエリ以上）
3. リライト種類（部分/全面/統合/分割）と選定理由
4. 変更レイヤーと具体的アクション（title修正、H2追加、数値更新等）
5. 第7章形式の証明書更新項目（更新日、改訂内容、出典）
6. 成功指標1つ以上（外門の通過、玄関で引き返す傾向、適合度等）
7. 28日後の再試運転で見る指標

ヒント：部分リライトから始める。全面リライトは、部分で2回効果がなかった場合の次の選択肢として検討する。
