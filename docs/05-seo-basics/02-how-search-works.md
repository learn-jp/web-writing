# 5-2 検索エンジンの基本動作。クロール・インデックス・ランキング

記事を公開したのに検索結果に載らない、順位の理由がわからない。クロール、インデックス、ランキングの3工程は、読者・SNS・生成AIへ届く物流の土台です。工場の巡回・記録・選別として一続きに見えなければ、どこを直すべきかも定まりません。

---

## 検索エンジンの3工程は、工場の巡回・記録・選別に似ている

> この節の要点：クロール・インデックス・ランキングは、工場の巡回・記録・選別として一続きに理解する。

第3章で、情報設計を工場ラインに例えました。検索エンジンも、巨大な問いと答えの工場です。あなたのサイトは、その工場に部品（ページ）を納入するサプライヤーに近い。部品が届かなければ、どれほど良い導管（第3章）も、どれほど磨いた玄関（第4章）も、読者の前に現れない。それが、物流設計の緊張感です。

| 工場の工程 | 検索エンジンの動作 | ライターが整えること |
|---|---|---|
| 巡回（クロール） | クローラーがページを発見・訪問 | クローラビリティ、サイトマップ、リンク |
| 記録（インデックス） | 内容を理解し、インデックスに登録 | 構造（H1-H4）、配送ラベル、本文の価値 |
| 選別（ランキング） | 問いに対し、最適なページを順位付け | 意図一致、E-E-A-T、ユーザー信号 |

部品が工場に届かなければ（クロールされなければ）、記録も選別も起きません。物流ルート（第5-5節）とラベル（第5-3節）の前提が、この工程です。

---

## 工程1。クロール（巡回）とクローラビリティ

> この節の要点：クローラビリティは、クローラーが迷わず巡回できる通路設計。内部リンクと構造が第一歩。

クローラー（クロールボット）は、Web上をリンクを辿って巡回するプログラムです。検索エンジンbot など。新しいページを発見し、更新を確認し、インデクサーに中身を渡します。

クローラビリティ（Crawlability）とは、クローラーがサイトを迷わず巡回できる度合いです。

工場ラインで言えば、次の条件が整っています。

```
✓ 通路が幅広く、障害物がない     → クローラーがリンクを辿れる
✓ 各工程に看板がある             → 見出し・構造が明確
✓ 行き止まり・私道がない         → 404、孤立ページがない
✓ 危険区域に立ち入り禁止が明示   → robots.txt で意図的に除外
```

自動車整備士がピット内の動線を確保するように、クローラーが迷わない通路を設計することが、読者への価値提供の第一歩です。

### クローラビリティを高める実務

| 施策 | 効果 |
|---|---|
| 内部リンク | サイト内の通路。重要ページへリンクを張る |
| XMLサイトマップ | 工場への納品リスト。技術側と連携 |
| 正しいHTTPステータス | 200（正常）、301（移転）を適切に |
| 浅い階層 | ホームから3クリック以内に主要記事 |
| モバイル対応 | モバイルファーストインデックス |

ライターが直接触れやすいのは内部リンクと見出し構造です。第3章の設計が、そのままクローラビリティに効きます。

### クローラビリティを阻害する典型例

| 問題 | 工場比喩 | 対処 |
|---|---|---|
| 孤立ページ（リンクなし） | 地図にない倉庫 | 内部リンク・サイトマップ |
| 重複したページ | 同じ部品の二重登録 | canonical、統合（第11章） |
| 極端に遅いページ | ラインが停止 | 性能は技術側、本文量のバランス |
| JavaScriptのみの内容 | 中身が見えない箱 | 重要テキストはHTMLに（技術連携） |

## 工程2。インデックス（記録）と知性による理解

> この節の要点：インデックスは巨大な問いと答えのカタログへの登録。構造とラベルの一致が理解の鍵。

クローラーが持ち帰ったHTMLを、検索エンジンのインデクサー（索引付けシステム）が処理します。ここで、現代の検索エンジンはAI・自然言語理解を使い、ページを理解しようとします。ChatGPTやGeminiが引用する際も、同様に見出し階層・FAQ・結論の位置を読み取ります。

- このページは何について書かれているか
- どんな問いに答えているか（第2章・第6章）
- 構造（見出し、リスト、表）は論理的か
- 配送ラベル（title、meta）と中身は一致するか

> インデックス＝、検索エンジンの巨大な問いと答えのカタログへの登録。

登録されなければ、どれほど良い導管も検索結果に現れない。第1章の宛名の判読に失敗して届かない。そのインデックス版です。

### インデックスされやすい構造（通信規格）

```html
<head>
  <title>副業の始め方｜初心者が今週末に登録まで進む3ステップ</title>
  <meta name="description" content="在宅で週末だけ試せる副業の選び方と、就業規則確認から登録までの手順を解説。">
</head>
<body>
  <h1>副業の始め方｜初心者が今週末に登録まで進む3ステップ</h1>
  <p>結論：最初の一歩は、就業規則の確認です。</p>
  <h2>会社に確認すること</h2>
  <h2>在宅で試せる副業3選</h2>
</body>
```

ブラウザでの表示結果（見た目）：

- H1が1つ、H2が論理的に並ぶ
- title・meta と H1 の約束が一致する
- スキャン読みでも主題と構成が一目でわかる

noindex を付けるページ。意図的にこの部品はカタログに載せないと決める場合。は別問題。公開した記事は、載せたい前提で設計します。

## 工程3。ランキング（選別）と問いに最適な答え

> この節の要点：ランキングは問いに最も誠実に答えるページを選ぶこと。操作より設計が長期で効く。

ユーザーが問いを投げると、検索エンジンはインデックスから候補を数千〜数万件取り出し、ランキング（順位付け）します。

現代のランキング要因は、単一の公式ではありませんが、本書では設計士がコントロールできる軸に整理します。

| 軸 | 内容 | 本章・他章 |
|---|---|---|
| 関連性 | 問い・意図との一致 | 第2章、第6章 |
| 品質・信頼 | E-E-A-T | 第5-6節、第7章 |
| 構造・技術 | クローラビリティ、Core Web Vitals | 本章、第9章 |
| ユーザー信号 | 選ばれ方、読み続け、即去り、SNSシェア（間接） | 第4章、第14章 |

ランキング＝、工場がこの問いには、この部品（ページ）が最適と判断すること。

上位を操作するトリックではなく、問いに最も誠実に答えるページを設計する。それが、長期的に効く検索エンジンへの最適化であり、読者への価値提供です。

## 3工程の流れは、物流ルート全体を表す

> この節の要点：公開からクリック・導管通過まで、3工程と外門・導管が一枚の物流ルートとしてつながる。

```
[あなたのサイト]
    ページ公開（部品完成）
        ↓ クロール（巡回・通路）
    インデックス（カタログ登録・理解）
        ↓ ユーザーが問いを検索
    ランキング（選別）
        ↓ 検索結果に表示（配送ラベルが見える）
    クリック → 第4章の外門 → 第3章の導管
```

最強の物流ルートとは、次の4点が揃うことです。

1. クローラーが確実にページを発見・巡回する
2. インデクサーが正しく内容を理解・登録する
3. 問いが来たとき、適切な候補として選ばれる
4. ラベル（title/meta）がクリックされ、読者が導管に入る

## Search Consoleは、工場からの物流レポートである

> この節の要点：Search Consoleは検索エンジンからの物流レポート。月1回の確認習慣をつける。

Search Console（検索エンジン運営者が提供する無料ツール）は、検索エンジンからの物流レポートです。

| レポート | わかること |
|---|---|
| インデックス登録 | カタログに載ったページ数 |
| クロール | エラー、未登録の理由 |
| 検索パフォーマンス | どの問いで表示・クリックされたか |
| サイトマップ | 納品リストの受理状況 |

ライターは、どの問い（クエリ）で表示されているかを見ると、第2章のペルソナ・意図の検証に使えます（第14章）。整備士が走行後の診断機器を読むように、月1回は確認する習慣をつけましょう。

### ポイント

- クロール→インデックス→ランキング＝巡回・記録・選別
- クローラビリティ＝ラインを巡回しやすくする（内部リンク、浅い階層）
- インデックス＝知性による理解とカタログ登録
- ランキング＝問いへの最適な答えとして選ばれること
- Search Consoleで物流のフィードバックを受け取る

### よくある間違い

| 間違い | 問題 | 改善の方向 |
|---|---|---|
| 公開＝インデックスと思う | 巡回・登録に時間がかかる | サイトマップ、内部リンク |
| 構造を後から任せる | インデクサーが誤解 | 第3章の構造を執筆時に |
| ランキング操作のみ | 短期、ペナルティリスク | 問いへの誠実な回答 |
| Search Consoleを見ない | 改善機会を逃す | 月1回は検索クエリ確認 |
