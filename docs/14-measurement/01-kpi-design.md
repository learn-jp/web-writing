# 14-1 あなたの物語KPIの設計

公開後、自分が読者として読み返した体験を、数字で確かめる。KPIは採点表ではなく、「読者としての自分」が留まるかどうかを振り返り、次の改善を決める羅針盤です。第6章の月次精密検査が、第14章のKPIダッシュボードを更新する入力データです。

## 第6章との違いをはじめに

> この節の要点：第6章は記事1本の故障診断、第14章はポートフォリオ全体の健康指標と改善の段取りである。両者は対立せず、精密検査がKPIの入力になる。

第6章では、記事1本あたりの第2の返球を精密検査しました。Search Consoleのクリック率（CTR）、GA4の直帰率、クエリ。整備士が1台の車を診断機で読む作業です。

第14章では、視点を上げます。工場全体で何台を、どの順番で、なぜ直すか。あなたの物語ポートフォリオが、ビジネスの問いに答えているかを測る設計です。

```
第6章 精密検査  →  記事1本の故障診断
第14章 KPI設計  →  ポートフォリオ全体の健康指標と改善の段取り
```

両者は対立しません。第6章の月次精密検査が、第14章のKPIダッシュボードを更新する入力データです。

---

## KPIとは何か

> この節の要点：KPIは「見たい数字のリスト」ではなく、改善の段取りを決める設計士の羅針盤である。誰のため・何を達成・どう測る・いつ見るを先に問う。

KPI（Key Performance Indicator）は、重要業績評価指標です。Webライティングの文脈では、「あなたの物語が、読者とビジネスの問いに、どれだけ答えているか」を数値で追うための、少数の核心指標です。

KPIを設計する前に、次の問いを立ててください。

| 問い | 設計士の視点 |
|---|---|
| 誰のための物語か | ペルソナ・ジャーニー（第2章） |
| 何を達成したいか | 行動目的（第1章）、CV・認知・信頼 |
| どう測るか | 第6章の計器、第14章のKPIツリー |
| いつ見るか | 月次精密検査、四半期PDCA（14-5節） |

KPIは「見たい数字のリスト」ではありません。改善の段取りを決めるための、設計士の羅針盤です。

---

## バニティ指標とアクション可能指標

> この節の要点：PVだけを追っても次の一手は曖昧になる。「この数字が変わったら何を直すか」が言える指標だけを選ぶ。

| 種類 | 例 | 特徴 |
|---|---|---|
| バニティ指標 | PV、フォロワー数、記事本数 | 見栄えはするが、次の一手が曖昧 |
| アクション可能指標 | 外門の通過（GSC CTR）、玄関で引き返す割合（GA4直帰率）、クエリ適合、CV率 | レイヤー特定→リライト可能（第6章） |

PVが増えた。それだけでは、外門が強くなったのか、物流が改善したのか、偶然の流入かは分かりません。第6-3節で学んだように、計器は束ねて読みます。

```
PV ↑ ＋ 外門の通過 ↓  →  外門（title・meta・OGP）を疑う（第4・5章）
PV ↑ ＋ 玄関で引き返す ↑  →  防波堤（リード）を疑う（第4章）
PV 横ばい ＋ 表示 ↑  →  検索物流は機能、外門が弱い（第5章 Web最適化）
SNS経由PV↑ 玄関で引き返す↑  →  シェア文と本文の約束がズレている（第9章）
```

KPI設計の第一歩は、「この数字が変わったら、何を直すか」が言える指標だけを選ぶことです。

## KPIツリーの設計

> この節の要点：ビジネス目標から北極星指標へ枝分かれさせ、第6章の計器と接続する。クラスター単位でKPIを設計する。

### 例：BtoB SaaSメディア

```
ビジネス目標：無料トライアル申込 月100件
    │
    ├─ 流入：オーガニック検索クリック 月5,000
    │       └─ KPI：Search Console クリック数、主要クエリの表示
    │
    ├─ 流入：SNS・AI引用経由セッション
    │       └─ KPI：GA4 参照元、ランディング直帰率
    │
    ├─ 関心：記事から製品ページへの遷移率 8%
    │       └─ KPI：GA4 イベント（内部リンククリック）、直帰率
    │
    └─ 行動：CTAクリック率 3%
            └─ KPI：GA4 コンバージョン、CTA周辺のスクロール深度
```

第12章のコンテンツ戦略（トピッククラスター、ハブ記事）と接続すると、KPIは「記事ごと」ではなく「クラスターごと」に設計できます。

| クラスター | 主KPI | 第6章の計器 |
|---|---|---|
| ハブ記事 | 表示・外門の通過（CTR）・内部リンク遷移 | クエリ適合、外門 |
| 詳細記事 | 玄関で引き返す割合・読み続け時間・CV寄与 | 関所、防波堤 |
| 比較・レビュー | CV率・クエリの商業性 | 証明書（第7章） |

## 記事タイプ別KPIの例

> この節の要点：Know型とGo型を同じ「一ページだけ見て去る割合（GA4直帰率）」で採点しない。意図の型（第2章）に応じて、成功の定義と主KPIを変える。

| 記事タイプ（第2章） | 主KPI | 一ページだけ見て去る割合の読み方 |
|---|---|---|
| Know（知りたい） | 読み続け時間・スクロール深度 | 高めでも問題ない場合あり |
| Go（行きたい） | 遷移率・CV | 一ページだけ見て去る＝目的達成の可能性 |
| Do（やりたい） | 手順完了率・再訪 | 特定H2までの到達率 |
| Buy（買いたい） | CV・比較表クリック | 商業クエリの適合（第6-4節） |

第6章の精密検査は記事1本の診断です。第14章のKPI設計は、「このタイプの記事は、何をもって成功と呼ぶか」をチームで合意する作業です（第12-5節のステークホルダー合意と接続）。

## KPI設計シート（実務テンプレート）

> この節の要点：四半期ごとに1枚の設計シートを更新する。北極星1つ＋サポートKPI3つに絞り、Won'tで今期やらないことを明記する。

四半期ごとに、次のシートを1枚更新します。

| 項目 | 記入例 |
|---|---|
| ビジネス目標（四半期） | オーガニック経由CV 月30件 |
| 北極星指標 | オーガニックCV数 |
| サポートKPI（3つまで） | ① オーガニッククリック ② ハブ記事の外門通過（GSC CTR） ③ 製品ページ遷移率 |
| 第6章計器との対応 | ① GSCクリック ② GSC CTR ③ GA4イベント |
| 見る頻度 | 月次（精密検査）＋四半期（PDCA） |
| Won't（今期やらない） | 全記事の滞在時間平均の改善 |

Won'tを書くことは、第3章の削ぎ落としと同じです。KPIが多すぎると、精密検査が形骸化します。3つに絞り、第6章の月次ルーティンで更新します。

## よくある間違い

> この節の要点：PVだけのKPI、全記事同一基準、KPIと改善アクションの未接続、精密検査の省略は避ける。

| 間違い | 改善 |
|---|---|
| PVだけをKPIにする | クリック・外門の通過・CVまで束ねる（第6-3節） |
| 全記事に同じ基準 | 意図の型・ジャーニー段階で変える（第2章） |
| KPIと改善アクションが未接続 | 「外門の通過が弱ければtitle修正」と書く |
| 四半期にKPIを変えすぎる | 北極星は年単位、サポートKPIは四半期 |
| 第6章の精密検査を省略 | KPIは精密検査の集計結果である |
