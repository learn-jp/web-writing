## 演習

> この節の要点：記事1本について改善レポートを作成する。精密検査→KPIツリー→PDCA→改善ログの一連の流れを体験する。

課題：自社または他社の記事1本について、改善レポートを作成してください（Search Console・Analyticsがなくても、公開情報と想定データで可）。

第6章・第7章・第11章の演習と同じ記事を使うと、精密検査→証明書監査→リライト計画→改善レポートの一連の流れを体験できます。

### 提出物

1. 対象記事URL（またはタイトル）
2. KPIツリー（北極星1つ＋サポートKPI 3つ。この記事の役割を明示）
3. 第6章形式の診断（予兆パターン、原因レイヤー、問い×答えマトリクス3クエリ以上）
4. GSC・GA4の読み取り（実データ or 想定。外と内を分けて記述）
5. ヒートマップまたはスクロール深度の所見（想定可。自分がどこで戻るかの特定）
6. PDCAの各段階（Plan：今月の目標 / Do：実施した or 計画した改善 / Check：データ / Act：次の一手）
7. 改善ログ1行（症状・アクション・再試運転日・目標指標）
8. 四半期PDCAで見るべきクラスター視点のメモ1つ

ヒント：KPIツリーは、この記事単体ではなく「この記事が属するクラスター」で書いてください。記事はポートフォリオの一部です。

## 応用編のまとめ（第8章〜第14章）

> この節の要点：応用編は「工房全体を誠実に運営し続ける」設計である。声・媒体・保全・戦略・段取り・測定が一本の思想につながる。

本編第7章で比喩の階段を登り切ったあと、応用編では設計思想を現場の運用へ広げました。一度、応用編全体の地図を確認しましょう。

| 章 | テーマ | 設計士が問うこと |
|---|---|---|
| 第8章 | トーン＆マナー | 証明書を、どう手渡すか（声の一貫性） |
| 第9章 | モバイルファースト | 短い画面でも、答えは届くか |
| 第10章 | アクセシビリティ | 誰にでも、出口まで辿り着けるか |
| 第11章 | リライトと更新 | 資産を眠らせず、修理し続けるか |
| 第12章 | あなたの物語戦略 | 単発ではなく、体系で設計しているか |
| 第13章 | 実践ワークフロー | 企画から公開まで、段取りは標準化されているか |
| 第14章 | 測定と改善 | 数字で学び、次の一手を決めているか |

応用編の流れは、次の一本の思想です。

```
声と媒体（第8〜10章）
  → 既存資産の保全（第11章）
  → 未来の物語の設計（第12章）
  → 日々の段取り（第13章）
  → 学びの循環（第14章）
```

本編が「1本の手紙を正しく届ける」設計でした。応用編は「工房全体を、誠実に運営し続ける」設計です。トーンを揃え、モバイルとアクセシビリティで消滅を減らし、リライトで資産を磨き、戦略とワークフローで再現性を高め、測定で問いに応え続ける。これが、応用編の完成形です。

## おわりに

> この節の要点：本書は型のリストではなく、読者の時間を預かる設計士としての生き方を渡すものである。今日ひとつだけ整える。

本書を最後まで読まれた方へ。

第1章の手紙から、第7章の証明書まで。比喩の階段を登り切ったあと、第8章の声、第9章の短い画面、第10章の工房のスロープ、第11章の修理、第12章の地図、第13章の段取り表、そして第14章の計器と循環まで。本編と応用編、両方の旅を、ここまで歩いてきました。

第7章のあとがきで、本書は「型のリスト」ではなく、読者の時間を預かる設計士としての生き方を渡したいと書きました。応用編を経た今、その生き方はより具体的な形を持っています。

- 声を一貫させ、渡し方で読者を迷わせない（第8章）
- 画面の制約のなかでも、答えを届ける（第9章）
- 誰にでも出口まで辿り着ける工房を設計する（第10章）
- 公開済みの記事を資産として磨き続ける（第11章）
- 単発ではなく、体系で物語を設計する（第12章）
- 企画から公開まで、再現できる段取りを持つ（第13章）
- 数字で学び、次の一手を決め、サイクルを回す（第14章）

これらは、別々のスキルではありません。第7-6節で示した骨格（問いを受け取り、時間を預かり、正しい答えを正しい形で届け、届いたかを確かめ、正しいと宣言する）の、現場での実践です。

自動車整備士として国家資格を取得し、現場で技術を磨いてきた経験。整備士が走行後の異音を無視しないように、設計士は第2の返球を無視しません。月次の精密検査（第6章）、四半期のPDCA（第14章）、失敗の記録と再試運転（第11章）。これらは、証明書を一度きりの発行ではなく、更新し続ける宣言の具体化です。

テクニックは、いつか古くなります。検索の仕様、SNSのアルゴリズム、AI引用の挙動、ツールの画面：入り口は変わり続けます。しかし、問いに応え、時間を預かり、正しいと宣言し、学び続ける姿勢は、変わりません。それが、本編と応用編を通じて、本書が一貫して伝えたかった設計士としての生き方です。

第7章では、寿司職人が板を磨くように、次の読者のために今日ひとつだけ整えると書きました。第14章の締めくくりとして、同じ言葉を、もう一度、あなたに贈ります。ただし、文脈は広がっています。

次に書く記事のために。次に直す記事のために。次の四半期のカレンダーのために。チームの改善ログのために。今日ひとつだけ、整えてください。

一本のtitle。一行のリード。一つの出典。一つの問い×答えマトリクスの行。一つの改善ログの行。どれでも構いません。大きな改革は、小さな整えの積み重ねから始まります。

画面の向こうにいる、名前も顔も知らない誰かが、あなたの記事に問いを投げてきます。その問いに、空の返球を返さない。消滅を切り捨てない。正しいと、宣言し、更新し続ける。

長い旅を、本当に、ありがとうございました。
